# 跟单管理系统文档

更新：2026-10-07。完整系统交付资料统一放在 `shared/delivery/`，覆盖当前已实现的一期业务和二期能力。需求、原型、技术设计与开发计划继续按阶段维护。交付文档描述使用、运行及交接，业务定义以各阶段正式需求和已确认增量为准。

## 阅读顺序

1. [交付清单](shared/delivery/交付清单.md)：范围、代码版本、环境核验和待交付项。
2. [系统说明与架构](shared/delivery/系统说明与架构.md)：角色、业务主链与技术组成。
3. 对应[操作手册](#操作手册)：按实际使用入口查步骤。
4. 技术接手时阅读[数据字典](shared/delivery/数据字典与关系图.md)、[接口与外部集成](shared/delivery/接口与外部集成说明.md)、[部署与运维](shared/delivery/部署与运维手册.md)、[维护与交接](shared/delivery/维护与交接说明.md)。
5. 核对[验收记录](shared/delivery/验收记录.md)与[版本发布记录](shared/delivery/版本发布记录.md)。

## 维护约定

Issue 正文、缺陷和执行状态统一由 GitHub 跟踪，规则见 [Issue tracker](agents/issue-tracker.md)。已删除的 Issue 副本和环境、原型差异记录可从 Git 历史查阅。历史里程碑记录保留当时版本及验证边界，当前交付状态以交付清单的核验日期为准。

功能、接口、数据或部署方式变更时，同步更新对应交付正文、操作手册、验收用例及发布记录。禁止将尚未执行的生产、真机、文件回传或业务验收填为通过。
