# 跟单管理系统文档

文档先按一期、二期分开，再按用途分类。文件移动不改变批准状态或业务规则；当前正式业务规则基线为一期 V1.60（明细合同出货时间已进入本地实现，尚未发布），二期处于需求建设阶段。

| 目录 | 内容 |
|---|---|
| `一期/requirements/` | 一期正式需求 |
| `一期/project/` | 一期技术设计、开发计划、页面地图、验收、里程碑和历史交接；`work-orders/` 保留 S00–S12 正式工单 |
| `二期/drafts/` | 二期能力构想及待确认内容 |
| `二期/project/` | 二期需求建设计划；后续经确认的技术设计与开发计划按用途放入 |
| `shared/` | 两期共用的小程序复刻和管理员表格视觉规范，保留已有确认及例外记录 |
| `agents/` | Issue 协作与领域文档规则 |
| `reference/` | 共用 Excel 模板、质检和工厂资料参考；保留原路径供现有测试使用 |

二期正式需求稿创建时放入 `二期/requirements/`，目前尚未创建。不为相同公共规则在两期各维护一份副本。

## 一期当前修改

[Issue #61：工厂／SKU明细合同出货时间](https://github.com/kocotree/order_tracking/issues/61)为本次唯一执行工单。用户已授权完成代码修改、测试并本地提交后停止，沿用当前分支；不运行Playwright。正式环境清理、推送、PR、部署和小程序发布仍不在本轮执行范围。实现与验证记录见一期里程碑末尾。

## 二期本轮已确认范围

内部同事通过飞书机器人提交来货出入资料，无歧义自动正式登记并影响对应订单进度，异常转人工；现有收货确认与机器人登记的同一差异不能重复生效。只回填现有 Base 的每周出货列，取消工厂/SKU周汇总导出。月账单先做数量分项，暂不加价格和金额；工厂分析与库存预警保留原设想。具体生效、归期和异常口径见二期建设计划。
