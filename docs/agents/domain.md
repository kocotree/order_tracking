# Domain docs

本仓库采用单一上下文，根目录 `CONTEXT.md` 是领域术语表；不存在 `CONTEXT-MAP.md`。

## 开始工作前

启动检查和批准顺序遵守根目录 [AGENTS.md](../../AGENTS.md)。在文档入口和术语表基础上，按任务读取：

- 业务与实现任务：所属阶段需求、对应已批准原型、技术设计、开发计划和当前工单；
- 历史决策核对：`docs/一期/project/一期里程碑与决策记录.md` 中相关条目，以及与当前范围相关的 ADR；
- 二期任务：`docs/二期/project/二期需求建设计划.md` 及相关已批准资料，草稿不得覆盖现行规则；
- 运维与交付任务：`docs/shared/delivery/` 中相关正文；接续未完成任务时同时读取交接记录。

## 资料职责

- 需求文档定义业务范围和验收口径；
- 已批准原型定义页面内容与交互；
- 技术设计定义实现边界；
- 开发计划定义切片顺序与依赖；
- 当前工单定义本次修改范围；
- `CONTEXT.md` 统一领域名词；
- `docs/shared/delivery/` 描述全系统使用、接口、运行、验收和交接，更新时核对当前实现及实际证据，不覆盖正式需求；
- GitHub Issue 跟踪具体执行，不覆盖上述正式资料。

发现资料冲突时先说明具体条目及影响，按上述职责确定应修订的正式资料，并按 `AGENTS.md` 的确认门执行。
