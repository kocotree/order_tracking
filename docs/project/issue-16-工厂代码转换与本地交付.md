# Issue #16 工厂代码转换与本地交付

## 本次范围

本地实现字母代码校验、可空字段、历史合同保护和一次性转换脚本；授权完成本地检查并提交后停止。没有推送、PR、环境部署或服务器数据转换。规则依据为正式需求 Issue #16 修订节；S02/S06 保持既有工单，补充本次差异，不另建重复执行单。

工厂代码截取第一个 `（`、`(` 或 `-` 前的内容；日常新增/编辑只接受字母或空值，存量脚本才做中文逐字拼音首字母转换。pypinyin 0.55.0 的词典可能包含少见读音，逐字存在多个读音均保守留空，不依赖词组消歧。重复组全部留空，包括与本来合法的字母代码碰撞的记录；停用工厂也参与重复检查。空值不会回退到工厂名称或供应商编号。

工厂编辑和原型仅调整代码可编辑/可空、校验及提示。正式弹窗将错误显示在弹窗内，避免错误被遮罩挡住；沿用既有页面样式，不改变表格、排序和分页。

## 代码与初始化路径

- `server/app/modules/factory_access/codes.py` 提供统一字母代码规范化，资料服务负责所有现有 API 新增/编辑路径；代码唯一索引保留，空值存 NULL，API 对外仍返回空字符串。
- `20260905_0028_nullable_factory_code.py` 仅调整字段可空，不转换现有数据；存在 NULL 时拒绝 downgrade，禁止猜测填充值。
- `server/scripts/migrate_factory_codes.py` 独立执行预览、应用、回滚；不作为 worker 周期任务或应用启动任务。
- 仓库现有 `server/scripts/` 未发现工厂初始化脚本；生产/测试历史的一次性外部初始化命令不纳入常驻代码。以后初始化应经工厂资料服务写入，不直接拼装中文代码入库；本轮不新增批量导入功能。
- 合同首次生成仍需代码完整，既有合同按原快照重新导出；顺序号按工厂 ID 和签订日期继续递增。合同编号、快照、供应商编号均不由转换脚本修改。

## 后续环境执行（本轮未授权运行）

共享测试和生产必须分别确认目标环境、发布提交及对照预览。以下命令在服务器 `server/` 目录运行，使用已经受控配置的 `ORDER_TRACKING_DATABASE_URL`；不要把凭据放入命令参数、计划、日志或仓库。

1. 部署前完成远程完整 CI、取得环境授权，并按既有备份流程保留完整数据库备份；确认恢复路径。应用字段结构迁移后才可运行本脚本。旧应用仍要求代码非空，不能在旧应用运行时转换数据。
2. 在仓库外准备仅运维可读写的备份目录。以下 `PLAN_PATH` 和 `BACKUP_PATH` 指向该目录内不同且尚不存在的 JSON 文件；文件自动以 0600 创建。对照包含业务信息，只在受控位置审核，不上传仓库/Issue。

```sh
# 不传 mode 也默认 preview，只读数据库并创建本地对照。
uv run python -m scripts.migrate_factory_codes preview --plan "$PLAN_PATH"
```

3. 审核 before/after/reason，确认 `duplicate`、`ambiguous`、`invalid` 留空名单。计划不能人工修改，apply 会重新计算并精确匹配；需要人工处理的工厂在转换后用网页编辑。
4. 取得本环境执行授权后，暂停工厂资料写入和合同生成（覆盖管理员请求、可能的一次性初始化路径），避免切换期间混用旧代码。重新 preview 确认计划未过期，再显式执行：

```sh
uv run python -m scripts.migrate_factory_codes apply --plan "$PLAN_PATH" --backup "$BACKUP_PATH"
```

5. apply 锁定全体工厂并比较原值/版本/集合，写前生成备份，先清除变化键再赋新值，防止唯一索引的中间态冲突。代码、递增版本和 `factory.code_migrated` 审计在同一事务提交，随后重新读回。事务失败会保留写前备份，不能将“存在备份”当作执行成功；需检查退出码、原值和审计。回读失败可能发生在提交之后，不能盲目重复运行，应检查备份和实际状态。
6. 验证多家空代码共存、人工补齐、首次合同新代码和老合同重新下载；恢复业务操作。实际验证通过才记录该环境完成。

## 回滚

需要时暂停相关写入，并使用本次 apply 的原备份：

```sh
uv run python -m scripts.migrate_factory_codes rollback --backup "$BACKUP_PATH"
```

回滚逐行要求代码及版本仍与本次 apply 的结果一致，并要求工厂集合未变化以及对应迁移审计存在；否则拒绝覆盖后续人工修改，需要重新核对处理。回滚只恢复原工厂代码，版本继续增加，并写 `factory.code_rollback` 审计；不删除迁移审计、不修改任何已生成合同。原代码可能仍是中文，回滚不等于撤销应用发布；若还要回退字段结构，须先处理所有 NULL 代码，另按发布回滚流程执行。
