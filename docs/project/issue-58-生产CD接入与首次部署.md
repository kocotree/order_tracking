## CD 实现与发布顺序

1. 独立 Issue/分支修改，通过 PR、完整 main CI。
2. 用户明确批准推送 v* 标签，即授权该版本自动部署生产。按标签精确提交核验 main push 完整 CI 的最新运行和五项任务均成功，不再次运行 CI。
3. 两类 GHCR 镜像均发布成功后，同一次 Release 工作流自动调用 Deploy production；不再手动触发 CD。
4. 校验 SSH 主机身份，部署凭据通过 GitHub Secrets；registry 使用短期 GITHUB_TOKEN。
5. 服务器校验两个镜像 revision，备份 MySQL/OSS，再迁移、启动、健康检查和记录版本。
6. 外部 HTTPS、飞书登录回调和真实用户授权单独验收；小程序审核发布单独执行。

生产 Compose 仅拉取 GHCR 镜像。旧 Git/build 发布脚本继续服务共享测试。
回滚使用上一版本镜像和配置，不自动降级数据库。失败时不记录发布成功，
但数据库 DDL 或已替换的容器可能需要人工处理，不宣称全流程原子回滚。
