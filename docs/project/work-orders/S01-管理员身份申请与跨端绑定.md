## 1. 工单目标

本工单打通管理员从网页申请到小程序绑定的第一个正式业务闭环：

1. 内部人员通过飞书 OAuth 登录管理员网页端；
2. 尚未取得管理员角色的用户使用本人手机号和短信验证码提交管理员申请；
3. 最高管理员查看、通过或拒绝管理员申请，并管理普通管理员启停；
4. 审核通过的管理员在小程序首次登录时取得微信身份并授权手机号；
5. 后端只在手机号与网页端已验证申请一致且唯一匹配时，把微信身份绑定到同一个内部 `userId`；
6. 管理员可以在小程序查看“我的”、更换小程序头像和退出当前会话；
7. 网页、小程序、数据库和审计记录对同一管理员使用同一个内部身份。

S01 完成后，可以独立演示“飞书登录 → 短信申请 → 最高管理员审核 → 微信手机号绑定 → 跨端同一身份 → 退出并重新登录”。订单、发货、返修等业务数据仍不在本工单出现。

## 2. 已确认范围与权限边界

### 2.1 本工单包含

- 内部用户、飞书与微信外部身份、网页与小程序会话；
- 飞书 OAuth `state`、短信验证码挑战、管理员申请；
- 最高管理员受控初始化；
- 最高管理员审核管理员申请；
- 最高管理员启用、停用普通管理员；
- 管理员网页端登录、申请、审核状态、管理员申请和管理员账号管理入口；
- 管理员小程序微信登录、手机号绑定、绑定状态、“我的”、小程序头像和退出登录；
- 相关权限、审计、幂等、限频、敏感信息脱敏和自动化测试。

### 2.2 管理员申请与工厂用户申请必须分开

- **管理员申请只有最高管理员可以查看和审核。**普通管理员不能看到管理员申请入口，也不能调用管理员申请查询或审核接口。
- **工厂用户申请由所有启用状态的管理员审核。**这里的“所有管理员”包括普通管理员和最高管理员。
- 工厂用户申请、工厂绑定和工厂用户启停属于 S02；S01 只建立可复用的角色、会话和权限校验基础，不提前制作对应页面或接口。

### 2.3 本工单不扩展的角色

一期业务角色仍只有“管理员”和“工厂用户”。“最高管理员”只是管理员角色内的系统权限标记，不创建第三种业务角色。

## 4. 数据库迁移与领域模型

在真实 MySQL 8 测试库中新增 S01 所需表和索引。所有时间戳保存 UTC，手机号、验证码、会话凭证和外部授权结果不得明文写入日志。

### 4.1 `users`

保存内部唯一用户身份，至少包括：

- 内部 `user_id`；
- 当前业务角色，未获角色时为空，S01 只授予管理员角色；
- `is_super_admin` 最高管理员标记；
- 启用或停用状态；
- 飞书显示姓名和网页端飞书头像引用；
- 加密手机号、手机号查询摘要和脱敏手机号；
- 小程序头像文件引用；
- 版本、创建和更新时间。

约束：

- 最高管理员必定同时是管理员；
- 最高管理员不能由普通申请审核产生；
- 最高管理员不能通过网页人员管理入口停用；
- 同一个已验证手机号不能归属于多个内部用户；
- 网页端飞书头像和小程序头像分开保存，修改小程序头像不得覆盖飞书头像。

### 4.2 `external_identities`

保存飞书和微信身份到内部 `user_id` 的映射：

- 平台类型；
- 应用、租户或环境范围标识；
- 平台用户标识；
- 内部 `user_id`；
- 绑定和最后登录时间。

平台、应用或租户范围和平台用户标识组成唯一约束。测试小程序 AppID 与公司正式 AppID 必须属于不同身份范围，即使平台返回相同格式的用户标识也不得混用。

### 4.3 `oauth_states`

保存短期、一次性的飞书 OAuth 状态：

- `state` 摘要；
- 发起终端、回跳目标；
- 过期、使用和创建时间。

原始 `state` 只发给浏览器，不写日志；回调必须同时满足存在、未过期、未使用，成功或失败处理后均不能再次使用。

### 4.4 `user_sessions`

保存网页和小程序会话摘要：

- 内部用户、终端类型和凭证摘要；
- 会话过期、最后活动和撤销时间；
- 网页 CSRF 校验所需摘要；
- 小程序访问凭证与续期凭证的关联或轮换信息。

数据库只保存不透明凭证的摘要。退出、账号停用、角色撤销后必须撤销相关会话；后端每次访问都以数据库当前用户状态和权限为准，不能只相信登录时写入凭证的旧角色。

### 4.5 `sms_challenges`

保存短信验证挑战：

- 手机号摘要、验证用途和验证码摘要；
- 过期时间、发送状态、失败原因摘要；
- 已尝试次数、验证时间和作废时间；
- 发起用户、请求编号和创建时间。

验证码不保存明文。新验证码发送成功后，同一用户和用途下的旧未使用验证码作废。

### 4.6 `admin_applications`

保存管理员申请和完整审核证据：

- 申请用户、飞书身份快照和已验证手机号；
- 待审核、已通过或已拒绝状态；
- 申请、审核人和审核时间；
- 拒绝原因；
- 版本和重新申请关联信息。

同一用户只能有一条当前待审核申请。已拒绝记录继续保留，重新申请创建新记录或明确关联新版本，不覆盖历史审核事实。

### 4.7 `stored_files`

为小程序头像建立技术设计中已批准的最小私有文件记录：

- 私有桶、随机对象键、原文件名、MIME、大小和文件摘要；
- 上传人和创建时间；
- 用户小程序头像通过明确外键引用。

S01 只使用该表保存管理员小程序头像，不提前实现订单、发货、返修或 Excel 文件关系。测试使用临时文件存储，真实联调使用项目独立的受控测试桶。

## 5. 后端模块与外部适配器

### 5.1 模块位置

在 `server/app/modules/identity_access/` 建立身份访问模块，通过模块公开命令和查询完成：

- 飞书身份解析和内部用户建立；
- 短信挑战发送与验证；
- 管理员申请提交、重新申请、审核和状态查询；
- 微信身份识别、手机号唯一匹配和绑定；
- 会话签发、续期、撤销和权限校验；
- 普通管理员启停；
- 最高管理员受控初始化；
- 小程序头像登记和替换。

路由不得自行修改用户、申请或会话表；必须调用该模块的公开操作。跨表写入、审核授予角色、微信绑定和会话撤销使用事务。

### 5.2 外部适配器

建立并注入以下接口：

- `FeishuIdentity`：生成 OAuth 地址、校验回调结果并取得企业用户身份；
- `SmsSender`：发送管理员申请验证码；
- `WechatIdentity`：使用 `wx.login` 临时 code 换取微信身份，并使用手机号授权 code 从微信服务端取得号码；
- `AvatarStore`：保存、读取和替换小程序头像对象。

本地和 CI 使用可控假适配器，不能调用真实外部接口。共享测试环境使用受控测试凭证。真实适配器不得把授权 code、App Secret、短信密钥、完整手机号或外部原始敏感响应写入日志。

短信服务商尚未确认时，先完成稳定接口、假适配器和业务测试；真实短信适配器必须等服务商和测试账号确定后再实现，不能擅自选择或购买短信服务。

### 5.3 最高管理员初始化

提供受控命令而不是手工 SQL，要求：

- 根据已确认的飞书应用范围和飞书用户唯一标识建立或提升最高管理员；
- 支持配置多名最高管理员；
- 重复执行幂等；
- 不接受普通网页申请直接提升为最高管理员；
- 记录操作者来源、目标用户、执行时间和结果审计；
- 命令参数和日志不出现访问密钥、Cookie 或验证码。

生产最高管理员名单和真实飞书身份由用户或公司管理员在部署阶段提供，不写入仓库。

## 6. API 契约

所有接口使用 `/api/v1` 前缀，错误响应继续使用 S00 的统一结构和 `requestId`。具体字段通过 OpenAPI 固化并生成网页端 TypeScript 类型；小程序共享相同的公开响应类型定义。

| 分组 | 方法与路径 | 权限和结果 |
|---|---|---|
| 飞书登录 | `GET /auth/feishu/start` | 生成一次性 `state` 并跳转飞书 OAuth |
| 飞书回调 | `GET /auth/feishu/callback` | 校验 `state`、解析身份、建立网页会话并跳转对应状态页 |
| 当前用户 | `GET /me` | 返回当前用户、角色、最高管理员标记、状态和终端可用能力 |
| 网页退出 | `POST /auth/logout` | 撤销当前网页会话并清除 Cookie |
| 短信挑战 | `POST /sms/challenges` | 向当前飞书用户提交的本人手机号发送申请验证码 |
| 提交申请 | `POST /admin-applications` | 校验验证码并创建待审核申请 |
| 我的申请 | `GET /admin-applications/me` | 返回当前申请状态和允许的下一步 |
| 申请列表 | `GET /admin/admin-applications` | 仅最高管理员查看和筛选管理员申请 |
| 申请详情 | `GET /admin/admin-applications/{id}` | 仅最高管理员查看申请和审核记录 |
| 通过申请 | `POST /admin/admin-applications/{id}/approve` | 仅最高管理员授予普通管理员角色 |
| 拒绝申请 | `POST /admin/admin-applications/{id}/reject` | 仅最高管理员，拒绝原因必填 |
| 管理员列表 | `GET /admin/users?role=admin` | 仅最高管理员查看普通管理员和状态 |
| 启停管理员 | `POST /admin/users/{id}/enable`、`/disable` | 仅最高管理员；最高管理员目标不可停用 |
| 微信登录 | `POST /mini/auth/wechat` | 解析微信身份；已绑定则登录，未绑定则返回需授权手机号 |
| 手机号绑定 | `POST /mini/auth/phone` | 后端向微信换取手机号并执行唯一匹配，不接受客户端明文号码作为依据 |
| 小程序续期 | `POST /mini/auth/refresh` | 轮换短期访问凭证和续期凭证 |
| 小程序退出 | `POST /mini/auth/logout` | 只撤销当前小程序会话，不解除身份绑定 |
| 小程序头像 | `POST /mini/me/avatar` | 登录管理员上传并替换自己的小程序头像 |

写接口按风险使用幂等键或版本校验。审核、启停和头像替换不得因重复请求产生重复角色授予、重复审核记录或孤立文件。

### 6.1 状态码

- `401`：没有有效会话或会话已撤销；
- `403`：角色、最高管理员标记或终端能力不允许；
- `404`：申请、用户或文件对当前用户不可见；
- `409`：申请已处理、版本冲突、手机号归属冲突或重复绑定冲突；
- `422`：手机号、验证码、拒绝原因或文件格式校验失败；
- `429`：短信、登录或验证码尝试超过频率限制；
- `503`：飞书、微信、短信或文件存储暂不可用。

## 7. 管理员网页端

在 `admin-web/src/modules/auth/`、`pages/`、`router/`、`stores/` 和统一 API 客户端内实现已确认原型对应页面。

### 7.1 登录和申请

- 未登录访问业务路由时进入登录页；
- 登录页只显示已确认的“通过飞书登录”入口；
- 飞书回调处理中显示明确加载状态，失败时显示可重试错误；
- 无角色用户只能进入管理员申请和自己的申请状态页，不能读取任何业务数据；
- 申请页姓名和网页头像来自飞书身份，只填写手机号和六位短信验证码，不填写职位；
- 待审核页支持刷新状态；
- 已拒绝页展示拒绝原因并允许重新申请；
- 已停用用户显示停用状态并拒绝进入业务路由；
- 网页退出只撤销当前网页会话。

### 7.2 最高管理员入口

- 只有最高管理员显示管理员申请入口；
- 支持查看待审核和历史申请详情；
- 通过前明确提示将授予普通管理员角色；
- 拒绝必须填写原因；
- 管理员账号列表允许最高管理员启用或停用普通管理员；
- 最高管理员不能停用自己或其他最高管理员；
- 普通管理员直接请求页面或接口均返回无权限，不能只靠前端隐藏按钮。

S01 不展示工厂用户申请页签。S02 加入该页签时，普通管理员和最高管理员都可以查看和审核工厂用户申请。

### 7.3 暂未实现的业务入口

S01 登录成功只证明管理员身份可用，不提前实现订单看板、订单与发货、产品资料或工厂资料。若公共外壳必须提供登录后的落点，只使用清楚标识为后续工单实现的最小空状态，不伪造业务数据或业务操作。

## 8. 管理员小程序

继续使用 `miniprogram/` 下同一个微信原生 TypeScript 项目，不创建管理员和工厂两套工程。

### 8.1 登录与手机号绑定

- 启动时先调用 `wx.login`，由后端识别微信身份；
- 已绑定且启用的管理员直接恢复同一内部账号；
- 未绑定身份只有在用户同意协议后才请求官方手机号授权；
- 后端使用微信手机号授权 code 获取号码，不接受前端自行填写的手机号；
- 手机号匹配已通过申请时完成绑定并签发小程序凭证；
- 匹配待审核申请时显示“管理员申请审核中”；
- 匹配已拒绝申请时显示拒绝状态并提示前往网页端重新申请；
- 没有申请时提示先前往管理员网页端申请；
- 无法唯一匹配时不合并账号，提示联系最高管理员；
- 账号停用时显示停用状态并阻止读取业务数据；
- 绑定成功后再次登录不重复要求手机号授权。

测试 AppID 不支持真实手机号能力时，只能用假适配器验证业务逻辑；真实手机号绑定必须使用具备相应能力的受控小程序 AppID 和真机完成。

### 8.2 “我的”、头像和退出登录

- 展示小程序头像、姓名、管理员类型和账号状态；
- 默认使用可取得的微信头像；没有可用头像时显示默认占位，并允许用户通过微信官方头像选择能力更换；
- 新头像上传后保存到私有文件存储，只影响小程序头像，不覆盖网页端飞书头像；
- 支持查看头像和更换头像；
- 退出登录前二次确认；
- 退出只撤销当前小程序会话，不删除微信身份、手机号或内部 `userId` 绑定；
- 重新登录通过已绑定微信身份恢复账号，不重复授权手机号。

S01 的“我的”只实现身份信息、头像和退出登录。通知设置及微信订阅消息属于 S11，本工单不制作假开关或假授权结果。

### 8.3 页面注册边界

S01 只注册身份状态页和实现本工单所需的管理员个人页，不提前制作订单、发货或返修页面。后续工单接入完整底部导航时复用同一身份状态和会话模块。

## 9. 安全、隐私与审计

### 9.1 登录和会话

- 网页 Cookie 使用 `Secure`、`HttpOnly` 和合适的 `SameSite` 设置；
- 所有网页写请求执行 CSRF 校验；
- OAuth `state` 随机、短期、一次性；
- 小程序访问凭证短期有效，续期凭证轮换并可撤销；
- 不在 `localStorage` 保存网页会话凭证；
- 不把 App Secret、短信密钥、授权 code、Cookie、访问凭证或完整外部响应返回前端。

### 9.2 手机号和验证码

- 完整手机号加密保存；
- 唯一匹配使用带服务端密钥的不可逆摘要；
- 页面和日志只展示脱敏号码；
- 验证码只保存摘要，并限制有效期、发送间隔、单日次数和错误尝试次数；
- 发送和校验响应避免泄露某个手机号是否已注册；
- 加密密钥和摘要密钥只放受控环境配置，不进入 Git。

### 9.3 权限和审计

### 10.1 后端领域与 MySQL 集成测试

3. OAuth `state` 缺失、伪造、过期或重复使用均失败；
4. 验证码正确时可以提交申请，错误、过期、超次数或已使用时失败；
5. 待审核申请不能重复提交，拒绝后可重新申请且保留旧记录；

7. 最高管理员通过申请后只授予普通管理员，不授予最高管理员标记；

10. 最高管理员可以停用普通管理员，但不能停用最高管理员；
11. 账号停用后网页和小程序已有会话立即失效，重新启用不自动恢复旧会话；
12. 已通过申请的同手机号唯一匹配并绑定到同一内部 `userId`；
