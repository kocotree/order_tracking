## 1. 工单目标

本工单打通“worker 从聚水潭读取产品与规格 → 业务模块严格筛选六个分类中的启用资料 → MySQL 保存只读产品快照 → 管理员网页端搜索和查看”的闭环：

1. 首次任务分页扫描聚水潭产品和规格，只保存六个指定商品分类中来源状态为启用的资料；
2. 后续任务按来源修改时间增量读取，幂等处理新增、修改、启用、停用、进入分类和移出分类；
3. 只有已成功落库且当前可用的规格可以被 S04、S05 和 S09 等后续工单严格匹配；
4. 管理员网页端沿用已确认原型，只读搜索、排序和分页查看产品规格；
5. 来源图片有值时进入私有缓存流程，失败可重试且不伪造图片；
6. 同步批次失败时不推进成功游标，不把半完成批次标记为成功。

S03 完成后，本地可以用可控假聚水潭适配器独立演示首次扫描、增量变化和产品只读页面。真实聚水潭正式 OpenAPI 联调没有完成前，只能记录“代码与假适配器验证通过，真实聚水潭产品同步联调待补”。

## 2. 已确认业务范围

### 2.1 商品分类白名单

只允许以下六个聚水潭“商品分类”原值：

- 童帽春夏；
- 童配春夏；
- 童装春夏；
- 童帽秋冬；
- 童配秋冬；
- 童装秋冬。

分类按聚水潭返回原值精确匹配，不使用包含、前缀、后缀、别名或模糊匹配。该白名单是 V1.42 的版本化业务规则，放在服务器产品同步模块中，不提供网页端配置入口；以后如需增删分类，应先修改正式需求和测试。

### 2.2 启用和退出范围规则

- 首次扫描时，只有分类在白名单内且来源 `enabled` 明确为启用的产品和规格才能成为可用于新订单的本地快照；
- 分类不在白名单、来源状态非启用、分类缺失或启用状态缺失的来源记录不能作为可用产品；
- 已经同步的产品或规格后续被停用时，标记为不可用于新订单，不物理删除；
- 已经同步的产品或规格后续移出白名单分类时，同样标记为不可用于新订单，不物理删除；
- 来源记录后续重新启用并重新进入白名单时，可以在成功增量批次中恢复为可用于新订单；
- 后续订单、发货、合同和返修必须保存自己的业务快照，不因产品资料后来停用、改名或换图而改写历史。

### 2.3 来源职责

- 聚水潭是产品、规格和图片的唯一上游；
- 飞书是 S05 的订单来源，不用于创建、补齐或覆盖产品主数据；
- 当前聚水潭只读插件只用于前期只读核验，不能被正式服务器代码调用，也不能替代正式 OpenAPI 联调；
- 管理员和工厂均不能在本系统内新增、编辑、启用、停用或删除产品和规格。

## 5. 数据库迁移与领域模型

迁移和集成测试必须使用真实 MySQL 8、InnoDB 和 `utf8mb4`，不能用 SQLite 替代。来源时间按确认后的聚水潭语义解析并统一保存 UTC。

### 5.1 `products`

至少保存：

- 内部 `product_id`；
- 聚水潭来源 `i_id`，作为页面“货号”，全局唯一；
- 产品名称，按正式需求全系统唯一；
- 是否至少有一个可用于新订单的规格；
- 图片来源引用、私有缓存引用和图片缓存状态；
- 来源修改时间、首次同步时间、最后成功同步时间；
- 创建和更新时间。

`i_id` 到页面“货号”的真实字段含义必须在正式 OpenAPI 样例中复核；未完成真实字段核验前，假适配器按已批准映射提供该值，但不得把假数据描述为真实字段验收。

### 5.2 `product_variants`

至少保存：

- 内部 `variant_id` 和所属 `product_id`；
- 聚水潭 `sku_id`，作为页面“产品编码”，全局唯一；
- 聚水潭 `properties_value`，原样保存为组合字段“颜色/规格”；
- 来源商品分类原值；
- 来源启用状态和是否可用于新订单；
- 来源修改时间、首次同步时间、最后成功同步时间；
- 创建和更新时间。

同一产品内“颜色/规格”组合唯一。`sku_id`、产品名称或颜色/规格冲突不得静默覆盖，当前批次失败并保留可追溯错误。

### 5.3 `product_sync_runs`

至少保存：

- 任务类型：首次扫描或增量；
- 状态：待处理、运行中、成功或失败；
- 起始游标、候选结束游标和最终成功游标；
- 开始、结束时间和 worker 标识；
- 已读取页数和记录数；
- 纳入、新增、更新、忽略、停用、移出范围和图片待处理数量；
- 不含敏感值的错误摘要和请求编号。

只有全部来源分页读取、字段校验、数据库事务和必要图片任务建立成功后，才把批次标记为成功并推进成功游标。失败批次保留记录但不推进游标。

### 5.4 图片缓存

- 来源 `pic` 为空时页面显示原型已有的无图状态，不创建虚假图片；
- 图片下载使用受控适配器，缓存到项目私有文件存储，不暴露上游凭证；
- 图片任务使用稳定去重键，失败记录原因并按现有 worker 机制重试；
- 图片失败不改变产品字段同步结果，但缓存状态必须可追踪；
- 新图片成功缓存后替换当前缓存引用，历史订单和历史导出继续使用自己的快照。

## 6. 聚水潭适配器与同步事务

### 6.1 `JstProductSource` 公开接缝

适配器只负责把正式 OpenAPI 响应转换为稳定来源对象，至少提供：

- 首次分页扫描；
- 按确认后的修改时间语义分页增量读取；
- `i_id`、`sku_id`、`name`、`properties_value`、`pic`、`category`、`enabled` 和来源修改时间；
- 页码、是否还有下一页和必要的来源请求标识；
- 超时、限频、授权失败、字段缺失和异常响应的稳定错误类型。

业务分类白名单和启用判断必须由产品同步模块再次执行，不能只相信适配器或上游请求过滤。

### 6.2 首次扫描

1. 建立唯一活动的首次扫描任务；
2. 分页读取来源并验证分页连续性、必要字段和重复标识；
3. 忽略从未同步且不符合六分类启用规则的记录；
4. 收集符合规则的标准化产品和规格；
5. 来源分页全部成功后，在一个 MySQL 事务内完成幂等写入、建立去重图片任务、同步批次成功状态和成功游标；
6. 事务提交后由图片任务处理器实际下载和缓存图片。

外部网络读取期间不得长时间占用数据库事务或行锁。

### 6.3 增量同步

1. 从最后成功游标开始，按正式接口确认的边界语义读取所有相关修改记录；
2. 增量请求不能只限制为当前白名单分类或当前启用状态，否则无法发现已同步资料退出范围；
3. 新进入白名单且启用的资料幂等新增或恢复；
4. 白名单内的已同步资料按来源修改时间更新；
5. 已同步资料被停用或移出白名单时标记不可用于新订单；
6. 从未同步且与本系统无关的记录忽略；
7. 全部页面和数据库事务成功后才推进游标；同一时间只允许一个有效产品同步任务。

正式 OpenAPI 对修改时间的包含边界、排序稳定性、删除记录和分类过滤能力尚未验证。实现真实适配器前必须使用受控账号核验；若条件缺失，保留接口和假适配器，不猜测真实语义。

## 7. worker 与内部触发

- 复用 S00 `background_jobs`、租约领取、失败恢复和 worker 进程，不引入 Celery 或 Redis；
- 增加产品首次扫描、产品增量同步和图片缓存处理器；
- 本地和运维验收提供无网页入口的受控命令或内部操作接缝，用于建立首次任务和单次增量任务；
- 生产增量间隔由非敏感服务器配置提供，默认建议值只有在正式接口限频核验后才能启用；
- 普通 API 启动不能自动执行首次全量扫描，生产首次同步需由受控上线步骤明确触发；
- 任务参数、结果和日志不得包含凭证、签名 URL 或无关完整原始响应。

## 8. 后端查询 API 与权限

### 8.1 管理员产品列表

提供 `GET /api/v1/admin/products`：

- 仅普通管理员和最高管理员可访问；工厂用户和未授权用户拒绝；
- 返回规格级列表，每行包含货号、图片可用状态或受控引用、产品编码、产品名称、颜色/规格；
- 只返回当前已成功落库且可用于新订单的产品规格；
- 支持按货号、产品编码、产品名称或颜色/规格进行同一关键词搜索；
- 支持原型已有字段排序和服务端分页；
- 不返回成本价、采购价、库存、供应商、仓位、来源原始响应或其他未确认字段。

图片如需独立读取，使用受管理员权限保护的产品图片接口或短期受控 URL；缺图返回统一无图结果，不把对象存储设为公开桶。

### 8.2 错误、审计和安全

- 同步任务记录系统操作者、任务类型、结果和请求编号；受控人工触发时同时记录内部管理员或运维身份；
- 列表查询不把每次读取写入业务审计，但保留现有结构化访问日志；
- 日志不得包含聚水潭凭证、签名、完整原始响应、Cookie、Token 或对象存储密钥；
- 上游未配置返回稳定“外部集成未配置/暂不可用”错误，不静默回退到假数据；
- 假适配器只在测试或显式 `local_demo` 环境注入，普通开发、共享测试和生产不得存在默认假同步后门。

## 10. TDD 顺序和测试接缝

核心产品同步使用 TDD。测试只通过公开产品同步服务、`JstProductSource` 接口、worker 处理器、`/api/v1` 和网页公开交互观察行为，不直接测试私有函数或复制实现算法计算期望值。

按一个失败测试到一个最小实现的垂直切片推进：

1. 六分类精确白名单、启用规则和标准化来源对象；
2. 产品、规格和同步批次 MySQL 8 迁移及唯一约束；
3. 首次多页扫描、无关资料忽略和事务落库；
4. 批次失败、重试和成功游标；
5. 增量新增、更新、进入范围、停用、移出范围和重新启用；
6. worker 任务领取、单活动任务和失败恢复；
7. 图片任务去重、失败重试和无图结果；
8. 管理员产品 API、权限、搜索、排序和分页；
9. 管理员网页产品列表；
10. OpenAPI 类型生成、漂移检查和三端回归。

必测场景至少包括：

- 六个分类分别可纳入，近似名称、前后缀、空分类和其他分类均不纳入；
- 白名单分类但 `enabled` 非启用、为空或非法时不成为可用产品；
- 同一 `i_id` 和 `sku_id` 重复读取幂等，同一批次不重复建记录；
- `sku_id` 全局唯一、产品名称唯一、产品内颜色/规格唯一约束在真实 MySQL 8 生效；
- 多页乱序、重复页记录、空页、超时、限频和字段异常得到稳定结果；
- 任一来源页失败或数据库事务失败时不推进游标，不把批次标记成功；
- 相同增量窗口重复执行不重复产品或规格；
- 产品或规格进入白名单、移出白名单、启用、停用和重新启用按规则变化；
- 已停用或移出范围的资料不再出现在可用查询，但数据库历史记录仍存在；
- 图片为空、下载失败、重复任务和重试成功符合规则；
- 管理员可以查询，工厂用户和未授权用户不能查询；
- 搜索、排序、分页总数和空状态与 API 契约一致；
- S01 身份、S02 工厂及用户回归测试保持通过。
