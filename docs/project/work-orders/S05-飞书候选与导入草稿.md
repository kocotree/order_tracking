## 1. 工单目标

本工单打通“管理员手动获取飞书新订单 → worker 分页读取指定视图 → 形成并校验完整订单候选 → 管理员排除或确认导入 → 复用 S04 草稿、派工和发布流程”的垂直闭环：

1. 管理员网页端在“待导入订单”页手动创建一次飞书获取任务，同一时刻只存在一个活动任务；
2. worker 分页读取“生产部”多维表格中“生产部--下单表以及成品进度表”的“总表（误删）”视图；
3. 系统以飞书 `record_id` 保存来源快照，以订单编号聚合完整候选，严格校验来源字段、首次导入范围、本地产品、工厂、工厂用户、跟单人员和合同出货时间；
4. 页面展示获取进度、结果数量、上次成功获取时间，以及“待处理、已导入”候选列表和详情；
5. 管理员可以二次确认后整单排除待处理候选，系统不删除或回写飞书数据，后续获取不再恢复该候选；
6. 只有全部明细校验通过的候选可以确认导入；导入在一个 MySQL 事务中生成来源为 `feishu` 的 S04 草稿、订单明细和工厂派工，并把候选标记为已导入；
7. 草稿在发布前继续只对管理员网页端可见，之后沿用 S04 的编辑、发布、三端查询和状态流程，不另建订单流程；
8. 重复获取、重复确认、worker 重试或并发操作不得重复创建候选、草稿、派工、审计记录或活动任务。

S05 完成后，管理员可以用一组同时包含新增、已存在、跳过和失败记录的飞书样例完成获取，确认一张候选后只生成一张可继续编辑和发布的草稿订单。

## 2. 已确认业务范围

### 2.1 来源和读取方式

- 一期只读指定 Base、数据表和视图，不读取同一 Base 的其他表，不写回飞书；
- 每次获取由管理员手动触发，不增加定时自动发现任务；
- worker 按飞书服务端分页顺序读取指定视图，每页成功处理后继续下一页；不能只读取第一页；
- MySQL 以“来源 Base＋数据表＋飞书 `record_id`”作为来源记录唯一键；“下单明细ID”只作为业务快照字段，不替代飞书 `record_id`；
- 同一来源记录在候选仍为待处理时再次出现，可以更新该候选的来源快照并重新校验；候选已导入或已排除后不再跟踪飞书后续修改；
- 指定视图当前约 1,581 行。实现按全视图分页读取、在 MySQL 中增量识别未导入且未排除的来源记录，避免依赖易漂移的公式更新时间游标而漏单；
- 单行解析失败只记录该来源记录错误并计入失败数量，其余来源记录继续处理；任务级失败不得删除或回滚既有候选、草稿或正式订单；
- 正式运行使用服务器端企业自建应用身份和最小只读 Base 权限；本次用户身份只读核验成功不等于生产应用授权已经完成。

### 2.2 已核验的真实来源字段契约

2026-08-22 已用当前用户既有飞书登录态只读核验目标 Base、数据表、视图和字段；未修改飞书数据。S05 按以下来源字段读取，启动任务时必须检查字段存在且类型兼容，字段缺失或类型漂移时整次任务失败并给出稳定错误，不猜测替代字段。

| 来源字段 | 当前类型 | S05 用途 |
|---|---|---|
| 飞书 `record_id` | 系统记录标识 | 来源幂等主键 |
| 下单明细ID | 自动编号 | 来源业务快照和人工追溯 |
| 订单编号 | 文本 | 聚合完整订单、映射系统订单编号 |
| 下单时间 | 日期时间 | 映射订单日期 |
| 商品名称 | 单选返回数组 | 严格匹配产品名称 |
| 产品颜色&规格 | 文本 | 原值映射颜色/规格，不拆分、不模糊匹配 |
| 产品编码 | 数字 | 按无小数的十进制字符串匹配 S03 聚水潭 `sku_id`，不得转为浮点数或科学计数法 |
| 工厂 | 单选返回数组 | 严格匹配系统日常工厂名称 |
| 下单数 | 数字 | 映射该行工厂下单数量，必须为正整数 |
| 跟单人员 | 单选返回数组 | 映射主订单唯一跟单人员 |
| 生产计划出货时间（提前或者推迟 的时间） | 日期时间 | 映射系统合同出货时间 |
| 出货总数 | 公式文本 | 判断首次导入范围 |
| 未出数量 | 公式文本 | 判断首次导入范围并展示来源进度 |
| 一级分类 | 公式文本 | 映射已确认的“服装/帽子”展示分类 |

多维表公式字段“合同出货时间”不作为一期交期来源；裁剪、裁剪进度、绣花、印花和其他生产进度字段不导入系统。

### 2.3 完整订单聚合和首次导入范围

- 一行对应“订单编号＋产品规格＋工厂＋下单数量”的一条来源明细，同一订单的全部来源行按规范化后的订单编号聚合；
- 同一订单内相同产品规格可以分配给多个工厂；导入时按产品规格汇总 `order_lines`，按“产品规格＋工厂”汇总 `order_assignments`；
- 同一订单所有来源行的订单日期、跟单人员和合同出货时间必须分别一致且唯一；为空、多值或不一致时保留为待处理候选并显示问题；
- 只有同一订单全部明细的“出货总数”均为 0，且至少一条明细“未出数量”大于 0，才属于首次上线可导入范围；
- 任意明细“出货总数”大于 0 时，候选保留在待处理并标记“不符合首次导入范围”，不得确认导入；
- 全部明细“未出数量”均不大于 0 时视为已结束订单，本次获取计入跳过，不在候选列表出现；
- 一个候选必须包含本次视图中该订单的全部来源行；页面和接口不允许选择、排除或导入候选中的部分明细。

### 2.4 严格校验

候选保存后执行以下校验，并保存候选级或明细级问题代码、字段和用户可读提示：

1. 订单编号、订单日期、产品名称、颜色/规格、产品编码、工厂、下单数、跟单人员和合同出货时间完整且类型合法；
2. 订单编号未被任意现有系统订单占用，且未对应另一条未排除候选；
3. 产品编码严格匹配 S03 当前可用于新订单的 `product_variants.sku_id`，同时产品名称和颜色/规格与本地快照严格一致；
4. 不使用模糊匹配，不因产品名称接近或颜色/规格包含关系自动选择规格，也不创建本地产品资料；
5. 工厂名称严格匹配启用的系统工厂资料，不维护来源别名；
6. 每个涉及工厂至少有一名审核通过且启用的工厂用户；
7. 跟单人员只允许“烧麦、松子、橄榄、大葱、青椒”，同一订单全部明细一致且只能有一人；
8. 同一订单全部明细的订单日期和合同出货时间分别一致且只能有一个；
9. 下单数必须为正整数，公式数量必须能严格解析为整数；
10. 同一来源记录未被排除或导入，整单满足第 2.3 节首次导入范围。

校验问题只由重新获取并重新读取当前来源、本地产品、工厂和用户资料后更新；页面不提供直接编辑飞书来源字段或手工覆盖匹配结果的功能。

### 2.5 候选状态、排除和导入

候选持久化状态只使用：

- `PENDING`：待处理，可查看、整单排除；全部校验通过时可确认导入；
- `IMPORTED`：已生成对应草稿或后续正式订单；不等同于订单已发布；
- `EXCLUDED`：管理员已排除，不在页面页签中展示，不提供恢复入口。

排除候选时：

- 只允许 `PENDING`，要求二次确认和 `Idempotency-Key`；
- 保存操作人、时间、当时全部飞书来源记录ID和审计日志；
- 不删除来源快照、不删除或回写飞书记录；
- 后续获取遇到这些来源记录时计入跳过，不重新创建候选。

确认导入时：

- 只允许全部校验通过的 `PENDING` 候选，要求二次确认和 `Idempotency-Key`；
- 锁定候选、来源行和订单编号，在事务内重新执行全部校验，不能只相信页面或上次获取结果；
- 通过 `orders` 模块的事务参与式草稿创建接口生成来源为 `feishu` 的 S04 `orders`、`order_lines` 和 `order_assignments`；
- 候选状态、对应 `order_id`、导入人、导入时间、来源快照和审计日志与草稿在同一事务提交；
- 任一步失败整体回滚，不留下半张订单、部分明细、部分派工或已导入候选；
- 相同幂等键返回首次结果；不同请求重复确认返回同一已生成订单，不再创建第二张草稿；
- 导入草稿初始 `version=1`、生命周期为 `DRAFT`、工厂不可见，后续编辑、发布和查询完全复用 S04。

### 2.6 批量确认语义

- 列表沿用已确认原型，允许勾选完整且“可导入”的候选后批量确认；不允许选择候选内部分明细；
- 批量操作以“一个候选一个事务”执行，不把多张订单放进一个超大事务；某张失败不回滚已成功的其他候选；
- 返回每张候选的成功或失败结果及生成的 `order_id`，页面汇总“成功、失败”数量并保留失败候选；
- 单张详情页的确认导入与批量确认调用同一候选确认接口和同一校验逻辑。

## 7. 模块、接口与事务设计

### 7.1 `order_import` 模块

该模块提供小而完整的接口：

- 创建或复用活动获取任务；
- 查询任务结果；
- 查询候选列表和详情；
- 排除候选；
- 确认单张或批量候选为草稿。

飞书分页、字段解析、完整订单聚合、严格校验、来源幂等、候选状态和导入事务隐藏在模块内部，不让页面或 worker 复制业务判断。

### 7.2 飞书来源 seam 和 adapter

定义 `FeishuOrderSource` seam，只暴露“按页读取指定视图并返回规范化来源页”的接口：

- 正式 adapter 使用企业自建应用的服务端凭据读取 Base；
- 本地/自动化 adapter 返回固定多页样例，可注入单页失败、字段漂移和重复记录；
- 未配置 adapter 在本地明确返回 `feishu_order_source_not_configured`，不能静默使用当前用户登录态或 mock 数据；
- adapter 负责飞书鉴权、分页参数、单元格返回形状和上游错误脱敏，`order_import` 模块负责业务语义。

### 7.3 复用 S04 草稿创建

现有 `OrderService.create_draft()` 固定创建 `manual` 草稿并自行开启事务，不能直接满足候选与草稿同事务提交。S05 只做一次最小深化：

- `orders` 模块新增内部可参与现有事务的草稿创建接口，接收明确的 `source`、订单头、明细和派工；
- S04 网页手工创建继续通过原 `OrderService.create_draft()` 调用该接口并固定 `source=manual`；
- S05 候选确认在自己的事务中调用同一接口并固定 `source=feishu`；
- 产品可用性、订单编号唯一、规格合并、工厂匹配、数量约束、订单快照和审计规则只保留一份实现；
- 事务参与接口只在后端模块内部使用，不暴露 SQLAlchemy Session、来源选择或任意 `source` 给 HTTP 客户端。

### 7.4 worker 失败和恢复

- worker 领取通用后台任务后把导入任务从 `PENDING` 改为 `RUNNING`；
- 每个来源页的候选更新使用短事务，避免单次任务持有全表长事务；
- 相同 `run_id` 重试时按来源记录和候选唯一键继续，不重复计数或建候选；
- 页读取失败按通用 worker 退避重试；最终失败时把导入任务标为 `FAILED` 并释放活动槽位；
- worker 崩溃后的通用过期租约恢复继续生效，运行任务不得永久阻塞下一次手动获取。

## 8. 后端接口与权限

所有接口位于 `/api/v1`，只允许已启用管理员网页会话调用；管理员小程序和工厂会话直接请求返回 403。列表统一服务器筛选、排序、分页和总数，响应包含 `requestId`。

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/admin/import-runs` | 创建或复用当前活动获取任务 |
| `GET` | `/admin/import-runs/{runId}` | 轮询任务状态和结果数量 |
| `GET` | `/admin/import-runs/latest` | 返回当前活动任务和上次成功获取时间 |
| `GET` | `/admin/import-candidates` | 查询待处理或已导入候选 |
| `GET` | `/admin/import-candidates/{candidateId}` | 查询候选完整来源快照、明细和问题 |
| `DELETE` | `/admin/import-candidates/{candidateId}` | 整单排除待处理候选 |
| `POST` | `/admin/import-candidates/{candidateId}/confirm` | 确认单张候选导入草稿 |
| `POST` | `/admin/import-candidates/confirm` | 批量确认完整候选，每张独立事务 |

`POST /admin/import-runs`、排除和确认要求 `Idempotency-Key`。典型错误：

- `400/422`：请求字段、筛选或来源类型不合法；
- `403`：角色或终端不允许；
- `404`：候选、任务不存在或不可见；
- `409`：候选状态、订单编号、并发版本或幂等冲突；
- `422`：候选当前校验不通过，返回字段级问题；
- `503`：飞书来源未配置、权限不足、限频或暂不可用，响应不包含上游凭据和完整原始响应。
