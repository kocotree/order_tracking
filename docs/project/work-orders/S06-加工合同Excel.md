## 1. 工单目标

本工单打通“管理员网页端订单详情 → 选择一个工厂 → 校验订单和工厂合同资料 → 首次生成合同编号与签订日期 → 按正式模板生成私有 `.xlsx` → 授权下载 → 重复导出保持历史合同稳定”的垂直闭环：

1. 一份加工合同严格对应“一个主订单＋一个工厂”，只包含该工厂在该订单中的派工明细；
2. 只有主订单统一已发数量为 0 时，管理员网页端才能首次或重复导出；带初始已发数量的订单不能导出；
3. 首次导出在 MySQL 事务中生成稳定合同编号、签订日期和不可变业务快照；
4. 同日同厂第一份合同编号不带后缀，第二份为 `-1`，第三份为 `-2`，并发导出不重号，既有编号永不重排；
5. 以正式参考模板的可见版式和固定条款生成 `.xlsx`，支持一款多规格和多款多规格；
6. 加工单价单元格保持空白，系统不接收、不保存加工单价和合同金额；管理员下载后填写单价，金额公式自动计算；
7. 每次导出保留导出人、导出时间、模板版本、字段快照和独立私有文件，重复导出继续使用首次合同编号、签订日期和合同快照；
8. 文件二进制保存到私有对象存储，MySQL 只保存合同、快照和文件元数据；所有下载必须经过后端管理员权限校验；
9. 管理员小程序端和工厂小程序端不增加合同入口、导出或下载能力。

S06 完成后，管理员可以对一张符合条件的多工厂订单分别导出合同；首次、重复、同日同厂多份及缺资料场景均符合正式规则，并能在 Excel 和 WPS 中打开和填写单价后得到正确金额。

## 2. 业务范围与规则

### 2.1 合同边界与导出资格

- 合同唯一业务对象为“一个主订单＋一个工厂”，数据库对该组合建立唯一约束；
- 合同只包含该工厂在该订单中的派工数量，不包含同订单其他工厂的派工；
- 导出提交时必须重新锁定并校验订单、工厂、明细和已发数量，不能只相信页面打开时的状态；
- 主订单统一已发数量大于 0 时，首次导出和重复导出均返回稳定错误，不能生成文件；初始已发数量不得被“尚无系统发货记录”的判断绕过；
- 工厂被停用不影响既有订单合同导出，但合同必填资料必须完整；
- 派工数量必须大于 0，且订单至少存在一条属于所选工厂的有效派工明细；
- 是否允许 `DRAFT` 草稿订单导出，按第 2.7 节由用户确认后写死，不由实现自行推断。

### 2.2 工厂资料校验和模板映射

首次导出前必须校验：

| 系统字段 | 是否必填 | 合同用途 |
|---|---:|---|
| 工厂代码 | 是 | 合同编号中的工厂代码 |
| 单位全称 | 是 | 乙方单位全称 |
| 单位地址 | 是 | 乙方地址 |
| 法定代表人 | 是 | 乙方法定代表人 |
| 联系人 | 否 | 当前模板没有已批准的联系人位置，不写入“委托代理人” |
| 联系电话 | 否 | 使用排序第一的主联系人电话；没有时留空 |

- 委托代理人、开户银行和银行账号不录入、不读取、不保存，对应模板位置保持空白；
- 甲方单位全称、地址等固定资料沿用正式模板的甲方内容，不在 S06 增加公司资料配置；合同编号和签订日期由系统替换；
- 乙方页首和签章区的示例工厂资料必须全部替换为合同快照，不能残留参考模板示例值；
- 缺少任一必填资料时禁止首次导出，接口返回缺失字段代码，页面显示可理解的缺失项；
- 重复导出使用首次合同快照，不因之后修改工厂主数据而覆盖历史合同；Issue #16 确认现时工厂代码留空不阻止既有合同重新导出，但仍遵守订单资格和权限约束；
- 产品图片和货号属于可选资料，缺少时对应单元格留空，不阻止导出。

### 2.3 合同编号和签订日期

- 合同编号格式为 `YYYYMMDD-KK-工厂代码`；同一签订日期、同一工厂的后续合同依次增加 `-1`、`-2`、`-3`；
- 第一份的内部顺序号为 `0`，显示编号无后缀；第二份内部顺序号为 `1`，显示后缀 `-1`；
- 订单编号不参与合同编号；
- 首次导出签订日期默认使用 Asia/Shanghai 当天，管理员可在确认弹窗中修改；
- 合同编号以管理员确认的签订日期分配，而不是以服务器 UTC 日期或文件生成完成时间分配；
- 同一订单＋工厂的首次并发请求只能成功创建一份合同，重复请求返回同一合同；
- 同日同厂不同订单并发创建时必须通过数据库事务锁定计数器，保证编号唯一且顺序稳定；
- 后续补录、删除或修改其他订单不得重排既有合同编号；
- 重复导出继续使用首次签订日期和合同编号，页面不允许修改日期。

### 2.4 合同明细与快照

首次导出保存不可变合同快照，至少包含：

- 订单ID、订单编号、订单日期、合同出货时间；
- 工厂ID、工厂代码、单位全称、地址、法定代表人和可用的主联系电话；
- 所选工厂的产品、规格、分类、聚水潭货号 `i_id`、产品名称、图片引用和派工数量；
- 合同编号、签订日期、模板版本、首次创建人和时间。

明细按以下规则生成：

- 先按订单中产品的稳定顺序分组，再按规格稳定顺序输出；
- 同一产品的货号、产品名称和产品图片在该产品所占行内纵向合并；
- 每个颜色/规格单独占一行，数量为该规格分给所选工厂的派工数量；
- 合同出货时间为主订单唯一日期，可在全部明细行纵向合并；
- 备注默认留空，不新增系统备注来源；
- 产品图片按单元格范围等比例缩放并居中，不拉伸；图片不可用时留空；
- 模板“产品编号”列使用聚水潭货号 `i_id`；同一款的多个颜色/规格共用一个货号；货号缺失时单元格留空，不阻止导出。

合同快照不保存加工单价、行金额、合同总额或管理员在下载文件后的本地修改。

### 2.5 重复导出和历史稳定性

- 每次点击导出都新增一条导出记录和一个独立私有文件，不覆盖已有文件；
- 重复导出从首次不可变合同快照重新生成，不重新读取当前订单、产品和工厂主数据来解释历史合同；
- 重复导出沿用原合同编号、签订日期、明细、工厂资料和模板版本；
- 每次导出保存导出人、导出时间、请求幂等键、生成状态、文件引用和失败状态；
- 同一个幂等键重试返回首次成功结果，不新增第二条导出记录；不同幂等键代表管理员明确再次导出；
- 生成失败不得留下可下载的半文件；已分配的合同编号不因文件生成失败被其他合同复用。

### 2.6 文件名和安全处理

- 单款合同下载文件名：`合同编号 订单编号 产品名称.xlsx`；
- 多款合同下载文件名：`合同编号 订单编号 第一项产品名称等N款.xlsx`；
- 文件名中的合同编号必须与工作簿内合同编号完全一致；
- 对 `/\\:*?"<>|`、控制字符和首尾空白做安全替换，避免路径穿越和不同操作系统下载失败；
- 对象存储键使用随机不可猜测值，不直接把业务文件名当对象键；
- 文件 MIME 类型固定为正式 `.xlsx` 类型，不接受客户端指定对象键、路径或 MIME；
- 合同文件为私有文件，下载响应使用经过安全处理的业务文件名。

### 2.7 已确认决定

#### 决定 A：草稿订单能否导出（已确认）

原型按“存在派工且已发数量为 0”显示导出入口，正式需求没有明确限制订单必须已发布。草稿仍可编辑；若先导出再修改草稿，会形成一份与当前草稿不同但合法保留的历史合同。

用户于 2026-08-24 确认采用：

- **仅 `PUBLISHED` 已发布订单允许首次和重复导出；**
- `DRAFT` 提示“请先发布订单后再导出加工合同”；
- `COMPLETED` 理论上已有发货，不符合统一已发数量为0；仍以统一已发数量硬校验为准。

理由：加工合同是对外执行文件，应以发布后的稳定派工为基线；这样无需增加“合同生成后锁草稿”或“合同版本作废”机制。

#### 决定 B：模板“产品编号”列取值（已确认）

用户于 2026-08-24 确认：

- **“产品编号”列使用聚水潭货号 `i_id`；**
- 同一款的多个颜色/规格共用一个货号，货号、产品名称和产品图片按产品分组纵向合并；
- 产品规格编码 `sku_id` 不另加到合同模板，仍由颜色/规格逐行区分；
- 货号属于可选产品资料，缺失时对应单元格留空，不影响导出。

该决定符合现有模板按“一款产品＋多行颜色/规格”组织明细的结构，也不改变模板列数。

上述两项决定已纳入本工单正式实施边界。

## 6. 模板生成规则

### 6.1 运行模板副本

- 正式参考文件继续保留在 `docs/reference/`，运行代码不得依赖 `docs/`；
- 实施时在后端运行目录增加版本化模板 `processing_contract_v1.xlsx`；
- 运行模板保留已提交合同案例 `合同` 工作表 A1:I51 的可见版式、字号、白底、边框、行高、列宽、打印设置、供需方区域和固定合同条款；
- 删除空白工作表、打印区域外无业务作用的残留对象、OLE 嵌入和超范围样式，不把隐藏对象复制进用户下载文件；
- 不修改原始参考模板，不静默修改固定条款文案；
- 模板版本写入合同和每次导出记录，后续模板升级另开明确变更，不反向改写历史合同。

### 6.2 明细行扩展

- 参考模板明细区为第 8 至 19 行，共 12 行；
- 明细不超过 12 行时复用现有区域，并清空未使用行的业务值和公式；
- 明细超过 12 行时在合计行之前插入足够行，复制对应样式、边框、行高和公式规则，并同步下移合计、条款和签章区域；
- 插行后更新合并区域、打印区域、分页和全部公式引用；
- 一款多规格时按产品分组合并货号、名称和图片；多款时每款分别建立合并组；
- 自动化必须验证 1 行、12 行和超过 12 行三个边界。

### 6.3 单价和金额公式

- 每个已使用明细行的加工单价列保持真正空白，不写 `0`、空字符串公式或隐藏默认值；
- 每个已使用明细行的总金额公式遵循：数量或单价为空时显示空白，两者为数值时计算 `数量 × 单价`；
- 合同总额只在全部已使用明细行的单价均为数值时显示合计，否则保持空白；
- 未使用明细行不保留会产生 `0` 的金额公式；
- 数量写入整数数值单元格，不写文本；金额保留模板货币格式；
- 公式由 Excel/WPS 打开并重算，后端不计算、不保存价格或金额；
- 自动化检查公式结构和引用，人工验收在 Excel/WPS 中填写单价后检查实际重算结果。

### 6.4 图片和 OOXML 安全

- 图片从私有产品图片存储读取，限定格式、大小、像素和解码资源，拒绝畸形图片；
- 插图以“contain”方式适配目标合并单元格，保持比例并居中；
- 缺图、对象不存在或可选图片读取失败时留空并继续生成，不能暴露内部对象键；
- 生成文件不包含宏、外部链接、OLE 对象、外部数据连接或参考模板的无关嵌入；
- 生成后重新打开工作簿并检查 ZIP/OOXML 结构、关系、图片引用、工作表、打印区域和公式，发现损坏时不得发布为可下载文件。

### 7.1 `processing_contracts`

至少保存：

- `signing_date`、`daily_sequence`、`contract_no`；

唯一约束：

- `contract_no` 唯一；
- `signing_date + factory_id + daily_sequence` 唯一。

合同快照只保存生成合同所需的业务值和稳定标识，不保存单价、金额、访问凭据或对象存储签名 URL。

### 7.2 `contract_number_counters`

- 分配后递增，事务失败由 MySQL 一起回滚；
- 已成功创建的合同即使后续文件生成失败，其编号仍属于该合同，不被另一合同复用；

同一管理员会话范围内的幂等键唯一；只有 `READY` 导出允许下载。失败记录用于审计和恢复，不提供页面历史列表。

## 8. 模块、对象存储与一致性设计

### 8.1 `contracts` 领域模块

模块对外只提供：

- 查询订单内各工厂合同状态和导出资格；
- 首次或重复创建合同导出；
- 根据导出记录授权下载文件。

编号分配、资格复核、快照构建、模板映射、幂等、生成状态和文件授权隐藏在模块内部，页面不得自己拼合同编号或判断最终资格。

### 8.2 通用私有文件 seam

- 新增面向私有业务文件的 `PrivateFileStore` seam，不复用头像专用接口承载合同；
- 正式 adapter 使用配置的私有 MinIO/S3 兼容桶；
- 本地和自动化 adapter 使用隔离临时目录或内存实现；
- 未配置正式对象存储时明确失败，不能静默写入仓库或公开目录；
- bucket、endpoint、access key 和 secret 只来自服务器环境变量；真实值不写入 Git、前端、文档或日志。

### 8.3 MySQL 与对象存储的一致性

MySQL 事务和对象存储上传不能组成单一数据库事务，按以下补偿流程处理：

1. 在短事务中锁定订单、资格、合同唯一键和编号计数器，创建或取得稳定合同及快照，并创建 `PENDING` 导出记录；
2. 事务提交后在内存中生成并校验工作簿；
3. 上传到随机临时对象键，校验字节数和 SHA-256；
4. 在新事务中创建 `stored_files` 并把导出原子更新为 `READY`；
5. 任一步失败把导出标记为 `FAILED`，尽力删除已上传但未引用的对象；
6. 同一幂等键重试复用既有结果；后台恢复可安全重做 `PENDING`，但不能重新分配合同编号；
7. 下载只接受 `READY` 且文件校验信息完整的记录。

## 9. 后端接口与权限

所有接口位于 `/api/v1`，只允许已启用管理员网页会话调用；管理员小程序、工厂会话和匿名请求返回 403/401。

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/admin/orders/{orderId}/contracts` | 查询订单内各工厂的合同状态、资格和缺失资料 |
| `POST` | `/admin/orders/{orderId}/contracts/{factoryId}/exports` | 首次或重复创建一份合同导出 |
| `GET` | `/admin/contract-exports/{exportId}/download` | 权限校验后下载已完成的私有 `.xlsx` |

`POST` 要求 `Idempotency-Key`。首次请求体只接受 `signingDate`；重复导出不接受修改合同编号、签订日期、快照、模板版本、文件名或对象键。

成功响应返回 `exportId`、`contractId`、合同编号、签订日期、安全文件名、状态和受控下载路径，不返回对象存储凭据或永久公开 URL。

典型错误：

- `400/422`：签订日期格式、参数或数据类型不合法；
- `401/403`：未登录、角色或终端不允许；
- `404`：订单、工厂、派工、导出或文件不存在；
- `409`：订单状态、已发数量、并发版本或幂等请求冲突；
- `422`：工厂合同资料缺失，返回字段级问题；
- `503`：私有文件存储未配置或暂不可用；
- `500`：模板生成或结构校验失败，响应不包含路径、对象键或内部堆栈。
