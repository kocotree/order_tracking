## 1. 工单目标

本工单交付“质检单创建返修任务”的独立闭环：

1. 管理员网页端上传真实但非生产的 `.xlsx`，生成临时预览，不直接创建正式返修单；
2. 按原始行和箱号解析工厂、产品规格、仓库退回数量和次品原因，严格匹配现有工厂与聚水潭产品快照；Excel 内照片不解析为系统业务数据；
3. 管理员核对并确认后，一次事务生成唯一返修单、质检明细和原始 Excel 附件关系；
4. 管理员网页端、管理员小程序和所属工厂小程序查询同一份真实返修任务；
5. 所属工厂可查看或下载原始质检附件，其他工厂不可访问返修单或附件。

S09 完成时，新返修单只能是“未完成”，返修数量、报废数量和返回总数量均为 `0`。S10 才开放工厂分批发回、自动完成和归档。

## 2. 业务范围与规则

### 2.1 质检 Excel 预览

- 只接受 `.xlsx`；拒绝 `.xls`、`.xlsm`、CSV、伪装扩展名和无效 ZIP/OOXML；
- 后端验证扩展名、MIME、大小、解压总量、条目数和工作表数；具体上限根据真实样例确认；
- 不计算公式，不执行宏，不请求外部链接，不信任工作簿内的路径或 URL；
- 保存原始文件并计算 SHA-256，建立有过期时间的临时预览；确认前不写入正式返修数据或通知；
- 一个文件必须严格匹配且只属于一个已启用工厂；多工厂、工厂不存在或工厂已停用均阻止确认；
- 产品和规格只匹配 S03 已落库且当前可用的快照；不模糊匹配、不自动建产品、不使用已停用规格；
- 仓库退回数量必须是正整数，箱号必须可读取；次品原因可为空；
- 明细按原始行保存，即使产品规格相同也不丢失箱号或原因对应关系；查询层可另行汇总同规格数量；
- 错误按文件级或“Sheet＋行＋字段”返回；存在任一阻断错误时不可确认，不创建部分返修数据；
- J:M 等照片区域不进入解析结果、不产生警告，也不阻止确认；照片只随原始 Excel 附件保留。

### 2.2 确认创建

- 确认时重新校验预览未过期、摘要未变、工厂仍启用、规格仍可用且预览未被确认；
- 确认携带 `Idempotency-Key`；重复请求返回首次结果，并发确认只生成一张返修单；
- 返修单号按已批准原型使用 `FXYYYYMMDD-NNN`，日期为 Asia/Shanghai 确认日，当日全系统序号从 `001` 开始，通过唯一约束与锁内取号保证并发唯一；
- 一次事务写入返修单、质检明细、原始 Excel 正式关系、操作日志和可去重的新任务通知事件；
- 返修单不保存原订单或正常发货单外键，不写正常订单数量台账，不改变任何订单数量或状态；
- 创建后状态为 `INCOMPLETE`，仓库退回总数量由质检明细求和，返修、报废和返回总数量均为 `0`；
- 原始 Excel 和已创建返修明细不提供编辑、替换或删除入口。

### 2.3 查询与附件权限

- 管理员可查看全部未归档返修单；管理员网页详情展示原始附件，不单独展示次品照片；
- 管理员小程序只读查看列表和详情，不展示质检附件；
- 工厂小程序只查询本厂任务，详情可查看或下载原始质检 Excel；
- 文件每次下载先经后端校验，再返回短时签名地址或流式响应；列表 API 不返回永久对象地址；
- 工厂 A 访问工厂 B 的返修单或附件统一返回 `404`；管理员小程序访问网页专用上传接口返回 `403`；
- 已停用工厂用户不能继续读取附件；业务与文件仍保留。

- 不实现微信订阅消息真实发送、通知偏好、重试或告警收口；S09 只写可去重业务事件；

## 6. 已确认的正式决策

### 6.1 质检 Excel 文件契约

**已确认（2026-08-26）：** 已读取并可视核对 `E22质检.xlsx` 和 `E28质检.xlsx`。两份文件共同确定以下文件契约：

- 只解析 `Sheet1`；`Sheet2`、`Sheet3` 在两份样例中均为空白，可忽略。如其他 Sheet 出现业务数据，本次预览整体报错，不静默丢弃；
- 第 1 行是表头，第 2 行开始是明细。基础八列必须依次为：`A 编号`、`B 厂家名称`、`C 商品编码`、`D 款式编码`、`E 商品名称`、`F 颜色/规格`、`G 数量`、`H 箱数`；
- 支持两种已见版式：A:H 无原因版；A:M 完整版，其后依次为 `I 次品原因`、`J:M 次品照片1～4`。解析器只读取 A:I，J:M 完整保留在原始附件中但不解析；不猜测其他列序或列名；新版式需另行确认；
- A 列对应工厂“供应商编号”，B 列对应“工厂名称”；同一文件所有明细的 A/B 必须各自唯一，且两者必须同时严格匹配同一家已启用工厂；
- C 列严格匹配 `ProductVariant.source_sku_id`，D 列严格匹配 `Product.source_i_id`，E 列严格匹配 `Product.name`，F 列严格匹配 `ProductVariant.properties_value`；四项必须同时指向同一个当前可用规格；
- G 列为正整数仓库退回数量；A:G 每个数据行均必须有值，不对空单元格做任意向下填充；
- H 列使用合并单元格表示箱号范围；解析时把合并区域左上角的箱号明确展开到区域内每一条原始明细，不对非合并空白格猜测箱号；
- I 列可使用与 H 列不同的合并范围。解析时按 I 列自身合并范围展开次品原因，不假设原因合并范围必须与箱号范围相同；
- J:M 的 WPS 单元格图片公式及 `xl/media/` 内容不解析、不校验为业务字段；工作簿外部关系仍一律阻止预览；
- 数据行必须连续；首个 A:G 全空行之后又出现业务数据时整体报错，避免静默漏行；
- 本地默认安全上限为：原文件 20 MiB、解压总量 100 MiB、ZIP 条目 20,000、工作表 10、数据行 5,000；服务器可通过非敏感环境配置调低，调高前必须重做资源测试；
- `E22质检.xlsx` 的固定结构化契约结果为 33 条明细、3 个箱号、仓库退回总数量 826；`E28质检.xlsx` 为 10 条明细、1 个箱号、总数量 126、无次品原因。两份文件作为解析器回归测试基线，照片只用于人工核对原附件完整性，不属于解析输出。

两份样例已补齐文件契约依据，并作为解析器实施与回归基线。

### 6.2 相同文件重复创建

**已确认（2026-08-26）：** 同一预览只能确认一次；完全相同 SHA-256 的原始 Excel 已生成返修单时，新预览显示已有返修单号并阻止再次确认，避免重复派发。如业务需要重用相同文件，另行定义有理由、有权限和有审计的例外流程。

### 6.3 临时预览有效期

**已确认（2026-08-26）：** 预览从上传成功起有效 24 小时。过期后后端拒绝重读和确认创建，前端统一提示“预览已失效，请重新上传质检 Excel”并回到初始上传状态，不开发独立过期页面。清理服务只删除过期且未被正式返修单引用的预览数据和临时文件；不新增调度器 UI。

### 6.4 质检照片处理

**更新确认（2026-08-26）：** 原始 Excel 已包含质检照片，系统不再解析、单独展示、保存或补传照片，也不建立照片与明细的独立关系。管理员及所属工厂通过受权下载的原始 Excel 查看照片；本确认替代此前的补传图片归属方案。

## 7. 数据库与领域模型

迁移与集成测试使用真实 MySQL 8、InnoDB、`utf8mb4` 和微秒时间戳。时间戳保存 UTC，返修编号与退回日期使用 Asia/Shanghai。

- `repair_previews`：上传人、状态、原始文件、摘要、匹配工厂、错误/警告、过期时间、确认时间和已生成返修单；
- `repair_preview_lines`：Sheet、原始行号/顺序、箱号、原始字段摘要、匹配规格、仓库退回数量、原因和校验结果；
- `repair_orders`：唯一返修单号、工厂、`INCOMPLETE/COMPLETED`、创建人、退回日期、原始文件、文件摘要、归档预留字段和时间戳；
- `repair_inspection_lines`：原始 Sheet/行号/顺序、箱号、产品规格快照与外键、仓库退回正整数和次品原因；
- 原始 Excel 通过 `repair_previews.original_file_id` 和 `repair_orders.original_file_id` 直接关联 `stored_files`；不建立额外照片或明细附件关系表；
- 返修单号需要并发安全日序列；不使用“先查数量再拼接”。

S09 可预建 S10 所需状态和归档字段，但不写发回批次/明细，不开放 S10 写接口。

## 8. API 与权限边界

| 终端 | 接口 | 作用 |
|---|---|---|
| 管理员网页 | `POST /admin/repair-previews` | 上传 `.xlsx` 并生成预览 |
| 管理员网页 | `GET /admin/repair-previews/{previewId}` | 重读预览、错误、警告和明细 |
| 管理员网页 | `POST /admin/repair-previews/{previewId}/confirm` | 幂等确认创建返修单 |
| 管理员双端 | `GET /admin/repairs`、`/{repairId}` | 查询列表/详情，按终端裁剪 |
| 工厂小程序 | `GET /factory/repairs`、`/{repairId}` | 只读本厂任务/详情 |
| 管理员网页/所属工厂 | `GET /files/{fileId}/download` | 逐次授权查看或下载 |

- 上传与确认校验网页终端和 CSRF，确认使用 `Idempotency-Key`；
- 错误语义：`401` 未登录，`403` 错误终端/无操作权限，`404` 工厂不可见/对象不存在，`409` 预览、幂等或重复文件冲突，`422` 文件/字段校验失败，`503` 对象存储不可用；
- 生成 OpenAPI 后同步管理员网页和小程序 TypeScript 类型并检查漂移。
