# 小程序原型复刻规范

> 状态：正式执行规范
>
> 适用范围：`miniprogram/` 中管理员小程序与工厂小程序的页面设计、实现和视觉调整
>
> 确认日期：2026年8月24日

## 1. 目标

已批准的小程序原型是正式页面的视觉和交互基准。除本规范明确允许的例外外，正式页面必须严格复刻原型，不得仅参考大致风格后自行重新设计。

严格复刻包括但不限于：

- 页面外壳、内容宽度、留白、间距和对齐；
- 信息层级、卡片结构、字段、字段顺序和数量口径；
- 标题、标签、按钮、提示、空状态和其他可见文案；
- 字号、字重、颜色、圆角、边框、阴影、分割线和状态样式；
- 搜索、筛选、页签、列表、详情、折叠、弹窗和底部导航；
- 默认状态、选中状态、禁用状态、展开状态和页面跳转关系；
- 原型已经明确的图标含义、位置、尺寸、颜色和图文排版。

## 2. 执行优先级

出现差异时按以下顺序判断：

1. 已确认的一期需求、当前工单和用户当前页面确认决定业务范围，不得为复刻原型提前实现后续工单功能；
2. 微信小程序平台能力、系统安全区、原生导航和微信用户习惯决定平台适配；
3. 在不违反前两项的范围内，其余可见内容和交互严格按已批准原型复刻。

不得使用假业务记录填充尚未实现的能力，也不得把原型中的历史文案、失效状态或超出当前工单的入口直接带入正式页面。

## 3. 允许简化的复杂图标和图形

原型中的复杂图标、插画或图形在微信开发者工具、WXML、WXSS 或目标基础库中无法稳定实现时，可以简化，但必须满足：

- 保留原图标的业务含义，用户无需猜测其用途；
- 保留大致轮廓、位置、尺寸、颜色、视觉重量和选中/未选中关系；
- 优先复用项目已有图标或使用简单、稳定的 SVG、图片资源和 WXSS 图形；
- 同一功能在不同页面使用一致图标，不混用多个含义相近但外形差异明显的图标；
- 简化只针对实现复杂度，不得顺带改变文字、按钮位置、导航项或业务操作。

如果简化后仍容易引起误解，应先向用户展示方案并取得确认。

## 4. 微信使用习惯优先的情况

原型与微信小程序平台或常见使用习惯冲突时，可以采用更适合微信的实现，包括：

- 只保留微信原生右上角胶囊，不重复绘制第二个胶囊；
- 正确适配状态栏、胶囊、安全区和底部手势区域；
- 返回操作遵循小程序页面栈，标题保持稳定居中；
- 日期、选择项、开关和确认操作优先使用稳定且符合微信习惯的控件或交互；
- 点击区域满足移动端使用需要，避免只有细小图标可以点击；
- 页面滚动、底部导航和弹层不得被系统安全区遮挡。

平台适配只能改善可用性，不能擅自删除正式字段、增加操作或改变业务结果。

## 5. 原型设计不合理时的处理

以下情况不要求机械照搬：

- 与已确认需求、正式字段名称、状态口径或当前工单冲突；
- 展示系统当前没有的真实数据，或要求提前开放后续工单功能；
- 在微信开发者工具或真机中出现遮挡、溢出、无法点击、无法返回等问题；
- 明显违背微信使用习惯、移动端可读性或基本可访问性；
- 同一原型内部存在相互矛盾的字段、文案、图标或交互。

处理方式：

- 单纯平台适配或复杂图标简化，可以按本规范直接处理，并在交付说明中列出差异；
- 涉及字段、文案、状态、按钮、页面跳转或业务规则变化时，必须在修改前说明冲突并取得用户确认；
- 不得以“原型不合理”为由进行个人审美重设计、增加装饰、改版布局或扩大功能范围。

## 6. 页面实施流程

每个页面都按以下顺序执行：

1. 打开该页面对应的原型，完整读取相关脚本、样式、图标和公共组件；
2. 核对正式需求、当前工单、现有接口字段和真实数据能力；
3. 列出本次页面的展示内容、字段、操作和跳转，取得用户确认；
4. 复用已确认的公共组件、设计变量和图标资源，实施最小范围改动；
5. 逐项检查布局、文案、状态、交互和不同数据状态，不用假数据掩盖缺失能力；
6. 在微信开发者工具中打开实际页面，与原型并排检查；必要时再做真机检查；
7. 在工单或交付说明中记录所有有意差异及原因。

一个页面确认完成后，进入下一页面仍需重新执行第 3 步，不能自动扩大上一页面的确认范围。

## 7. 完成标准

同时满足以下条件才可称为完成：

- 除已记录例外外，页面的内容、结构、视觉和交互与原型一致；
- 页面只展示当前工单允许的真实能力，不存在假记录和提前开放入口；
- 复杂图标的简化版本语义明确、排版一致；
- 微信状态栏、胶囊、安全区、滚动、返回和底部导航正常；
- 构建、代码检查和相关测试通过；
- 微信开发者工具中的实际页面已经完成视觉检查，且有意差异已说明。
