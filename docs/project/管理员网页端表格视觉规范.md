# 管理员网页端表格视觉规范

> 状态：2026-08-22 用户确认
> 适用范围：`admin-web/` 中已有和后续新增的后台列表页、数据表格、表格标题行、状态标签、排序与分页。
> 原型基线：`prototype/admin-web-lowfi/` 中对应页面、公共组件和最终加载的样式。
> 正式实现基线：`admin-web/src/`。

## 1. 新会话或新 Agent 的必读顺序

修改管理员网页端列表或表格前，必须依次完整读取：

1. `docs/project/一期里程碑与决策记录.md`，确认当前阶段；
2. 当前阶段的已批准工单；
3. 本规范；
4. 对应原型页面脚本、公共组件及全部相关样式；
5. 正式页面组件和公共样式。

不得只看截图、只看某一条 CSS、只凭上一个会话总结或凭其他页面经验直接修改。

## 2. 资料职责和冲突处理

1. 需求文档和当前工单决定正式字段、业务文案、数据、权限、状态和操作范围。
2. 已确认原型决定页面外壳、信息层级、控件顺序、布局、表格视觉和交互方式。
3. 本规范记录已经确认的可重复尺寸和页面级精确参数。
4. 正式工程现有样式只是待核对实现，不得反过来覆盖原型或本规范。
5. “与原型对齐”不等于复制原型演示数据。不得复制“低保真原型”标识、原型专用说明、假订单数量或假账号；正式页面继续显示真实接口数据和正式业务文案。
6. 需求、工单、原型和本规范发生冲突时，不得静默选择，也不得先改再说明；停止可见改动，列出冲突并取得用户确认，确认后同步更新本规范和对应工单。

## 3. 实施方式

1. 优先复用公共表格类、排序按钮、标签、分页和设计变量，不得为单页另写一套近似样式。
2. 不得用其他页面的行高、字号或列宽推算当前页。不同业务表可以有不同密度，必须使用下方页面级参数或对应原型的最终计算样式。
3. 同一元素命中多份 CSS 时，以浏览器最终计算样式为准。后加载规则、选择器优先级和表格自适应都必须纳入判断。
4. 表格列宽要求指浏览器中的实际渲染宽度。只写 `width`、但最终发生换行或宽度偏差，仍视为未完成。
5. 横向空间不足时保留页面既定 `min-width`，由表格外层横向滚动，不得压缩到表头换行、操作重叠或列宽失真。
6. 只处理用户当前确认的页面和项目，不借视觉对齐增加按钮、页签、字段、状态或业务行为。

## 4. 所有后台数据表的公共规则

| 项目 | 固定要求 |
|---|---|
| 页面内容卡片间距 | `14px` |
| 表格卡片标题行 | 高度 `54px`；内边距 `0 16px`；内容垂直居中；底部 `1px` 分隔线 |
| 标题文字 | `18px`；字重 `800`；单行显示 |
| 表头行 | 高度 `40px`；字号 `13px`；字重 `800`；文字色 `#37404b`；背景色 `#f1f3f6` |
| 单元格边框 | `1px solid #dde1e7`；使用 `border-collapse: collapse` |
| 普通单元格 | 默认左右内边距各 `14px`；垂直居中；超长文本单行省略，不得随意换行撑高 |
| 序号列 | 实际宽度 `52px`；左右内边距各 `8px`；水平居中；单行；字重 `600`；不得排序 |
| 排序列 | 仅已确认业务列显示公共双箭头；再次点击在升序和降序间切换 |
| 非排序列 | 序号、图片、选择框、操作等辅助列默认不排序，除非用户另行确认 |
| 操作区 | 操作项保持单行，已确认双操作页面的间距为 `12px`，不得粘连 |

## 5. 订单列表的精确基线

对应正式路由：`/orders`。对应原型路由：`#/orders`。

### 5.1 页面与数据行

- 顶部标题显示“订单列表”，不得显示模块名“订单与发货”。
- 表格类为 `.order-list-table`，`min-width: 1132px`，`table-layout: fixed`。
- 表头高度 `40px`；数据行高度 `40px`，不得再设为 `56px`。
- 普通单元格为 `13px / 700`，上下内边距为 `0`，左右各 `14px`。
- 序号单元格为 `13px / 600`，左右各 `8px`，居中。

### 5.2 十一列宽度

按“序号、订单编号、产品名称、分类、跟单人员、工厂、合同出货时间、发货进度、已发/订单数、状态、操作”的顺序：

`52 / 82 / 164 / 68 / 84 / 110 / 142 / 160 / 110 / 96 / 104px`

在表格可用空间大于最小宽度时，固定布局可以按同一比例扩展；不得单独放大订单编号、分类或跟单人员列，导致比例偏离原型。

### 5.3 标签与操作

- 分类和跟单人员使用原型中的圆角标签；跟单人员颜色按姓名沿用原型映射。
- 状态使用 `.status-badge`；高度 `22px`、最小宽度 `44px`、内边距 `0 10px`、字号 `13px`、字重 `700`，订单列表状态标签不显示前置圆点。
- 状态色：草稿为紫色 `#65547b / #f0ebf7`；已逾期使用危险色；未完成使用信息色；已完成使用成功色。
- “详情、删除”保持同一行，间距 `12px`。是否显示删除由正式业务规则决定，不照搬原型演示行。
- 页脚继续显示正式接口总数和真实分页；不得复制原型的“原型数据仅用于验证……”提示。

## 6. 待导入订单列表的精确基线

对应正式路由：`/orders/import`。对应原型路由：`#/pending-imports`。

- 表格类为 `.import-candidate-table.pending-import-table`，`min-width: 1040px`，固定布局。
- 表头和数据行均为 `40px`；表格字号 `13px`；普通单元格字重 `700`。
- 九列按“选择、序号、订单编号、产品名称、分类、跟单人员、工厂、校验状态、操作”的顺序：

`44 / 52 / 100 / 228 / 82 / 112 / 142 / 144 / 100px`

- 选择列和序号列左右内边距各 `8px`、居中；两列与操作列不排序。
- “获取飞书新订单”和“批量导入为草稿”之间保持 `12px`，不得粘连。
- 校验状态标签高度 `22px`、字号 `13px`、字重 `700`，不显示前置圆点。
- “详情、删除”保持单行且有明确间距；不得依赖空格字符撑开。
- 每页显示 `10` 条；页脚显示真实总数和正式分页。

## 7. 订单详情的精确基线

对应正式路由：`/orders/:orderId`。对应原型路由：`#/orders/:orderNo`。

- 顶部标题为“订单详情 · 订单编号”；主体卡片间距 `14px`。
- 概览卡片顶部操作行最小高度 `54px`、内边距 `9px 18px`；返回按钮、状态标签和操作按钮的顺序、尺寸、圆角均以原型为准。
- 概览信息使用三列两行布局，只显示“分类、跟单人员、合同出货时间、订单数量、已发数量、未发数量”；每格最小高度 `58px`，字段名单元格最小宽度 `118px`。
- 订单明细表为十列：序号、图片、产品编码、产品名称、颜色/规格、工厂、下单数量、已发数量、未发数量、发货进度。最小宽度 `1080px`，表头高度 `40px`，数据行高度 `48px`，字号 `14px`。
- 十列宽度依次为：`56 / 72 / 110 / 210 / 135 / 86 / 96 / 96 / 96 / 160px`。序号、图片不排序，其余八列使用公共双箭头排序。
- 关联发货单保留原型表头和表内空状态；S07 前不得制作可进入的发货单详情。
- 订单详情页不显示独立的“工厂派工与进度”卡片；工厂、数量和进度由订单明细表承载。详情底部新增只读“操作日志”，仅显示时间、操作人、操作内容，不提供编辑、删除、筛选、分页或独立日志页面。
- 当前正式业务与原型只保留阶段门禁差异：草稿继续显示“编辑草稿、删除订单”；S06 前不得开放原型中的“导出加工合同”。
