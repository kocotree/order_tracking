# 跟单管理系统一期需求文档 V1.46

> **文档范围：**一期需求为订单、派工、合同出货时间、发货记录、订单完成、次品退回返修、工厂合同资料和加工合同Excel导出。
>
> **文档状态：**需求定版稿（V1.46 已确认 S08 发货清单、撤回作废、按发货单退回及互斥规则）
>
> **确认日期：**2026年8月25日
>
> **范围说明：**“合同出货时间”是一期间隔、排序、逾期判断和加工合同明细字段；加工单价仅保留为导出Excel中的空白填写列，不属于系统业务数据。

## 1. 项目目标

建设一个由飞书企业自建管理员网页应用、管理员小程序端、工厂小程序端和公司服务器后端组成的跟单系统，用于管理订单导入与派工、工厂装箱发货、发货记录、次品退回返修以及订单最终完成。

系统解决的核心问题是：内部管理员和多个工厂使用同一套订单数据，按产品规格、工厂和合同出货时间追踪实际发货，并追踪仓库退回工厂的次品是否全部发回，减少手写发货清单、返修单据分散、重复录入和数据对不上的情况。管理员在电脑网页端完成完整管理工作，并通过小程序移动查看订单、发货记录和返修进度；工厂通过小程序完成本厂任务、装箱、正常发货和返修发回操作。

### 1.1 一期原则

- 公司阿里云ECS上的MySQL 8.0数据库是唯一正式跟单业务数据源；一期Excel用于发货清单和加工合同导出。
- 飞书多维表格是新增订单的上游录入来源，不保存发货记录和订单完成等正式跟单结果。
- 飞书管理员网页应用、管理员小程序端和工厂小程序端共用部署在公司服务器上的后端API、MySQL正式数据和权限规则，任何前端都不得直接连接数据库。
- 管理员网页端提供完整管理能力；管理员小程序端只提供适合移动查看和现场处理的功能，不要求两个终端完全复制。
- 订单编号、产品名称和组合字段“颜色/规格”采用严格规则，避免模糊匹配。
- 工厂端只填写实际发生的数据，不重复填写管理员已经分配的计划。
- 正式业务记录保留操作日志，不允许无痕删除或修改。
- 一期新建独立代码项目；现有CloudBase小程序代码仅保留为历史参考，不继续作为正式开发基础。
- 一期管理订单、进度、正常发货记录、次品退回返修、工厂合同资料和加工合同Excel导出；正常发货不设置待收货、已收货、实际收到数量或到货日期，系统不保存加工单价和合同金额。
- 质检单返修不关联原订单或正常发货单，不改变正常订单进度；按发货单退回必须扣减来源订单的已发数量，并通过正常订单任务重新补发。

## 2. 用户角色与权限

| 角色 | 人员范围 | 一期权限 |
| --- | --- | --- |
| 管理员（内部人员） | 公司内部管理人员，可配置多人；申请时不填写职位 | 管理用户和工厂及工厂合同资料；创建和导入订单；指定跟单人员；分配工厂、合同出货时间和数量；查看全部工厂进度和正常发货记录；创建和查看返修单；下载发货清单；导出加工合同Excel；确认订单完成；删除尚未产生有效发货记录的订单。普通管理员默认查看全部业务数据，不按申请人职位或订单跟单人员限制数据范围。系统不提供正常收货确认、加工单价录入或保存。 |
| 工厂用户 | 职位只使用“老板”或“工厂员工”，可一厂多人 | 只查看本工厂被分配的正常任务和质检单返修任务；创建正常发货单和质检单返修发回记录；填写正常装箱数据、返修数量和报废数量；从“发货记录”查看本厂正常发货记录，并从返修任务详情查看质检单返修发回结果。 |

- 一期只有“管理员（内部人员）”和“工厂用户”两种系统角色，管理员与内部人员是同一种身份。“最高管理员”是管理员角色内的系统权限标记，不是第三种业务角色。
- 工厂用户职位只允许“老板”和“工厂员工”，职位只作为人员标签，不区分权限。
- 管理员申请不填写职位，普通管理员默认查看全部业务数据，不按职位或订单跟单人员限制数据范围；订单业务字段“跟单人员”继续使用烧麦、松子、橄榄、大葱、青椒。
- 一个工厂用户只能归属一个工厂。
- 同一订单分给多个工厂时，工厂看不到其他工厂名称、下单数量和进度；管理员可以查看全部。
- 同一管理员账号在网页端和小程序端使用同一角色、数据范围和操作记录；终端差异只影响功能入口，不改变业务权限。
- 管理员网页端一期先作为独立HTTPS网站运行，入口显示“通过飞书登录”；用户完成飞书授权后，由服务器获取飞书用户身份、飞书企业通讯录中已验证的手机号并建立系统会话。飞书应用必须获得读取当前用户手机号的必要权限；未返回手机号、权限被拒绝或手机号格式无效时登录失败并提示联系管理员处理，不创建缺少手机号的管理员申请账号。后续嵌入飞书工作台时可改为飞书客户端免登，但继续复用同一内部用户、权限和会话校验规则。
- 内部人员首次通过飞书登录但尚未取得角色时，只能在管理员网页端提交管理员身份申请，不能查看业务数据。申请页面展示飞书身份中的姓名和脱敏手机号，申请人不填写手机号、不输入短信验证码、不填写职位；服务器使用飞书返回的已验证手机号提交申请。
- 管理员身份申请只在网页端提交；管理员小程序不提供申请入口。管理员首次进入小程序时先取得微信身份，尚未绑定时由用户授权手机号，服务器使用该手机号匹配飞书登录已保存的管理员申请并将微信身份绑定到同一内部userId。未匹配到申请时提示先前往管理员网页端申请，不得自动创建重复管理员账号。
- 网页端申请手机号与小程序授权手机号必须一致且唯一匹配；匹配到已通过申请时进入系统，匹配到审核中或已拒绝申请时显示对应状态，无法唯一匹配时禁止自动绑定并提示联系最高管理员处理。绑定成功后不重复要求手机号授权。
- 管理员小程序默认展示微信头像，允许用户在小程序内更换头像；小程序头像只用于小程序端展示，不覆盖管理员网页端使用的飞书头像，也不作为身份审核资料。管理员可以退出小程序登录，退出只清除当前会话，不解除微信身份、手机号与内部userId的既有绑定；重新登录时通过微信身份恢复同一内部账号，不重复授权手机号。
- 网页端首次完成飞书登录、小程序首次完成微信登录及必要的手机号绑定后，客户端使用短期访问凭证和最长30天未活动失效的滚动续期凭证自动恢复会话。刷新页面、关闭后重新打开网页或小程序，以及使用固定服务端密钥的正常服务重启，不要求用户重新登录。主动退出、账号停用或权限撤销、用户清除浏览器或微信本地数据、续期凭证异常或超过30天未使用时必须重新登录；系统不签发永久且不可撤销的登录凭证。
- 只有最高管理员可以查看、通过或拒绝管理员申请，通过后授予普通“管理员”角色，普通管理员不能查看管理员申请或调用对应审核接口。
- 最高管理员不能通过普通管理员申请获得，只能在生产环境初始化或受控系统配置中授予；生产环境允许配置多名最高管理员，避免唯一账号不可用时无法继续授权。
- 普通管理员可以审核工厂用户申请、绑定工厂，并在用户列表中启用或停用工厂用户；最高管理员同时具有这些权限，并可以启用或停用普通管理员。最高管理员账号不能在人员管理页面停用。用户记录保存在MySQL中，人员管理页面是受权限控制的管理入口，不能以直接修改数据库代替日常人员管理。
- 管理员先建立系统工厂资料；工厂用户首次打开小程序提交真实姓名、经本人授权验证的联系电话、职位，并选择一个已有工厂申请，不能自由输入或创建工厂。系统不采集身份证，不进行国家级实名认证。
- 管理员网页端的工厂用户申请列表操作统一为“详情”。详情使用弹窗展示申请人姓名、验证联系电话、职位、申请工厂、工厂资料联系人及联系电话、申请时间、申请状态和审核记录；待审核申请在弹窗内通过或拒绝，通过时再次确认绑定工厂，拒绝时必须填写原因。
- 工厂用户和内部管理员申请人在审核通过前均不能查看业务数据；未获授权的网页访问者同样不能查看业务数据。
- 管理员确认导入订单前，订单涉及的每个工厂都必须已建立系统工厂资料，并且至少有一名审核通过且启用的工厂用户。

| 管理员小程序端 | 移动查看：订单查询与详情、工厂发货进度、正常发货明细和质检单返修进度与详情，以及接收提醒；不提供订单状态变更操作。 |

## 3. 核心业务对象

### 3.1 产品资料

- 产品名称在产品资料库中必须唯一。
- 产品规格使用一个组合字段“颜色/规格”，产品资料同步使用聚水潭properties_value；订单导入仍使用多维表格中的严格原始组合值进行匹配，不拆分颜色、花型或尺码，也不进行模糊猜测。
- 系统内部为产品生成productId，为每个“产品＋颜色/规格”组合生成variantId。
- 页面展示的“产品编码”使用聚水潭SKU条码字段sku_id；该字段用于唯一识别具体产品规格，不使用多维表格中的内部产品编码。
- 产品图片和货号为可选字段，一期有资料时用于页面展示、发货清单和加工合同导出；没有资料时对应Excel单元格留空。
- 聚水潭是产品资料的唯一上游。系统只把聚水潭“商品分类”精确等于“童帽春夏、童配春夏、童装春夏、童帽秋冬、童配秋冬、童装秋冬”且来源状态为启用的产品和规格纳入本系统产品库；分类名称不使用包含、前缀或模糊匹配。
- 系统后端首次扫描聚水潭产品资料、后续按修改时间增量读取，并在服务器按上述分类白名单和启用状态判断是否可用于新订单；已经同步的产品或规格后续被停用或移出白名单分类时，只标记为不可用于新订单，不删除历史记录或既有业务引用。增量读取必须能够识别已同步资料的停用和移出分类变化，不能因只请求当前启用或当前白名单数据而漏掉状态退出。
- 聚水潭字段映射为i_id→货号、pic→图片、sku_id→产品编码、name→产品名称、properties_value→颜色/规格；同时保存来源商品分类、来源启用状态和来源修改时间用于范围判断与追溯。管理员和工厂均不能在本系统内新增、修改或删除产品及规格。

### 3.2 工厂资料

- 系统工厂名称用于日常识别、派工和筛选，必须填写且全系统唯一，与合同中的单位全称分开保存。
- 工厂资料单独保存《成品工厂供应商信息》中的供应商编号，例如禹帆为A10、金甲为E01；供应商编号与用于生成合同编号的工厂代码是两个独立字段。供应商编号必须填写、统一保存为大写且全系统唯一。
- 管理员网页端工厂列表在工厂名称前展示供应商编号；工厂详情弹窗展示供应商编号；新增工厂时录入并校验供应商编号；普通编辑弹窗只读展示供应商编号。
- 工厂资料保存工厂代码、单位全称、单位地址、法定代表人、一个或多个联系人及联系电话。
- 工厂代码必须填写且全系统唯一，例如希舟为XZ，用于生成合同编号；单位全称允许多个工厂记录使用相同值。
- 飞书多维表格同步统一、正确的工厂名称，系统直接与日常工厂名称严格匹配，不维护来源别名，也不使用模糊匹配；名称不一致时阻止导入并修正上游数据。
- 导出加工合同前，工厂代码、单位全称、单位地址和法定代表人必须填写；联系人及联系电话可以留空。
- 系统不录入或保存委托代理人、开户银行和银行账号；加工合同模板中的对应位置保持空白。
- 上线前使用现有《成品工厂供应商信息》一次性初始化工厂资料；系统不长期提供批量导入入口，后续由管理员在工厂资料页面新增或编辑。

### 3.3 主订单

- 订单编号从飞书多维表格导入，或由管理员在应急手工新建时填写，例如E81；该字段必填且全系统唯一。
- 数据库使用内部 orderId 关联数据，订单编号用于人员识别和Excel匹配。
- 一个订单包含多条产品明细，每条明细为“产品＋颜色/规格＋订单数量”。
- 同一订单内相同产品规格只能有一条明细；重复添加时自动合并数量。
- 一个主订单可以派给多个工厂。
- 一个主订单只指定一名跟单人员；跟单人员用于订单归属展示和筛选，不限制其他管理员查看或处理该订单。

### 3.3.1 飞书多维表格订单导入

- 一期读取业务指定多维表格“生产部--下单表以及成品进度表”中的“总表（误删）”视图，以飞书记录ID作为外部来源标识，以订单编号聚合属于同一订单的全部明细。
- 多维表格一行对应一条“订单编号＋商品名称＋产品颜色&规格原文＋工厂＋下单数”明细；同一订单可以通过多行分配给多个工厂。
- 一期不设置每5分钟或其他定时自动发现任务。管理员在网页端“待导入订单”页点击“获取飞书新订单”，系统才从上述指定多维表格和视图增量读取尚未导入、尚未排除的新来源记录，并按订单编号聚合为待处理候选订单。
- 待处理候选订单是飞书来源快照，不属于系统订单；获取只生成或更新候选记录，不直接创建草稿订单或正式订单。获取完成后页面反馈新增、已存在或跳过、失败数量，并展示上次成功获取时间。
- 首次上线导入支持按下单时间、订单编号、工厂和产品筛选，并按完整订单勾选；不允许只选择同一订单中的部分明细。
- 同一订单只要至少一个颜色/规格来源明细的原始发货进度严格小于50%，就进入候选并允许在其他校验通过后导入；等于50%不属于“小于50%”。全部颜色/规格的原始发货进度均大于或等于50%时，本次获取计入跳过，不生成候选。
- 符合范围时必须导入该订单的全部来源明细和全部颜色/规格，不只导入发货进度低于50%的行；原始发货进度按该行“出货总数÷下单数”计算，下单数必须为正整数。
- 待导入订单页只使用“待处理、已导入”两个页签；管理员可以删除一张仍处于待处理状态的完整候选订单，不允许只删除同一订单中的部分明细。
- 删除前必须二次确认。删除只在本系统中将该候选订单标记为已排除，不删除或回写飞书源数据；系统保留飞书来源记录ID、操作人和操作时间，后续增量发现时跳过该来源记录，不再提供“已忽略”页签或恢复操作。
- 管理员在待导入页检查全部明细并一次性“确认导入为草稿”；只有同一订单的全部有效明细校验通过后，系统才以单次事务生成草稿订单及其派工数据，避免只导入部分明细。草稿可以编辑、完成派工并发布，工厂不可见；发布后才成为工厂可见、可执行的正式订单。
- 导入前必须严格校验订单编号、商品名称、产品颜色&规格、工厂、下单数、合同出货时间和跟单人员。订单日期不作为候选校验条件；颜色/规格直接使用多维表格组合值，不进行字符串拆分或模糊猜测。
- 同一订单全部明细的“跟单人员”必须一致且只能有一人；为空、多人或明细之间不一致时，订单停留在待导入状态，由管理员确认统一后再导入。
- 产品资料库不存在对应聚水潭SKU条码，或“产品名称＋颜色/规格”无法严格匹配时，订单停留在待导入状态；系统必须先完成聚水潭产品资料同步并重新校验，不允许在订单确认时创建本地产品资料。
- 工厂名称无法严格匹配系统工厂资料时，订单停留在待导入状态。管理员必须先创建工厂资料并保存名称绑定；后续相同名称自动复用绑定关系。
- 订单涉及的全部工厂都至少有一名审核通过且启用的用户后，管理员才能确认导入为草稿，确保草稿后续发布为正式订单时能够通知到工厂。
- 已经存在的订单编号不能重复导入；同一批飞书记录重复拉取时必须返回原导入结果，不得重复创建订单或派工。
- 系统每次手动获取只增量读取尚未导入、尚未排除的新来源记录；重复点击不得重复生成候选记录、草稿订单或正式订单。“已导入”表示来源候选记录已经生成对应草稿或后续正式订单，不等同于订单已经发布。
- 管理员确认导入为草稿时把当前来源快照写入MySQL正式数据库；以后手动获取时跳过已导入记录，不检测或同步其后续修改，也不自动回写多维表格。
- 系统记录每次手动获取、校验、确认导入、成功或失败的时间、管理员、飞书记录ID和错误原因，便于追溯与重试；单次获取失败不得影响已有候选记录、草稿订单或正式订单。
- 管理员网页应用保留最小版应急手工新建入口，放在“更多操作”中，不支持订单Excel批量导入；手工订单与飞书导入订单共用相同字段、校验、派工和发布流程，并分别记录来源为feishu或manual。
- “下单时间”映射为可空订单日期：来源存在时保存，缺失时允许为空；同一订单多条来源日期不一致也不阻止导入。订单日期不在订单页面展示，不作为候选校验条件；“商品名称”映射为产品名称；“产品颜色&规格”原值映射为颜色/规格；“下单数”映射为工厂下单数量；“跟单人员”映射为主订单唯一跟单人员。
- “生产计划出货时间（提前或者推迟 的时间）”映射为系统“合同出货时间”；多维表格中由采购底表计算得到的同名公式字段“合同出货时间”不作为一期订单交期来源。
- 同一订单全部来源明细的合同出货时间必须一致且只能有一个；为空或不一致时，订单停留在待导入状态，由管理员统一确认后再导入。
- 确认导入时按每条来源明细保存“初始已发数量”，并与系统后续有效发货数量分开持久化；不得把导入前历史数量伪造成系统发货单、数量台账事件或操作记录。
- 初始已发数量是不可降低的导入历史基线。普通草稿编辑不得清零、改小或绕过它；任一工厂派工数量不得调整为小于该派工的初始已发数量，订单明细数量不得调整为小于其全部派工初始已发数量合计。
- 飞书导入成功后在订单操作日志写入“从飞书导入订单：订单数量 3,000，初始已发数量 2,382，未发数量 618。”，实际数字按订单汇总并使用千分位；日志至少可查询时间、操作人和操作内容。
- 多维表格中的裁剪、裁剪进度、绣花和印花等生产进度字段继续保留在原表，不导入一期跟单系统。

### 3.4 工厂派工与合同出货时间

- 每张订单只保存一个合同出货时间，订单内所有产品规格和工厂共用该时间。
- 管理员发布订单前，按产品规格、工厂和下单数量完成派工，并填写订单级合同出货时间。
- 同一产品规格可以分配给多个工厂。
- 订单发布前，各工厂的下单数量之和必须等于该订单明细数量。
- 派工明细不录入、不展示也不保存加工单价；加工单价仅在导出的加工合同Excel中保留空白列，由管理员导出后自行填写。
- 一期不支持订单开始执行后增加工厂或调整已发布分配。尚未产生正式发货单时，管理员可以撤回已发布订单；撤回后订单回到“草稿”，保留原订单内容和操作日志，撤销相关工厂待办并通知相关工厂用户。
- 工厂只能读取分配结果，不填写计划数量。

### 3.5 发货单与装箱

- 一张发货单只能属于一个工厂，但可以包含该工厂的多个订单。
- 发货单号由系统生成并全系统唯一，格式为 FH＋日期＋当日流水号，例如 FH20260722-001。
- 一只实体纸箱可以混装不同订单、不同产品和不同规格。
- 每只实体纸箱必须有箱号；小程序只记录箱号及内容，不提供箱标打印或二维码。
- 相同装法的连续箱子使用“装箱组”批量录入，尾箱和混装箱可以单独录入。

### 3.6 加工合同

- 一份加工合同只对应一个主订单和一个工厂；同一订单分给多个工厂时，分别生成合同。
- 同一合同可以包含该订单分配给该工厂的多个产品规格，全部明细共用该订单唯一合同出货时间。
- 首次导出时合同签订日期默认当天，管理员可以修改；系统保存到“订单＋工厂”合同信息中，重复导出沿用已保存的日期和合同编号。
- 同一签订日期、同一工厂的第一份合同使用无序号编号，格式为“YYYYMMDD-KK-工厂代码”，例如“20260713-KK-XZ”。
- 同一签订日期、同一工厂后续首次生成的第二份、第三份合同依次使用“-1”“-2”等后缀，例如“20260713-KK-XZ-1”和“20260713-KK-XZ-2”；已保存和已导出的合同编号永不重排或修改，订单编号不写入合同编号。
- 系统保存每次导出时的合同字段快照、导出人和导出时间，产品资料或工厂资料后续修改不覆盖已经保存的历史导出记录。

### 3.7 质检单返修与按发货单退回

- 质检单返修与按发货单退回是两个不同流程：前者从“返修退回”页签创建独立返修任务，后者从有效正常发货单详情中执行退回操作。
- 退回日期自动使用当天，不录入仓库退回物流单号；所有创建和数量变更均保留操作日志。

**质检单退回：**

- 质检单退回不关联原订单或原发货单。系统生成全系统唯一返修单号；一张返修单只属于一个工厂，可以包含多个产品规格和箱号明细。
- 管理员上传Excel后，系统读取供应商编号、厂家名称、商品编码、款式编码、商品名称、颜色/规格、数量、箱号、次品原因和次品照片；次品原因和照片允许为空。
- 质检单按“箱号＋产品规格”保留原始明细，不因产品规格相同而丢失箱号、原因或照片的对应关系；列表或详情可以另外汇总相同产品规格的数量。
- 系统使用供应商编号或已绑定工厂名称匹配工厂，使用聚水潭产品编码严格匹配产品规格。无法匹配的工厂或产品必须在导入预览中标出，全部有效明细确认前不能生成正式返修单。
- 原始质检Excel作为返修单附件保留；管理员和该返修单所属工厂可以查看或下载，其他工厂不可访问。系统能解析的照片自动显示；无法解析时允许管理员补传，照片缺失不阻止创建返修单。
- 返修单创建后成为对应工厂的返修任务。工厂可以分多次发回，每次选择返修任务和产品规格，填写本次返修数量和报废数量。
- 每条返修发回记录保存工厂提交发货的系统时间及产品编码、产品名称、颜色/规格、返修数量、报废数量、返回数量和仓库退回数量；其中返回数量等于返修数量与报废数量之和，仓库退回数量为同一返修单内相同产品编码、产品名称和颜色/规格的质检明细数量合计。
- 返修数量表示工厂已完成返修并随本次记录发回的数量；报废数量表示工厂判断无法返修但仍随本次记录返回仓库的数量，不代表工厂可以自行销毁。
- 每次提交必须满足“返修数量＋报废数量＝本次发回实物总数量”；所有有效发回记录的返修数量与报废数量合计为返修单返回总数量，且不得超过仓库退回总数量。
- 工厂提交返修发回记录后数量立即生效，不再经过管理员确认收回；返回总数量等于仓库退回总数量时返修单自动完成。
- 只有已完成的返修单可以由管理员归档。归档不是删除，也不是返修状态；归档后管理员网页端、管理员小程序和所属工厂小程序均不再展示该返修单，但返修数据、附件、发回记录、归档人、归档时间和操作日志继续保留。
- 质检单返修数量不改变任何正常订单的已发数量、多发或少发结果。

**发货单撤回与作废：**

- 正式发货单提交后不能直接编辑或删除。所属工厂启用用户可以在本厂发货单详情点击“撤回发货”，填写必填原因后提交作废申请；申请入口不设置提交时限。
- 提交申请只把发货单置为“作废申请中”，不改变订单、派工或发货数量。同一发货单同一时间最多存在一个待处理申请；待处理期间禁止新增按发货单退回。
- 管理员在发货单详情的“撤回申请”卡片审核通过或拒绝，不新增独立作废列表。审核拒绝不改变数量，发货单恢复“已发货”；审核通过保留原发货事实并追加等量负向数量记录，发货单变为“已作废”。
- 工厂可以对已经发生部分退回的发货单提交撤回申请，但该申请不得审核通过，管理员只能拒绝，避免对已退数量重复扣减。审核通过前服务端必须再次校验不存在任何已生效退回。
- 申请、审核和数量变更均保留申请人、申请时间、原因、审核人、审核时间、审核意见及操作日志；重复或并发请求不得重复生成申请或数量记录。

**按发货单退回：**

- 只有有效的已发货正常发货单才在“发货明细”标题栏右侧显示“退回”操作。管理员点击后打开弹窗，不跳转到“返修退回”页签。
- 弹窗居中显示，不重复展示发货单号、工厂和关联订单信息；标题下直接展示退回明细表，字段为选择、订单编号、产品编码、产品名称、颜色/规格、发货数量、可退数量和本次退回数量。订单编号只读展示，每一行固定对应工厂提交发货时绑定的原订单派工，管理员不能重新选择或改变订单归属。管理员勾选产品规格后填写本次退回数量，并在表格下方填写本次选中产品共用的退回原因；退回原因必填。
- 同一正常发货单产品规格可以分多次退回，但累计退回数量不得超过该明细当前可退数量；可退数量等于该明细已发数量减去已生效的累计退回数量。
- 弹窗底部只提供“取消”和“确认退回”，不显示数量影响提示。
- 管理员确认退回后，系统立即从对应订单产品规格与工厂任务中扣减已发数量；未发数量相应增加。
- 按发货单退回不生成独立业务单号、独立列表记录或独立状态；系统必须在原发货单详情和原订单操作日志中保留退回日期、操作人、产品规格、退回数量、退回原因以及数量变更前后值。
- 如果来源订单已经完成，确认退回后自动恢复为“未完成”；当前日期已经晚于合同出货时间时显示为“已逾期”，并保留原完成记录和本次恢复原因。
- 工厂后续在原正常订单任务中按增加后的未发数量创建普通发货单，继续使用正常装箱和提交发货流程。
- 按发货单退回不生成工厂返修任务或返修发回记录，工厂不填写返修数量或报废数量；普通补发提交后重新计入正常订单已发数量。

## 4. 一期主流程

```mermaid
  B --> C[工厂创建发货单并装箱]
  C --> D[工厂提交正式发货单]
  D --> E[发货记录立即生效并计入已发数量]
  E --> F[管理员确认订单完成]
```

```mermaid

  R1[管理员上传质检单创建返修单] --> R2[工厂查看返修任务]
  R2 --> R3[工厂分批填写返修数量和报废数量]
  R3 --> R4[返修数量与报废数量立即计入返回总数量]
  R4 --> R5[返回总数量等于仓库退回总数量后自动完成]
```

```mermaid
flowchart LR
  T1[有效发货单详情打开退回弹窗] --> T2[选择产品规格填写数量和必填原因]
  T2 --> T3[扣减订单已发数量]
  T3 --> T4[原工厂正常未发数量增加]
  T4 --> T5[工厂创建普通发货单补发]
  T5 --> T6[补发记录提交后立即生效]
```

### 4.1 管理员创建并派发订单

1. 管理员填写唯一订单编号并选择产品规格和订单数量。
2. 管理员填写订单唯一合同出货时间，并将每条产品规格按工厂和数量拆分。
3. 系统校验每条产品规格的全部下单数量等于订单数量。
4. 管理员正式发布后，相关工厂收到新任务通知。

### 4.2 工厂发货

1. 工厂从本厂未完成任务中选择本次发货的订单产品规格，不允许自由输入产品名称。
2. 系统默认按最早未完成合同出货时间优先分配发货数量。
3. 当同一规格同时存在于多个订单时，系统按合同出货时间最早的订单优先分配，提交前展示分配结果，工厂可以调整。
4. 超过所有订单待交数量的部分必须由工厂在提交前选择归属订单。
5. 工厂按箱号或装箱组填写实际装箱内容。相同装法录入一次即可批量生成连续箱号。
6. 系统自动汇总数量并校验装箱明细与发货数量一致。
7. 工厂可以选填0至3张压缩后的发货凭证照片和备注。
8. 提交后发货单进入“已发货”，立即形成有效发货记录并计入订单已发数量；正式记录不可直接修改或删除。

### 4.3 发货记录生效

一期不设置管理员收货确认。工厂提交正式发货单后，发货日期、发货数量、装箱明细、凭证和备注立即形成有效发货记录，并计入订单已发数量。系统不保存待收货、已收货、实际收到数量、到货日期、少货、多货或规格不符等正常收货数据。

### 4.4 管理员确认订单完成

订单不会因为已发数量达到订单数量而自动完成。管理员确认本订单不再继续发货，并核对全部有效发货记录后，手工执行“确认订单完成”。

确认前系统必须检查：

- 不存在待管理员处理的发货单作废申请。

全部大货发货记录核对完成后，即使已发数量多于或少于订单数量，管理员仍可确认订单完成。系统记录完成人、完成时间，并永久显示多发或少发结果。

### 4.5 次品退回返修

1. 质检单退回：管理员在网页端进入“返修退回”，上传质检Excel并确认明细后生成独立返修任务；工厂分批填写返修数量和报废数量，提交后立即计入返回总数量，返回总数量达到仓库退回总数量后自动完成。
2. 按发货单退回：管理员在有效正常发货单详情中打开“退回”弹窗，选择产品规格，填写退回数量和必填的退回原因。
3. 管理员确认按发货单退回后，系统扣减对应已发数量，并在原发货单和订单日志中保留记录。
4. 按发货单退回后，原工厂正常任务的未发数量增加；工厂通过普通发货单补发，不填写返修或报废数量。
5. 已完成订单发生按发货单退回时自动恢复为“未完成”；当前日期已经晚于合同出货时间时显示为“已逾期”。补发记录提交后，由管理员再次确认订单完成。

## 5. 状态定义

### 5.1 订单主状态

| 状态 | 定义 |
| --- | --- |
| 未完成 | 订单已经发布、尚未由管理员确认完成，且当前日期未晚于合同出货时间。是否已经产生发货记录通过数量与进度展示，不再拆分订单状态。 |
| 已逾期 | 订单尚未由管理员确认完成，且当前日期已经晚于合同出货时间。 |
| 已完成 | 全部大货发货记录核对完毕，管理员执行“确认订单完成”。 |

订单状态判定优先级为“已完成”高于“已逾期”高于“未完成”。草稿是订单正式发布前的编辑阶段，不属于正式订单状态；订单不设置“已取消”状态。未产生任何有效发货记录的正式订单可以由管理员直接删除；删除后不再出现在订单列表和工厂任务中，但删除操作日志必须保留。

### 5.2 发货单状态

草稿 → 已发货。已发货记录立即计入订单已发数量，不设置待收货或已收货状态；异常作废流程为“作废申请中 → 已作废”。

### 5.3 质检单返修状态

| 状态 | 定义 |
| --- | --- |
| 未完成 | 返回总数量小于仓库退回总数量；是否已经提交过发回记录通过数量与返回进度展示，不再拆分返修状态。 |
| 已完成 | 返回总数量等于仓库退回总数量。 |

质检单返修没有截止日期，不设置“已逾期”状态。

### 5.4 质检单返修发回记录

工厂提交后记录立即生效，不设置待确认收回或已收回状态，也不复用正常发货单状态和编号。

### 5.5 按发货单退回操作

管理员确认后数量扣减立即生效。该操作不设置独立业务单号、列表记录或工厂返修状态；后续补发状态由原订单和普通发货单状态承接，原发货单和订单日志保留完整操作证据。

## 6. 数量与进度口径

### 6.1 正常订单数量

| 指标 | 计算或定义 |
| --- | --- |
| 订单数量 | 管理员在主订单产品明细中填写的目标数量。 |
| 下单数量 | 管理员按工厂和合同出货时间为该工厂设定的目标下单数量。 |
| 初始已发数量 | 飞书订单导入时逐派工保存的历史发货基线；手工订单为0，不生成系统发货记录，普通草稿编辑不得降低。 |
| 系统有效发货数量 | 工厂全部有效普通发货单的申报数量合计－已生效的作废和按发货单退回数量；退回后通过普通发货单补发时重新增加。 |
| 已发数量 | 初始已发数量＋系统有效发货数量。页面、未发数量、进度和加工合同资格统一使用本口径。 |
| 未发数量 | max（下单数量－已发数量，0）。 |
| 多发数量 | max（已发数量－订单数量，0）。 |
| 少发数量 | max（订单数量－已发数量，0）。 |

工厂是否按时按“实际发货日期不晚于合同出货时间”判断。实际发货日期取工厂提交正式发货单的业务日期。

### 6.2 质检单返修数量

| 指标 | 计算或定义 |
| --- | --- |
| 仓库退回总数量 | 管理员通过质检单明细确认由仓库发给工厂处理的数量合计。 |
| 累计返修数量 | 工厂全部有效质检单返修发回记录中“返修数量”的合计。 |
| 累计报废数量 | 工厂全部有效质检单返修发回记录中“报废数量”的合计；对应实物仍须返回仓库。 |
| 返回总数量 | 累计返修数量＋累计报废数量，即工厂通过全部有效返修发回记录累计发回的实物数量。 |
| 待返回数量 | max（仓库退回总数量－返回总数量，0）。 |

质检单返修数量仅用于独立返修单闭环，不参与正常订单的发货进度、多发、少发或完成条件计算。按发货单退回不使用本表口径，直接按第6.1节扣减正常订单数量。

## 7. Excel导出

### 7.1 发货清单导出

工厂提交正式发货单后，管理员可以从网页端发货单详情下载Excel。一张发货单生成一个文件，文件名为“厂家名称_发货日期_发货单号.xlsx”。管理员小程序端可以查看发货单内容，但不承担Excel文件导出。

**Sheet：发货明细**

- 以现有《厂家发货模版.xlsx》样式为基础。
- 标题写入发货日期和总箱数；表头固定为订单编号、箱号、货号、品名、颜色/规格、装箱数量、合计。
- “颜色/规格”直接使用系统组合字段，不拆分为“颜色”和“尺码”，导出文件不增加“尺码”列。
- 混装箱按多行输出相同箱号；相同装法的连续箱组可以显示稳定箱号范围。总箱数按不同实体箱号统计，总数量按明细合计汇总。
- 明细超过模板固定行数时按模板样式自动扩展，不能截断数据。

**Sheet：汇总**

- 表头固定为日期、名称、颜色/规格、数量。
- 按“发货日期＋产品名称＋颜色/规格”汇总；同一发货单中即使来自不同订单，只要这三个字段相同就合并数量。
- 汇总不显示订单编号和箱号；每条明细的原订单归属仍完整保留在“发货明细”和数据库原发货记录中。

最终文件只保留“发货明细”和“汇总”两个 Sheet，删除模板中的空白 `Sheet3`，不得新增其他 Sheet。

发货清单导出后，由管理员按现行工作方式手工更新本地Excel和飞书多维表格。一期不提供自动回写、双向同步或写入冲突处理。

### 7.2 加工合同导出

管理员在网页端订单详情中，按“一个订单＋一个工厂”导出加工合同Excel；管理员小程序端和工厂小程序端不提供合同导出。

- 只有主订单统一已发数量为0时才能导出加工合同；初始已发数量或系统有效发货数量任一大于0时，首次导出和重复导出均禁止。
- 以现有《0529成品加工合同模版(1).xlsx》样式和固定合同条款为基础，一期只导出.xlsx文件，不生成PDF。
- 合同明细包含产品编号或货号、产品名称、产品图片、颜色/规格、该工厂的下单数量、加工单价、总金额、合同出货时间和备注。
- 系统不提供加工单价录入，不保存加工单价或合同金额；导出的每条明细“加工单价”单元格保持空白。
- 管理员导出后在Excel中补填加工单价，明细总金额和合同总金额通过预置公式自动计算；单价尚未填写完整时，对应金额和合同总金额保持空白。
- 单一产品订单的文件名为“合同编号 订单编号 产品名称.xlsx”；包含多个产品时为“合同编号 订单编号 第一项产品名称等N款.xlsx”。文件名开头的日期和序号必须与工作簿内合同编号完全一致。
- 单位全称、单位地址、法定代表人或工厂代码缺失时禁止导出，并提示管理员先补全工厂合同资料。
- 合同固定条款不在系统中逐份编辑；一期不提供合同审批、在线签署、对账、付款或结算功能。

## 8. 列表、筛选与提醒

### 8.1 订单列表

- 搜索字段：订单编号、产品名称、颜色/规格。
- 正式订单状态筛选：全部、未完成、已逾期、已完成；管理员可另外查看草稿。
- 高级筛选：工厂、跟单人员、合同出货时间范围。由于“已逾期”已经是正式订单状态，不再重复设置“仅看逾期”。
- 排序方式：默认紧急程度、合同出货时间升序、合同出货时间降序、更新时间最新；订单日期可空且不展示，不提供“订单日期最新”排序。
- 默认排序：逾期未完成优先；其他进行中任务按合同出货时间优先；已完成订单排在后面。
- 当前日期晚于订单唯一合同出货时间且订单未完成时，主订单显示逾期提醒。

### 8.2 返修单列表

- 管理员网页端“订单与发货”增加“返修退回”页签。
- 该页签只管理质检单返修任务，顶部支持按返修单号或工厂名称搜索，并按返修状态、工厂多选和退回时间范围筛选；返修状态只使用“未完成、已完成”。
- 退回时间为管理员上传质检单并确认创建返修任务的系统时间，默认记录当天实际创建时间，不由管理员手工填写。
- 列表字段为序号、返修单号、工厂、返修数量、报废数量、返回总数量、仓库退回总数量、退回时间、状态和操作；退回时间只显示年月日，底部显示每页条数并使用与其他管理列表一致的分页。
- 列表操作包含“详情”；已完成返修单另外显示“归档”，点击后二次确认。归档成功后该返修单立即从列表消失，不增加“已归档”页签或恢复入口。详情右上角显示工厂名称和返修状态；数量汇总按两行两列展示，第一行为返修数量和报废数量，第二行为仓库退回总数量和返回总数量。
- 质检单资料展示附件及退回明细，明细列顺序为序号、产品编码、产品名称、颜色/规格、仓库退回数量、箱号、次品原因和次品照片；相邻且箱号相同的明细合并箱号单元格。
- 详情中的工厂发回记录按产品规格展示发货日期、产品编码、产品名称、颜色/规格、返修数量、报废数量、返回数量和仓库退回数量；返回数量等于该行返修数量与报废数量之和，仓库退回数量为该规格最初由仓库发给工厂的数量，发货日期只显示年月日，不显示时间，不提供实际收回数量、收回状态或确认收回操作。
- 管理员通过“新建返修单”直接进入质检Excel上传、导入预览和确认创建流程，不提供退回方式选择。
- 按发货单退回不在该页签展示，也不生成任何独立业务单号。
- 管理员小程序端在底部“发货”板块的“返修进度”页签提供未归档质检单返修列表和详情，支持按“未完成、已完成”筛选并只读展示状态、工厂、仓库退回总数量、返修数量、报废数量、返回总数量、质检明细和工厂发回记录；不提供上传质检单、新建返修任务或确认收回操作。

### 8.3 消息提醒

- 新订单发布：通知相关工厂用户。
- 临近合同出货时间：提前3天早上提醒相关工厂用户和订阅管理员。
- 到期与逾期：合同出货时间当天、逾期第1天提醒，之后每3天提醒一次，直至任务处理完成。
- 工厂发货：通知订阅管理员。
- 发货单作废申请结果：通知对应处理人。
- 管理员通过质检单创建返修任务：通知该返修单所属工厂的已启用用户。
- 工厂提交质检单返修发回记录：通知订阅管理员查看，并可进入管理员小程序“发货—返修进度”的对应详情；提交后数量立即生效，返回总数量达到仓库退回总数量时返修单自动完成。
- 管理员在有效发货单详情弹窗中确认退回：通知对应工厂正常订单未发数量已经增加，并提示按普通发货流程补发。
- 每位用户可以在小程序端关闭业务通知；一期不在管理员网页端提供通知订阅设置页。
- 管理员网页端保留待办、红点和通知记录；未获得微信订阅消息授权或关闭业务通知时，仍显示系统内红点和待办。
- 相同用户、订单和提醒节点必须去重，避免重复发送。

## 9. 数据、权限与审计要求

- 一期新建独立代码项目，在同一项目中分别维护后端服务、管理员网页端和微信小程序，三个程序独立构建和部署，共用同一套API契约。
- 后端服务和管理员网页部署到公司阿里云ECS；后端通过MySQL账号访问数据库，管理员网页端和微信小程序只能通过HTTPS API访问业务数据。
- 开发、测试和生产数据必须隔离。本地开发使用本机MySQL 8.0开发库和测试库；生产环境使用公司ECS上的MySQL 8.0独立正式数据库。
- 生产环境上线时不带测试业务数据，但必须预置最高管理员和必要系统配置；最高管理员权限不能由普通申请流程获得。
- 小程序本地缓存只用于开发和演示，不能回写为正式数据。
- 所有查询和写入必须由服务器后端按用户角色、工厂归属和记录状态校验，不能只依赖前端隐藏按钮。
- 飞书管理员网页应用和小程序端必须通过统一的服务器业务API访问正式数据，不得分别维护独立业务数据库。
- 飞书身份和微信身份均映射到系统内部userId；同一内部管理员在两个终端共享角色和操作记录。管理员网页端申请使用飞书返回的企业通讯录已验证手机号，不再填写手机号或使用短信验证码；小程序首次绑定时授权手机号，服务器只在标准化号码一致且唯一匹配时绑定微信身份。
- 管理员申请只能从网页端提交；小程序未匹配到网页申请时只提示前往网页端申请，不在小程序创建管理员申请。手机号不一致或无法唯一匹配时不得自动合并用户。
- 飞书应用凭证、微信应用凭证、多维表格访问凭证、数据库密码及其他密钥只保存在服务器环境变量或密钥配置中，不得写入网页、小程序代码、Git或数据库业务记录。
- 管理员在任一终端完成写入后，另一终端重新查询时必须看到一致结果；操作日志使用同一管理员身份记录来源终端、操作人和时间。
- 用户申请与审核、待导入订单删除、订单发布与撤回、订单删除、正常发货、质检单返修创建、发回与归档、发货单详情退回与订单进度扣减、合同导出、完成、撤销和作废操作均记录操作人、时间和变更内容。
- 正式发货单不能直接编辑或删除。工厂提交作废申请，管理员审核后作废，系统回退对应数量并保留原记录。
- 管理员误操作“订单完成”时，可以填写原因撤销完成，订单恢复为“未完成”；当前日期已经晚于合同出货时间时显示为“已逾期”，原完成记录必须保留。
- 正式数据库必须使用项目独立账号和最小权限，不得使用MySQL root账号作为应用运行账号；正式库必须配置自动备份并在上线前验证恢复流程。

### 9.1 上线切换与工厂推广

1. **试运行：**选择两至三个配合度较高的工厂，使用符合“至少一个颜色/规格原始发货进度严格小于50%”条件的完整订单试运行，验证历史基线、任务查看、装箱、发货记录和订单进度流程。试运行订单一经导入即以新系统为准，不要求工厂重复维护旧发货数据。
2. **正式切换：**试运行稳定后确定统一切换日期。切换日期之后新增的订单全部进入待导入列表，经管理员确认后使用新系统；切换前订单仅在满足本文严格小于50%整单导入条件时进入新系统，其余继续按旧方式处理到结束。

当前仍合作的工厂资料可以在上线前统一初始化。试点工厂用户先在小程序申请并由管理员审核；每个订单涉及的全部工厂至少有一名已启用用户后才能确认导入为草稿。草稿对工厂不可见，只有草稿发布为正式订单后，被分配的工厂才会收到任务。上线后不长期要求同一订单同时维护新旧两套发货数据。

| 管理员小程序端 | 订单 | 只读查看待办、搜索和筛选订单，以及查看订单详情、工厂进度、合同出货时间和异常状态。 |
| 管理员小程序端 | 发货 | “发货记录”页签只读查看正常发货概览、按规格汇总的发货明细、逐箱装箱明细、发货凭证、工厂备注和操作记录，不展示产品图片、产品编码或管理操作；“返修进度”页签只读查看未归档质检单返修列表、数量进度、质检明细和工厂发回记录。 |
| 工厂小程序端 | 工厂任务 | 查看本厂正常订单任务和未归档质检单返修任务；按发货单退回只增加原正常订单的未发数量，不生成独立返修任务。 |
| 工厂小程序端 | 发货记录 | 只展示本厂正常订单发货记录，支持按订单编号或产品名称搜索及按发货日期范围筛选；详情按订单和箱号默认折叠展示明细，并展示发货凭证、工厂备注和操作记录；工厂端申请作废的操作名称显示为“撤回发货”，提交后仍须管理员审核。页面不设置返修页签，返修历史发回记录在对应返修任务详情查看。 |
| 工厂小程序端 | 创建发货单 | 选择本厂订单明细、填写实际发货数量、创建箱号或装箱组、上传凭证并提交发货。 |

## 11. 一期验收标准

- [ ] 飞书管理员网页应用、管理员小程序端和工厂小程序端通过同一套公司服务器API访问MySQL正式数据库，不直接连接数据库，也不分别维护独立业务数据。

- [ ] 新代码项目分别包含服务器后端、管理员网页端和微信小程序；现有CloudBase小程序不再作为正式开发基础。

- [ ] 管理员可以在“待导入订单”页点击“获取飞书新订单”，从“生产部--下单表以及成品进度表”的“总表（误删）”视图增量获取尚未导入、尚未排除的新来源记录，按订单编号生成待处理候选；系统不设置每5分钟或其他定时自动发现，未经管理员确认导入不会创建草稿订单。

- [ ] 订单只要至少一个颜色/规格原始发货进度严格小于50%即可按整单导入全部明细；等于50%不满足“小于50%”，全部规格均大于或等于50%时不生成候选。
- [ ] 飞书来源订单日期存在时保存、缺失时允许为空，订单日期不阻止候选导入、不在订单页面展示，也不提供误导性的订单日期排序。
- [ ] 每个导入派工独立保存初始已发数量；页面统一已发数量等于初始已发数量加系统有效发货数量，未发数量和进度据此计算，草稿编辑不能降低基线或把订单/派工数量改到基线以下。
- [ ] 飞书导入成功后订单详情底部操作日志显示时间、操作人和汇总文案；待导入详情每行校验结果只显示“通过”或“未通过”，详细原因保留在页面顶部。

- [ ] 待导入订单页只显示“待处理、已导入”；管理员可以二次确认后删除整张待处理候选订单，系统不删除飞书源数据，但保留来源记录ID及操作日志并确保后续同步不再重复出现。

- [ ] 系统首次扫描并按修改时间增量读取聚水潭产品资料，只把六个指定商品分类中来源状态为启用的产品和规格纳入本系统，以sku_id作为页面产品编码；已同步资料被停用或移出分类后不可用于新订单但不删除历史。产品资料未同步或无法严格匹配时订单不能导入，全部明细校验通过后才能一次性确认导入为草稿；草稿发布后才成为工厂可见、可执行的正式订单。

- [ ] 订单涉及的每个工厂都必须至少有一名审核通过且启用的用户，未满足时不能确认导入。

- [ ] 重复点击“获取飞书新订单”不会重复生成候选记录、草稿订单或正式订单；获取完成反馈新增、已存在或跳过、失败数量并展示上次成功获取时间，失败不影响已有草稿或正式订单；系统不检测已导入记录修改，也不自动回写多维表格。

- [ ] 系统使用“生产计划出货时间（提前或者推迟 的时间）”作为合同出货时间，使用“出货总数”和“下单数”计算原始发货进度并判断严格小于50%的整单导入范围，不读取同名公式合同日期或裁剪、绣花、印花等生产进度字段。

- [ ] 一个订单只有一名跟单人员；同一订单明细中的跟单人员为空、多人或不一致时不能确认导入，跟单人员不限制其他管理员查看和处理。

- [ ] 管理员网页端作为独立网站时显示“通过飞书登录”；完成飞书授权后由服务器识别企业用户并取得飞书已验证手机号。未获角色的内部人员只能在网页端提交管理员身份申请，页面只展示飞书姓名和脱敏手机号，不填写手机号、不使用短信验证码、不填写职位；只有最高管理员可以查看、通过或拒绝申请。飞书未返回可用手机号时不得创建申请。

- [ ] 管理员小程序不提供管理员申请入口；首次进入时取得微信身份并授权手机号，只在手机号与网页端已验证申请一致且唯一匹配时绑定到同一内部userId。没有申请、手机号不一致或无法唯一匹配时不自动创建或合并账号，并提示前往网页端申请或联系最高管理员。

- [ ] 管理员小程序默认使用微信头像并允许仅在小程序端更换，不覆盖网页端飞书头像；“退出登录”经二次确认后只清除当前会话，不解除微信、手机号与内部userId绑定，重新登录不重复授权手机号。

- [ ] 网页端和小程序端在首次登录或绑定后自动续期：页面刷新、关闭后重新打开及正常服务重启不要求重新登录；并发请求只触发一次续期。主动退出、账号停用或权限撤销、清除客户端数据、续期凭证异常或连续30天未使用后不能恢复旧会话。

- [ ] 最高管理员不能通过普通申请流程获得；生产环境预置最高管理员并允许配置多名。普通管理员和最高管理员均可审核工厂用户申请、绑定工厂及管理工厂用户启停；只有最高管理员可以管理普通管理员启停，最高管理员账号不能在人员管理页面停用。

- [ ] 工厂用户申请包含真实姓名、经本人授权验证的联系电话、职位和申请工厂；管理员从详情弹窗核对工厂资料联系人后通过或拒绝，拒绝必须填写原因，已处理申请保留审核人、审核时间和拒绝原因。

- [ ] 管理员网页端工厂列表和详情弹窗展示《成品工厂供应商信息》中的供应商编号；新增工厂时编号必填、自动转为大写且不能重复，编辑时编号只读；供应商编号与生成合同编号使用的工厂代码分开保存，不互相覆盖。

- [ ] 系统不提供委托代理人、开户银行、银行账号或来源别名的录入字段，不在数据库保存这些数据；飞书工厂名称直接严格匹配系统工厂名称，加工合同模板中已取消资料的对应位置保持空白。

- [ ] 普通管理员默认查看全部业务数据，不按申请人职位或订单跟单人员限制数据范围；同一管理员账号在网页端和小程序端具有相同角色和数据范围，任一终端完成操作后另一终端可以查询到一致结果。

- [ ] 管理员网页端可以完成订单导入与手工创建、多工厂派工、查看发货记录、发货清单和加工合同Excel导出、订单完成以及基础资料和人员管理的完整流程；系统不提供正常收货确认或加工单价填写。

- [ ] 管理员小程序端可以只读查看订单和进度，以及正常发货单的发货概览、按规格汇总的发货明细、逐箱装箱明细、发货凭证、工厂备注、操作记录和质检单返修进度及详情；不展示产品图片、产品编码，也不提供确认订单完成或其他订单状态变更操作。

- [ ] 管理员可以创建唯一订单编号，为每张订单填写唯一合同出货时间，并将每个产品规格完整分配到多个工厂。

- [ ] 尚未产生正式发货单的已发布订单可以撤回到草稿；订单内容和日志保留，相关工厂待办被撤销并收到通知；产生正式发货单后不能撤回。

- [ ] 订单不设置“已取消”状态；管理员可以直接删除尚未产生有效发货记录的正式订单，删除后订单及相关工厂任务不再展示，但删除操作日志保留。

- [ ] 工厂只能看到本厂任务，无法读取其他工厂数据。

- [ ] 工厂可以在不重复填写计划数据的情况下创建多订单、混装箱发货单。

- [ ] 装箱组可以批量录入相同装法，系统正确生成箱号和数量汇总。

- [ ] 工厂提交正式发货单后，发货记录立即生效并计入订单已发数量；系统不提供待收货、已收货、实际收到数量、到货日期或异常收货流程。

- [ ] 系统按实际发货日期和合同出货时间正确判断工厂是否按时发货。

- [ ] 管理员可以在全部大货发货记录核对完毕后确认订单完成，系统按已发数量正确显示多发或少发。

- [ ] 管理员网页端“返修退回”只管理质检单返修任务；新建时直接进入质检Excel上传和预览，不提供退回方式选择。

- [ ] 质检Excel可以读取并预览工厂、产品规格、数量、箱号、次品原因和照片；系统保留原始Excel，按箱号保存原始明细，原因和照片允许为空，无法解析的照片可以补传；所属工厂可以在返修任务详情查看或下载原始质检附件，其他工厂不可访问。

- [ ] 只有有效的已发货正常发货单才显示“退回”；操作从发货单详情弹窗进行，工厂和订单自动带出，管理员选择产品规格，填写退回数量和必填的退回原因。

- [ ] 按发货单退回不生成独立业务单号或列表记录；原发货单详情和原订单操作日志可以查看退回日期、操作人、产品规格、数量、原因和变更前后值。

- [ ] 工厂只能查看本厂质检单返修任务，可以分多次填写返修数量和报废数量；两者之和等于本次发回实物总数量，报废实物仍须返回仓库。

- [ ] 工厂可以对本厂已发货发货单提交无时限的“撤回发货”申请，提交本身不改变数量；同一发货单最多一个待处理申请，待处理期间禁止新增退回。

- [ ] 已经发生部分退回的发货单仍可提交撤回申请，但管理员只能拒绝、不得审核通过；服务端在审核通过前重新校验，不能依赖前端按钮状态。

- [ ] 只有已完成返修单可以归档；管理员二次确认归档后，管理员网页端、管理员小程序和所属工厂小程序均不再展示该返修单，且系统继续保留返修数据、归档人、归档时间和操作日志。

- [ ] 工厂提交质检单返修发回记录后，返修数量与报废数量立即计入返回总数量；不提供管理员确认收回操作，返回总数量等于仓库退回总数量后返修单自动完成。

- [ ] 质检单返修不改变正常订单进度；按发货单退回确认后扣减对应订单的已发数量，使工厂正常未发数量增加。

- [ ] 按发货单退回不生成工厂返修任务，工厂从原正常订单任务创建普通发货单补发，不填写返修数量或报废数量；补发提交后数量按正常订单规则恢复。

- [ ] 订单在三端只使用“未完成、已逾期、已完成”三个正式状态；未完成订单超过合同出货时间自动显示“已逾期”，已完成优先于逾期判断。返修任务只使用“未完成、已完成”，不设置截止日期或“已逾期”。

- [ ] 已完成订单发生按发货单退回时自动恢复为“未完成”，若当前日期已经晚于合同出货时间则显示为“已逾期”；保留原完成记录和恢复原因，补发记录提交后由管理员再次确认完成。

- [ ] 管理员可以下载只包含“发货明细”和“汇总”两个 Sheet 的 Excel；空白 `Sheet3` 已删除，汇总按“发货日期＋产品名称＋颜色/规格”跨订单合并，原订单归属仍保留在发货明细中。

- [ ] 导出的发货清单使用组合字段“颜色/规格”，管理员可以据此手工更新现有本地Excel和飞书多维表格。

- [ ] 只有统一已发数量为0的订单可以按“一个订单＋一个工厂”导出.xlsx加工合同；带初始已发数量的订单不能导出。同日同厂第一份合同编号无后缀，第二份使用“-1”，第三份使用“-2”并依次增加，既有编号永不重排；文件名、必填工厂资料、可空图片、空白加工单价列、金额公式及重复导出行为均符合第3.6节和第7.2节。

- [ ] 系统不录入或保存加工单价和合同金额；管理员在导出的Excel中自行填写加工单价后，明细金额和合同总金额由公式正确计算；合同导出不增加PDF、合同审批、在线签署、对账、付款或结算流程。

- [ ] 订单、正常发货、质检单返修创建与发回、发货单详情退回与进度扣减、合同导出、完成、撤销和作废均保留可查询的操作日志。

- [ ] 业务通知只能在小程序端设置；管理员网页端不提供通知订阅设置页，但可以查看待办、红点和通知记录。

- [ ] 本地开发库、自动化测试库和生产正式库相互隔离，生产环境不包含测试业务数据。

- [ ] 生产数据库使用独立最小权限账号并完成自动备份配置；上线前至少完成一次恢复验证。

## 12. 一期不包含

- 系统内加工单价录入、加工单价和合同金额保存，以及基于这些金额的报价、成本核算、对账、付款和结算。
- 管理员网页端与管理员小程序端全部功能逐项复制；复杂录入、Excel和基础资料管理以网页端为准。
- 正常发货单的仓库收货确认、实际收到数量、到货日期、少货、多货或规格不符处理。
- 加工合同导出之外的其他合同管理能力。
- 工厂委托代理人、开户银行、银行账号和来源别名的录入与保存。
- 把聚水潭中不属于“童帽春夏、童配春夏、童装春夏、童帽秋冬、童配秋冬、童装秋冬”或来源状态非启用的商品作为可用于新订单的产品资料。
- 订单执行后追加工厂或调整已发布分配。
- 检测或同步已导入订单在飞书多维表格中的后续修改。
- 自动回写或双向同步本地Excel和飞书多维表格。
- 把不符合“至少一个颜色/规格原始发货进度严格小于50%”条件的订单导入，或只导入完整订单中的部分明细。
- 电脑文件夹或订单Excel自动导入。
- 把多维表格中的裁剪、裁剪进度、绣花和印花等生产进度同步到一期系统。
- 在系统内创建仓库质检结果、无次品确认或完整仓库质检工作台；一期只导入仓库已经提供的次品质检Excel。
- 返修复检、返修后质量合格判定、再次返修、报废货物收回后的后续处置、赔偿和扣款。
- 仓库向工厂退回次品时的物流单号、物流轨迹和运输状态管理。
- 管理员网页端通知订阅设置页。
- PDF合同、合同审批、在线签署和合同固定条款的逐份编辑。
- CloudBase正式后端、PostgreSQL或与MySQL并行的第二套正式业务数据库。
- 箱标打印和二维码。
- 物流轨迹追踪。
- 超出本需求文档的复杂经营报表。

> **需求基线：**一期开发、测试和验收均以本文档 V1.46 为准。新增业务字段、状态、权限或统计口径时，应先补充需求定义和验收标准。
