# 维护与交接说明

基线：2026-09-30。本套资料覆盖全系统；运行版本、客户版本、启用状态及未验收项见[交付清单](交付清单.md)。历史实施过程留在阶段里程碑与GitHub，日常接手使用本文和现行正文。

## 接手顺序

1. 检查`git status`、分支及worktree，保护现有未提交改动。
2. 阅读根目录[AGENTS](../../../AGENTS.md)、[文档入口](../../README.md)和[CONTEXT](../../../CONTEXT.md)，按[资料读取规则](../../agents/domain.md)确定本次相关资料。
3. 阅读任务所属需求、原型、技术设计、开发计划、当前Issue及依赖；历史决策核对时读取[一期里程碑](../../一期/project/一期里程碑与决策记录.md)相关条目，二期任务读取[二期建设计划](../../二期/project/二期需求建设计划.md)。接续任务读取交接记录，运维与交付任务核对[交付清单](交付清单.md)。
4. 技术接手再读[架构](系统说明与架构.md)、[数据](数据字典与关系图.md)、[接口](接口与外部集成说明.md)及[运维](部署与运维手册.md)。
5. 只读确认当前目标环境与测试基线后，按Issue分支／独立worktree实施。

正式规则与当前实现发生冲突时指出具体条目，按资料职责确认修订。历史“未推送／未部署”描述只表示当时状态；已合并、CI通过、服务器部署、小程序发布和业务签收分别核验。

## 工程与启动

工具链与本地数据库准备见[根目录 README](../../../README.md#本地开发)，安装和启动命令由各工程维护：

| 工程 | 接手入口 |
|---|---|
| 后端 | [server README](../../../server/README.md)：配置加载、锁定安装、迁移、API／worker、隔离测试与产品运维 CLI |
| 网页 | [admin-web README](../../../admin-web/README.md)：锁定安装、API 类型、开发代理与构建 |
| 小程序 | [miniprogram README](../../../miniprogram/README.md)：API 类型、项目配置、环境地址与开发者工具 |

测试库独立，真实凭据只写受控配置；遵循现有锁文件，禁止使用生产资源执行本地自动化。

`local_demo`仅在本机演示使用假身份和假数据，不能作为外部联调、真机或生产验收。外部适配器配置缺失须明确失败，避免误用真实资源。worker入口及角色由[部署说明](../../../deploy/README.md)管理。

## 修改与检查

| 改动 | 同步资料／必要验证 |
|---|---|
| 业务／数量／权限 | 先确认定义及验收；同步阶段需求、CONTEXT、设计；以隔离MySQL验证事务、权限、并发、幂等及数量不变量 |
| 数据库 | Alembic迁移＋模型＋[数据字典](数据字典与关系图.md)；空库升级、存量承接、`alembic check`及数据保留边界 |
| HTTP接口 | 路由、OpenAPI、两客户端生成类型＋[接口说明](接口与外部集成说明.md)；按受影响调用链验证 |
| MCP／机器人 | 工具／回调契约、本人权限、文件安全、手册、离线与真实闭环验收分开 |
| 前端／小程序 | 读取对应原型及共用视觉规范；字段、按钮、跳转和样式按批准内容；更新对应手册 |
| 部署／配置 | 运维正文、环境示例、部署失败边界、恢复兼容性；真实服务器操作另行授权 |
| 发布 | 精确SHA与CI、Release、schema、运行和客户端证据写[发布记录](版本发布记录.md) |

按受影响工程 README 执行相称检查；接口变更同步 OpenAPI 和两客户端生成类型。远程完整 CI 还包含部署脚本、MySQL 迁移／漂移及两镜像构建，执行基线见[CI](../../../.github/workflows/ci.yml)。纯文档整理检查链接、路径、内容和空白；本地检查与远程 CI 分别留证据。

## 文档维护和导出

跨阶段交付资料集中在`docs/shared/delivery/`，4类操作手册与截图放`manuals/`；需求和设计保留阶段目录。变更写入对应现行章节，删除已失效规则，避免长期叠加覆盖说明。Issue台账留在GitHub，协作规则见[issue-tracker](../../agents/issue-tracker.md)。

Markdown为手册正文，截图使用相对`assets/`路径。已有图片保持原内容；涉及自动同步、箱贴、来货出入、Codex等缺少新截图的流程使用文字步骤，不能把历史截图当当前验收证据。既有工厂PDF为历史导出，须重新导出后再对外交付。

需要PDF时，用VS Code Markdown PDF及`manuals/pdf-style.css`，A4、四边15mm、关闭页眉页脚。核对字体、分页、表格、图片、链接和版本日期后记录导出版本。本轮没有重新生成或视觉核对PDF。

## 责任与访问交接

在正式签收时填写以下责任表；授权通过公司受控凭据渠道完成，禁止在正文粘贴秘密、资源ID或个人身份标识。

| 责任 | 要交接的内容 | 当前负责人 |
|---|---|---|
| 业务与验收 | 工厂资料、用户审核、数量口径、业务样例及签收结论 | 待填写 |
| 系统维护 | 仓库／Issue、开发工具、发布规则、文档、依赖与故障处理 | 待填写 |
| ECS／域名／数据库 | 受控登录方式、权限申请、schema、容量及值班联系方式 | 待填写 |
| OSS／备份 | RAM权限、备份位置、保留规则、最近恢复证据 | 待填写 |
| 飞书／聚水潭／模型 | 应用归属、管理员授权、回调及权限发布、Token维护、模型额度 | 待填写 |
| 微信 | AppID归属、开发者／体验者、合法域名、模板、发布版本 | 待填写 |
| MCP／Plugin | 客户端安装入口、版本与兼容范围、本人OAuth、文件能力 | 待填写 |

停用离职账号、转移应用维护权、轮换凭据须明确影响范围；身份密钥和文件签名密钥更换需评估既有数据和核对表兼容性，禁止直接覆盖。
