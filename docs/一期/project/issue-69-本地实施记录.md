## 实现

- 新增管理员 `GET /api/v1/admin/shipments/summary`：关键词、工厂、日期、排序、页码和每页条数均由后端处理，返回摘要行和总数。管理员鉴权、参数白名单及分页边界通过接口校验。
- 工厂和日期先缩小候选范围；装箱关联订单、产品名按原箱号与箱内明细顺序取首次出现，二进制去重避免误合并大小写或重音不同的名称。数量在单独摘要聚合中计算，数据库完整筛选、计数、排序后分页。
- 发货数量保持旧详情口径：收货确认前为原报箱数合计，确认后为确认箱数合计；不因为本次性能改动改成数量流水净额。原列表可见的作废、撤回和历史撤回申请中单继续可见；普通草稿、关联撤回编辑草稿和已删除单不进入列表。
- 默认日期/单号倒序；选定列使用数据库中文自然排序键，并保留旧接口 `submitted_at DESC, shipment_id` 的同值顺序。查询级设置避免完整摘要在默认 1024 字节或排序长度处截断，不修改连接池或全局配置。
- 独立 `GET /api/v1/admin/shipments/factory-options` 覆盖完整可见发货范围，前端沿用中文选项排序；不受分页、关键词或日期筛选影响。未使用工厂目录替代此范围。
- 页面只获取每页 10 条摘要，独立启动工厂选项请求，选项慢或失败不阻塞列表。合并同一次筛选事件的重复触发，忽略过期响应，越界返回有效页。保留表格、序号、列宽、样式、筛选和详情跳转。
- 旧全量详情 API、小程序、订单详情关联发货、装箱、凭证、日志及所有写流程均保留。没有新增迁移、索引或缓存。
