# Issue #70 本地实施记录

关联 [Issue #70](https://github.com/kocotree/order_tracking/issues/70)，属于 #66。用户授权四工作区并行，本地修改、必要测试和提交后停止；不运行 Playwright 或其他浏览器验收，不推送、建 PR、合并 main、部署或真实外发。

## 基线与实现

基线为最新 main `e0b81a4` 与已批准范围/设计记录 `ef81a3c`。独立分支 `codex/issue-70-repair-pagination`，独立本地 MySQL 测试库，不访问开发、共享测试或生产数据。

- 新增管理员网页专用 `GET /api/v1/admin/repairs/summary`：关键词、工厂名称多选、状态、退回日期、八列排序、计数与分页均在数据库执行；返回十个列表摘要字段，每页默认 10 条。原管理员及工厂列表、详情、草稿、发回、归档写流程保留。
- 新增 `GET /api/v1/admin/repairs/factory-options`：完整未归档返修范围，包含仍有关联返修的停用工厂；独立加载，沿原前端中文选项排序。
- 实施检查发现 `RepairOrder` 已在确认和发回事务中维护四个数量及状态，旧详情/列表正是直接读取这些头字段。因此采用现有权威头摘要，省去重复聚合明细；不存在质检行与发回行连接导致数量倍增的问题。多质检行、多批次、部分发回、报废及最终完成测试与未改动详情对照。
- 字符串排序复用 #71 的 `natural_sort_keys`，在 MySQL 全局生成中文数字排序键，再分页；同值保持原退回日期降序、返修单号降序。计数不计算排序键。查询级提示避免递归和长排序键默认上限，不修改数据库全局/会话配置；本切片无需新增表或迁移。
- 网页取消循环取完所有分页；列表与选项分别请求，列表返回即可显示。请求序号保护过期回复，筛选/排序变更批量重置页码且只发一次列表请求；归档后重新读取总数并回有效页。
