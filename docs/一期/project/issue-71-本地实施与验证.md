## 实现

- 新增管理员 `GET /api/v1/admin/factories/page`：关键词、合同完整性、接入状态全部在 SQL 筛选，全局计数和排序后取当前页。页面固定每页 10 条，旧全量接口及小程序选择工厂接口保留。
- 联系人搜索使用 EXISTS；工厂接入人数按启用的 factory 角色用户聚合，工厂资料完整性仍使用工厂代码、单位全称、地址和法定代表人。当前页联系人批量获取，不再逐厂查询人数/联系人。
- 新增管理员 `GET /api/v1/admin/factories/options` 与 `identityApi.listFactoryOptions()`，返回 ID、供应商编号、名称及总数。范围和顺序沿用原管理员全量工厂列表，包含停用工厂；不返回联系人和合同资料。#68 通过本地依赖提交使用此契约。
- 工厂页把筛选、排序、分页交给接口，保留原表格/弹窗/样式。筛选输入只有搜索后生效，旧请求不覆盖新结果，页码越界重新请求最后有效页，编辑保存后保持有效当前页。
- 中文数字排序使用 MySQL 递归 CTE 生成完整权重，数值列直接排序；字符串的主、次、三级权重分开，数段按长度/内容比较，前导零等价；全角等 Unicode 十进制数字先归一化。原供应商编号顺序仍为同值排序的次序。#69、#70 复用独立 helper 提交。
- 联系人排序按完整显示顺序拼接；SQL 语句局部提高 GROUP_CONCAT、排序比较长度、递归层数，未修改全局数据库设置。未新增缓存、业务字段、索引、迁移或运行依赖。
- 同步 OpenAPI 及两端生成类型；小程序运行逻辑未修改。
