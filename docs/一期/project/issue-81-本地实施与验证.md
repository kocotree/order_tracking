# Issue #81 本地实施与验证

2026-09-10，基于 main `50b747e`，分支 `codex/issue-81-factory-filter`。用户已确认需求、交互和本地执行，停止于本地提交。

## 实现

四页工厂菜单顶部增加名称包含搜索，独立保存候选搜索和选择；更换关键词保留选择，清空恢复原完整选项，无匹配提示明确。菜单搜索回车不提交业务表单。订单和发货勾选即查，待导入仍点击搜索，返修沿用响应式筛选；有效查询回第一页，重置清空菜单词和选择。返修菜单补齐既有公共样式需要的 `is-open` 类。

管理员发货摘要新增重复 `factories` 名称查询参数，SQL 在全局计数、排序、分页前以或关系精确匹配；原 `factory` 继续支持，同时传入则合并去重。参数绑定避免把名称拼接为 SQL；关键词、日期及权限继续使用原逻辑。原工厂选项接口和其他端发货接口不变，不需要迁移。同步 OpenAPI 和两端生成类型。

修改文件集中于四个 Vue 列表、公共菜单搜索样式、client 请求序列化、管理员 shipment API/list_query、对应测试和正式资料。

## 手工验收入口

用 `git worktree list` 找到 `codex/issue-81-factory-filter` 对应目录，在该目录启动。现有其他分支服务没有重启；当前已有地址不能视为本分支代码。

后端按现有本地环境启动方式提供本分支 API，使用独立的本地演示/开发配置，不要将回归测试库作为持久演示库，也不要加载生产配置。可用现有本地演示脚本：在 `server/` 执行 `uv run uvicorn scripts.repair_period_demo:create_demo_app --factory --host 127.0.0.1 --port 8081`；需先按 [Issue #76 本地演示配置](issue-76-本地验证与交接.md)设置已存在的隔离演示库及本地身份，不能直接照抄其数据初始化/迁移步骤。本次未启动此服务。

网页在 `admin-web/` 执行 `VITE_API_PROXY_TARGET=http://127.0.0.1:8081 pnpm dev --port 5181`（Node 24、pnpm 11.22.0）。分别打开 `/orders`、`/orders/import`、`/shipments`、`/repairs`。

1. 在有多个工厂的列表进入第二页，打开工厂菜单，输入部分名称；应只缩小候选，业务列表和页码保持。
2. 勾选甲工厂，换词找到乙工厂再勾选；清空词后两项仍选中。订单/发货/返修按原方式更新；待导入点击“搜索”才生效，生效后回第一页。
3. 加日期、状态或其他已有条件，检查命中甲或乙且满足其他条件；排序、跨页总数正确。选项中能找到当前页未出现的工厂。
4. 输入不存在的名称，检查空提示；点击“重置”，搜索词和选择都清空、恢复全部工厂。检查菜单可见、表格原有列宽和分页布局。
