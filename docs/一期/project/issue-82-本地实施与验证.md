# Issue #82 工厂三列表分页本地记录

基线 main `50b747e`，本分支 `codex/issue-82-factory-pagination`。用户2026-09-10确认方案并授权实现、必要测试及本地提交后停止。本轮不推送、创建PR、合并、部署或运行真实外发；Issue仍待后续发布及人工验收。

## 实现范围

- 工厂订单任务：全局权限、关键词、状态、日期和排序在SQL完成后计数分页，仅批量读取当前页本厂派工及数量流水。共享管理员查询增加可选工厂范围，保留所有既有排序、初始已发＋有效数量、合同出货日期及本厂逾期口径；他厂独有明细不能命中本厂关键词或分类。
- 工厂返修周期：复用现有分页接口，首次只取20条，按周期关键词及状态服务器筛选，不再串行等待全部页。
- 工厂发货记录：新增 `/api/v1/factory/shipment-page`，登录身份限定工厂，搜索订单编号/产品、日期过滤后计数分页。只返回卡片所需摘要，原详情与旧全量接口保留；总箱数及确认收货后的数量与详情对应，撤回/作废状态和原显示数量不变。按submittedAt降序、shipmentId稳定排序。搜索覆盖原型定义的全部产品名，同时兼容卡片缩写的字面搜索。
- 小程序两个页面共三列表：首屏即显示、触底追加、总数为全量匹配数；请求序号防旧响应覆盖，追加防重复在途请求并按ID去重，失败不递增页数且保留已显示卡片，可点击重试，末页停止。
- 普通详情返回沿用页面栈保留列表和滚动；正常/重新发货、撤回成功后订单及发货记录失效，返修提交成功后返修列表失效，下次显示加载第一页并回顶部。失效版本仅保存在当前小程序进程，不持久化业务缓存。

文件集中在 orders 的SQL分页/快照、shipments 的独立factory_query与API、小程序API及factory-tasks/factory-shipments、相关测试和生成类型。无数据库迁移、管理员页面功能或卡片重设计。

## 同数据性能对照

本机独立MySQL 8性能库，纯合成数据，不读生产或共享业务数据。FastAPI TestClient、同进程同条件，每场景先预热一次再测三次中位数；耗时包括身份校验、服务查询及JSON序列化，不包括真实网络和小程序渲染。SQL次数包含身份校验；响应体积为实际HTTP JSON字节数。

订单旧路径取自基线 `50b747e` 的 `OrderService.list_visible`，绑定到同一快照实现，与新API取相同第一页20条比较；发货旧全量详情入口与新20条摘要入口比较；返修模拟旧客户端每页100条串行取全与新20条单页。每组还逐字段比较相同首20条：订单完整响应；发货将旧详情投影为卡片；返修周期字段。8组均一致。

120返修周期仅为分页压力合成数据，不代表实际业务规模。单页返修本来已经SQL分页，20周期场景没有查询次数收益，耗时存在本机波动；收益是超过一页时不再等待全量响应。订单响应字段/大小不变，收益来自只组装当前页；发货通过分页与摘要同时减小处理及传输量。

本轮量测后的本地验收界限：订单首屏含鉴权最多9次SQL、发货最多5次，数量/明细增长不再逐单追加详情SQL；三列表首屏请求一页，固定数据全局搜索与跨页完整性不变。回归测试以服务层订单最多6次、发货最多2次断言对应界限。不把SQL次数固定解释为数据库成本恒定，也不承诺生产提速百分比。
