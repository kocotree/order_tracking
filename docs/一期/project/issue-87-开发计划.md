## 任务1：宽松导入与异常资料草稿

执行Issue：[#88](https://github.com/kocotree/order_tracking/issues/88)。

依赖：无执行Issue前置；以已确认需求、技术设计和原型为基线。

### 范围

- 来源解析保留缺失/错误原值，任一明细精确进度<95%或存在无法计算数量的明细时整单进入候选；全部数量正常且各行≥95%才按进度跳过。
- 创建来源明细存储及基础迁移，保存全部原始资料、稳定来源身份和人工日期；未知数量保持null。产品、工厂、账号、日期、数量、跟单资料问题不阻止导入。
- 管理员待导入/草稿详情支持宽松导入及只读展示；禁止旧整单保存/发布接口绕过新来源资料边界。不提前开放尚未完成的派工能力。
- 保留执行ID、账本和合同；迁移结构及历史映射在本任务设计并测试，第4项负责整体验证。

预计文件范围：server/app/adapters/order_source.py、order_import模块、db模型/迁移、orders查询与API；admin-web待导入及草稿详情、相关测试和生成类型。

### 验收

- [x] 94.99%、恰好95%、全部≥95%、同单超发与低进度混合、数量缺失/非法均按规则入选或跳过，入选包含全单全部明细。
- [x] 来源去重、重复确认及事务失败不创建重复或半份订单；缺稳定身份/无法确定订单归属明确失败。
- [x] 异常原文完整保留，未知不显示0；草稿工厂不可见；非日期字段不能通过旧API修改。
- [x] 隔离MySQL 8基础迁移、导入集成测试、网页组件测试及相关静态/类型/构建和OpenAPI一致性通过。

## 任务2：未派工来源更新与合同出货时间保存

执行Issue：[#89](https://github.com/kocotree/order_tracking/issues/89)。

依赖：依赖任务1完成并验证；基于其稳定detailId、可空资料和版本结构。

### 范围

- 按既有来源集合读取未派工最新资料；生成服务器端差异预览，确认后原子更新。取消、读取失败、来源缺行/变号不覆盖现有资料。
- 仅允许未派工合同出货时间自动保存；人工覆盖包括主动清空受保护，其他字段全部只读。来源日期减4天只执行一次。
- 实现版本/预览有效期/幂等、保存与刷新互斥、失败反馈与迟到响应隔离；为任务3提供派工前来源检查能力。
- 已派工资料不由飞书覆盖；不做来源新增/删除同步。

预计文件范围：来源适配器、order_import/orders服务与API、预览模型及迁移；admin-web订单详情/差异弹窗、测试及生成类型。

### 验收

- [ ] 实际差异先预览后确认，取消零业务写入；确认更新后再取消派工不撤销已确认更新。
- [ ] 日期保存失败不能当作已生效；清空可保存但不能派工；重复来源更新不重复减4天、不覆盖人工日期。
- [x] 双人更新、保存与刷新冲突、预览过期和来源变化有明确结果；只读字段的伪造请求被拒绝。
- [x] 后端隔离事务/接口测试、网页组件及相关类型构建通过，接口生成文件同步。

任务2的来源更新和日期保存已本地实现；前两项涉及派工的端到端条件留待 #90 接入后验收，当前继续拦截旧整单发布，不能据此开放派工。验证明细见[#89实施记录](issue-89-本地实施与验证.md)。

## 任务3：明细分批派工与工厂发货闭环

执行Issue：[#90](https://github.com/kocotree/order_tracking/issues/90)。

依赖：依赖任务1、2完成并验证；复用来源预览、日期保存和稳定明细身份。

### 范围

- 实现选择明细、来源检查、校验预览、整批确认事务和幂等；有问题整批不派，超发允许。同厂部分、跨厂分批均支持。
- 派工时建立执行关联并固定初始已发，移除阻止超发的数据库约束，支持同SKU/厂不同来源独立派工；首派离开草稿。
- 同时完成工厂列表/详情/统计/发货选单/保存/提交/撤回重提的有效派工权限，以及按批次工厂的派工通知outbox与消费者范围；不得留给任务4补权限。
- 网页订单明细按已批准原型实现进度、勾选、按钮、弹窗；仅本表改列宽，表头800、内容700、序号52px/左右8px。全部派工隐藏选择及两按钮。
- 实现基本逐明细数量、未发下限0及已交足行不进待发选单，同步网页/两类小程序接口类型。

预计文件范围：orders、shipments、notifications_audit服务/API、模型迁移、admin-web订单详情、miniprogram订单/发货相关消费、生成类型及测试。

### 验收

- [ ] A厂先派B厂后派、同厂部分先派、同SKU/同厂两来源分别派工，日期和初始量不丢失。
- [ ] 任一无效行导致整批零派工/零事件；事务回滚、双人竞争、同key重试/不同payload、停用竞态均受保护。
- [ ] 超发正常派工且不进入待发任务，账本与初始量不重复累计，其他明细欠量不能被抵扣。
- [ ] 工厂只能获取并提交本厂有效派工；未派工行/跨厂ID/失效ID不可越权；派工通知仅本批本厂、重试不重发。
- [ ] 核心MySQL事务TDD、发货权限回归及三端相关检查通过；正式网页与原型实际浏览器对照，视觉证据单独记录。

## 任务4：分批派工配套规则与整体回归

执行Issue：[#91](https://github.com/kocotree/order_tracking/issues/91)。

依赖：依赖任务1→2→3全部完成并验证；在统一集成基线上验收。

### 范围

- 完成管理员订单列表/首页/日期筛选及计数的整体口径：全部含草稿，未派阻止完成，逐行逾期，手动完成必须全派且逐条交足，保留恢复链路。
- 删除整单撤回，改为在订单内选择一个已派工工厂并撤回该厂全部有效派工；其他工厂不受影响，有有效系统发货时禁止，最后一个工厂撤回后订单回草稿。撤回保留当前值和历史、不主动刷新，再派走普通来源检查和差异确认。
- 有工厂已派即可导出该厂合同，取消整单全派及已发为零限制；保留法定合同资料、编号和首次快照，不建设同厂后派合同修订。
- 到期提醒仅有效已派且欠量行，原角色/节点不扩张；复核任务3的派工通知与权限闭环。
- 核对完整迁移映射和历史执行ID/初始量/账本/合同保留，验证切换与回滚前提；不建设用户说明不存在的历史已完成欠量兼容例外。
- 集成验收四项结果，完善发布与验证记录；本任务准备发布方案，不自动授权部署或真实通知。

预计文件范围：orders查询/生命周期、contracts、notifications_audit、shipments联动；三端状态消费、完整迁移与测试、数据/API/运维和验收文档。

### 验收

- [ ] 零派草稿、部分派工、缺日期、未派逾期、交足未派、逐条超发及人工完成/恢复均符合需求，SQL全量筛选计数后分页。
- [ ] 同厂部分派工可导出该厂已派合同；已发/初始超发不阻止，未派厂无合同；原编号/快照保持。
- [ ] 按工厂撤回只影响所选工厂；有有效系统发货时拒绝，最后一厂撤回后回草稿；重新派工、发货、收货差额、退回与重提数量一次生效，未派/失效任务不泄露、不发送提醒。
- [ ] 隔离MySQL迁移核对ID、关系、数量及合同不丢失；有新业务数据时不允许有损回滚。
- [ ] 完成受影响及整体回归、三端静态/类型/构建、OpenAPI、原型对照与迁移检查；分别记录本地、CI、小程序人工验收、部署及真实通知的完成/未完成状态。
