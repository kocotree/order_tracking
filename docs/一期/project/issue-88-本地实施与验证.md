## 实现结果

- 候选按每条明细的整数数量精确比较：任一明细低于 95%，或数量未知/非法，拉入整单全部明细；恰好 95% 不触发。缺稳定来源身份、无法确定订单归属仍拒绝，不猜测创建订单。
- 来源解析保留允许读取的原始业务字段；缺失、文本、布尔、非整数、无穷值及超出存储范围的数量归一化为 null，合法已发 0 保持 0。下单数量必须为正才可计算。异常下单日期不会中断整页读取。
- 新增 `order_details` 存储逐来源资料、原文快照、来源时间/哈希、匹配结果、人工日期覆盖和后续派工关联；`orders.detail_mode` 区分新来源草稿和旧执行模型。订单、候选汇总及 API 数量允许 null。
- 确认导入不要求资料完整，事务中保存整单全部来源明细，只创建草稿，不创建执行行、工厂派工或通知。重复确认返回同一订单；写入失败全部回滚。
- 日期覆盖按稳定来源明细保存，同 SKU/工厂的不同来源行保持独立。旧解析版本必须重新获取飞书订单后再导入，避免沿用旧版本推测出的 0。
- 新来源草稿在管理员详情只读展示，未知显示“—”，超发保留真实百分比且进度条不溢出；旧整单保存/发布 API 被服务端拦截，旧编辑入口转至详情。候选单条/批量导入不再因资料问题禁用。
- 管理员分页快照批量读取本页来源明细，避免逐订单额外查询。生成 OpenAPI 和两个客户端类型同步。
- 小程序仅修改共用数量格式化的 null 兼容、生成类型和开发预览数据，未修改页面布局、派工或发货流程。
