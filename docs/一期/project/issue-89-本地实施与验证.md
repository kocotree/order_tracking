## 实现

- 管理员网页提供“更新未派工明细”，依稳定来源记录集合读取；不扫描新增订单、不使用增量游标、不追加或删除明细。无可靠来源关联、来源缺失/重复、订单号或明细身份变化时拒绝覆盖。
- 服务端保存五分钟有效的预览，包括订单/明细版本、操作者、来源原文及 hash、匹配结果和差异。取消仅留下未消费的技术预览，不写订单、执行资料或业务审计；读取失败不创建预览。
- 确认前在数据库事务外再读同一来源集合；来源资料或匹配结果变化须重新预览。短事务按订单、明细 ID 顺序加锁，校验版本和未派工状态，只应用服务器保存的预览，原子更新资料、版本、审计和幂等结果。相同 key/相同请求返回原结果，不同请求冲突；MySQL 可重复读下使用当前锁定读取取得最新幂等结果。
- 仅未派工合同出货时间可人工修改，失焦保存。接口只接收日期、订单版本和明细版本，额外字段拒绝。主动清空同样记录人工覆盖；来源日期仅从原始来源日期减四个自然日，来源更新保护人工日期及清空值。
- 保存期间与刷新互斥；失败保留输入并提示重试，未保存日期阻止刷新。切换订单、离开页面或取消后不采用迟到的来源响应；确认重试保留同一幂等 key。
- 已派工明细不参与来源读取或写入；已开始执行订单的跟单人不随未派工刷新更换。执行 ID、数量账本、初始基线和合同均不被此服务修改，不创建通知。
- 来源匹配复用导入的产品/工厂匹配规则；未知数量保持 null，异常原文变化在差异弹窗可见。保存结果按原明细展示顺序返回，不把数据库锁定顺序用于页面序号。

新增路径位于 `/api/v1/admin/orders/{orderId}`：

| 路径 | 行为 |
|---|---|
| `PATCH /details/{detailId}/contract-date` | 保存可空日期及人工覆盖 |
| `POST /source-refresh/preview` | 生成差异预览 |
| `POST /source-refresh/confirm` | 校验并确认预览，要求 Idempotency-Key |

只使用 Web 管理员会话及 CSRF；未增加小程序编辑接口。OpenAPI、网页及小程序生成类型同步。
