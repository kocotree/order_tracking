## 实际变更

- 管理员订单列表和首页统一按来源明细／当前有效执行明细计算数量、日期、逾期、筛选及排序。未知数量保留空值，SQL 对完整集合筛选和计数后再分页；“全部”和首页包含草稿。首页搜索和排序也在完整集合上执行，再返回十条及真实匹配总数。
- 保留人工确认完成：全部来源明细有效派工且每条待发为零才允许完成；超发不抵扣别行欠量，未派工交足也不能完成。重新打开仍要求原因并记录日志。
- 删除 `POST /admin/orders/{orderId}/withdraw`、`OrderService.withdraw`、旧整单撤回事件分支和网页按钮；不保留兼容路径。发货单撤回是独立业务，保持原有链路。
- 新增 `GET /admin/orders/{orderId}/dispatch/factories` 和 `POST /admin/orders/{orderId}/dispatch/withdraw`（均带现有 `/api/v1` 前缀）。写入只接收 `factoryId`、`version`，要求网页管理员、CSRF 和幂等键；不同内容复用同键冲突。
- 撤回事务锁定订单、来源和派工；所选工厂已有有效系统发货时拒绝，否则使该厂全部有效 assignment 失效，来源恢复未派工。其他工厂及原 ID、账本、合同、历史保留；末厂撤回回草稿，其余保持已发布。不读取飞书。再派工复用来源检查、差异确认、版本和幂等流程，建立新的有效 assignment，历史基线不重复计入当前数量。
- 旧人工／历史订单首次按工厂撤回时接入来源明细展示，使用已有执行快照和可核验来源关联；无可靠来源的 legacy 行使用保留快照校验，不伪造飞书刷新。
- 订单详情按已确认弹窗实现单一工厂选择、禁用发货工厂及原因提示、影响说明、初始禁用确认、取消和确认撤回；无原因输入或二次确认。仅增加本页交互及字段样式，未修改其他页面列宽。
- 合同资格只要求所选工厂存在有效派工及原法定资料；不再以整单全派或已发数量拦截。首次合同只收录该厂当前有效派工；已有合同继续按首次编号、日期和快照重复导出，不追加后派明细、不创建修订流程。
- 到期扫描仅选有效派工且待发大于零的明细。外部投递前按原任务 ID 复核有效性、日期、欠量和当前接收权限；撤回、交足、换厂或失去跟单资格的任务跳过，管理员批量卡片剔除失效行。角色、节点和渠道不扩张。
- OpenAPI 和网页／小程序生成类型同步；旧暂时禁止来源订单完成/撤回及“有初始已发不能导合同”的断言更新为正式规则，删除与全局隔离夹具重复的局部清理夹具。

## 迁移与数据核对

新增 `20260911_0037`：将 assignment 的 `detail_id` 唯一索引改为普通索引，允许同来源保留撤回历史；单一有效关系由订单／来源行锁和来源当前 assignment 指针共同维护。历史草稿 assignment 标记 inactive，不改原分配量、初始已发或 ID。

隔离 MySQL 测试按原始表快照比较订单、执行行、assignment、数量账本、合同和 outbox，除草稿有效标记外保持；不查询当前飞书重算历史，不生成发货、合同或迁移通知。存在新派工或撤回记录时，0037 在修改结构前拒绝降级；0036／0034 的来源资料降级保护继续保留。

`alembic check` 未发现模型漂移。SQLAlchemy 对来源与 assignment 双向外键报告循环排序提示；实际迁移和集成测试单独验证这些关系，未将该提示作为外键验证通过的替代证据。

## 本地验证

- 定向 MySQL 测试覆盖全局分页、逐条完成、撤回回滚/并发/幂等、跨厂有效发货隔离、旧派工拒绝提交、合同快照、延迟通知权限、历史无来源再派及网页 API 权限。
- Ruff、MyPy（76 个应用文件）、OpenAPI 生成一致性和 Alembic 模型检查通过。
- 管理员网页：105 项测试通过（旧合同提示断言更新后仅重跑受影响的 17 项）；TypeScript、ESLint、Vite 构建通过。
- 小程序：100 项测试、TypeScript、ESLint、构建结构检查通过。
- 完整后端回归仅运行一次：430 通过、1 失败、1 跳过，耗时 715.86 秒。失败为旧收货测试在已发 35／订单 40 时人工完成，与新规则冲突；将该测试的订单／派工量设为 35，保留初始已发 5 与系统发货 30 后，原测试定向通过。跳过项为未配置隔离私有 OSS 测试桶。未将这次完整运行描述为全部通过，也未重复运行整套回归。
- 完整回归后补强“已保存发货草稿在派工撤回后提交”的事务测试，并定向通过；补齐首页全量搜索/排序/草稿范围后，25 条来源订单的分页、计数和首页 API 定向测试通过。再次运行 Ruff、MyPy、OpenAPI 一致性、网页首页 5 项测试及网页类型/Lint/构建、小程序生成类型和构建检查通过。
