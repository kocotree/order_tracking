# Issue #97 退役代码清理与本地验证

对应 [Issue #97](https://github.com/kocotree/order_tracking/issues/97)。用户于 2026-09-14 授权建票并实施，基线为 main `40262d0`（已核验同提交 main 完整 CI 成功），独立分支 `codex/issue-97-dead-code-cleanup`。

## 修改范围

- `server/app/modules/identity_access/service.py`：删除管理员申请验证码、提交、批准、拒绝四个退役写方法；保留 OAuth 自动授权、身份绑定、权限、历史读取和既有构造参数。
- `server/app/modules/shipments/service.py`：删除旧 `request_void`、`review_void`；保留现行自主撤回及历史数据读取、通知消费。
- `server/app/adapters/external.py`：删除全仓未引用的旧适配器文件。
- `server/app/modules/orders/dispatch.py`：继承来源更新服务构造函数，复用其哈希和快照适配器；不改变校验、锁、幂等和事务顺序。
- `miniprogram/modules/orders/format.ts`：删除未引用的规格汇总函数。
- `admin-web/package.json`、`pnpm-lock.yaml`：移除未使用的 element-plus 及其独占依赖；保留其他依赖版本。
- 身份、通知和来源更新三个后端集成测试文件：调整退役流程的造数与测试；没有修改页面、API、数据模型或迁移。

## 测试调整理由

删除仅验证旧管理员申请的三个测试：短信创建待审申请、旧短信错误次数限制、拒绝后重新申请历史。短信申请入口已退役，不再以保留测试为理由保留生产写方法。

原审批授权测试改为验证现行 OAuth 自动授权、普通管理员无权读取申请历史、最高管理员身份重入稳定；管理员启停/会话失效与微信绑定测试改用自动授权造数，原核心断言保留。历史待审/拒绝申请直接使用 ORM 创建，保留历史状态不能阻止微信登录的验证。

两处历史撤回通知测试通过同文件内的小型造数函数写入历史申请及 outbox，保留收件人范围、去重、卡片内容及消费后无剩余事件的断言；不再测试退役申请方法的重复提交行为。现行自主撤回的幂等与数量回归继续运行。

来源更新的既有降级保护测试会先成功从 0037 降到 0036，再因保护校验拒绝后续降级；原测试没有恢复 head，导致其后的重新派工测试被旧唯一索引阻止。本轮只增加 finally 恢复最新结构，保留原断言，不改变生产迁移。
