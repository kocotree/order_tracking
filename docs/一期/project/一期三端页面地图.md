# 跟单管理系统三端页面地图

核对：2026-09-30。本文维护现行页面入口和终端职责，覆盖一期及已实现二期增量；业务字段与验收以[一期需求](../requirements/一期需求文档.md)、[二期需求](../../二期/requirements/二期需求文档.md)及已批准专题为准。历史页面演变见[里程碑](一期里程碑与决策记录.md)和 Git 历史。

## 1. 终端职责

| 终端 | 一级入口 | 职责 |
|---|---|---|
| 管理员网页 | 订单看板、订单与发货、产品资料、工厂资料、人员管理；顶部通知 | 业务管理、数量核对、批量文件、导出及人员权限 |
| 管理员小程序 | 订单、发货、我的 | 移动只读查询、个人资料与通知 |
| 工厂小程序 | 任务、发货记录、我的 | 本厂任务、装箱发货、自主撤回与返修发回 |

两类小程序共用一个工程，按身份进入对应页面；工厂只能访问本厂数据。小程序均无独立工作台，底部导航不显示通知红点，未读数在“我的—通知中心”显示。

## 2. 管理员网页入口

路由依据：[router/index.ts](../../../admin-web/src/router/index.ts)。

| 入口 | 路由 | 页面与操作 |
|---|---|---|
| 登录／停用 | `/login`、`/access-status/disabled` | 飞书登录；最高管理员由服务端受控白名单识别 |
| 看板 | `/` | 待派工、今日发货、逾期及订单进度摘要，跳转对应列表 |
| 订单列表 | `/orders` | 订单关键词、分类、工厂、跟单人员及业务／派工状态筛选；日期按明细汇总展示，可排序并进入详情 |
| 手工草稿 | `/orders/new`、`/orders/:orderId/edit` | 已有手工建单与草稿编辑入口 |
| 订单详情 | `/orders/:orderId` | 多跟单人员、明细日期、数量与派工；未派工维护、来源更新预览确认、派工／按厂撤回、完成／重开、合同与箱贴、来货出入、关联发货及日志 |
| 发货列表 | `/shipments` | 筛选正常发货记录，查看收货状态，进入详情或下载同厂同日汇总 |
| 发货详情 | `/shipments/:shipmentId` | 箱内数量核对、保存草稿与整单确认收货、按单退回、清单导出、凭证与日志 |
| 返修周期 | `/repairs` | 按工厂＋半年周期汇总；全部返完后整周期归档 |
| 质检上传 | `/repairs/new` | 批量 `.xlsx` 解析、逐份校验和确认创建 |
| 返修详情 | `/repairs/:repairId` | 周期／原单资料、附件和返修进度；返回数量由工厂提交生效 |
| 产品 | `/products` | 聚水潭同步产品、七分类、规格和 SKU 图片，只读查询 |
| 工厂 | `/factories` | 列表、新增、编辑及合同资料；供应商编号编辑时只读 |
| 人员 | `/people/admin-users`、`/people/factory-applications`、`/people/users` | 最高管理员管理普通管理员启停；管理员审核并绑定工厂申请、管理工厂用户 |
| 通知 | `/notifications` | 本人通知与业务跳转 |

订单与发货下保留订单、发货、返修入口。旧待导入页面、获取新订单按钮和候选确认入口已退役；`/orders/import/*` 进入未找到页。后台每 20 分钟同步来源并创建／维护草稿，按同订单同工厂校验后自动派工，详情仍可手动维护和派工。

## 3. 管理员小程序入口

页面注册依据：[app.json](../../../miniprogram/app.json)。

| 一级入口 | 页面目录 | 内容与边界 |
|---|---|---|
| 身份 | `auth`、`status` | 微信身份与手机号绑定已有管理员；未匹配提示先完成网页飞书登录，停用拒绝访问 |
| 订单 | `admin-orders`、`admin-order-detail` | 搜索筛选、明细合同出货时间汇总、工厂进度和关联发货；业务只读 |
| 发货 | `admin-shipments`、`admin-shipment-detail` | 发货记录筛选及正常发货单详情；不提供收货或退回办理 |
| 返修进度 | `admin-shipments` 内页签、`admin-repair-detail` | 按工厂与周期查看进度、质检明细与发回记录；不上传质检或归档 |
| 我的／通知 | `profile`、`notifications` | 姓名、角色、脱敏电话、头像、微信提醒授权、全部／未读通知和退出 |

正常发货详情按订单和箱号折叠，展示凭证、备注和记录。管理员小程序不提供质检原件下载、复杂录入、派工、订单完成或 Excel 导出。

## 4. 工厂小程序入口

| 一级入口 | 页面目录 | 内容与边界 |
|---|---|---|
| 身份申请 | `auth`、`factory-apply`、`factory-status`、`status` | 微信登录、选择已有工厂并申请、待审核／拒绝／停用状态 |
| 任务—订单 | `factory-tasks`、`factory-task-detail` | 本厂有效派工、日期、进度、产品规格和来货出入只读折叠区；无差异记录隐藏整区 |
| 创建发货 | `factory-create-shipment` | 从任务入口进入，选择本厂订单规格、箱号、装箱数量、选填凭证／备注、预览并提交；支持多订单、混装、连续箱与尾箱 |
| 发货记录 | `factory-shipments`、`factory-shipment-detail` | 正常发货历史、装箱、凭证及合法自主撤回；撤回后从原单继续修改并同号重发 |
| 任务—返修 | `factory-tasks`、`factory-repair-detail`、`factory-repair-return` | 本厂周期任务、质检附件、历史记录；按规格填写返修／报废数量并预览提交，后台分配到原质检单 |
| 我的／通知 | `profile`、`notifications` | 姓名、职位、脱敏电话、所属工厂、提醒授权、通知及退出 |

工厂自主撤回须满足未确认收货、无有效退回等正式条件，符合条件立即冲销有效数量；重新提交沿用单号。按发货单退回增加原正常任务未发数量，工厂按普通发货流程补发。返修发回仅更新返修进度，报废实物仍须返回仓库。

## 5. 跨端流程

1. **订单：** 飞书来源 → 后台同步草稿／未派工资料 → 自动或手动按厂派工 → 工厂可见任务；已派工资料和人工覆盖受保护，人工撤回暂停自动派工。
2. **正常发货：** 工厂装箱提交 → 立即记入有效已发 → 管理员逐箱核对并确认收货 → 差额一次入账；订单完成由管理员网页办理。
3. **退回与补发：** 管理员发货详情选择规格、数量及原因 → 扣减有效已发并留日志 → 工厂通过原任务普通补发。
4. **质检返修：** 网页批量上传并确认 → 本厂周期任务 → 分批返修／报废发回 → 返完自动完成 → 管理员整周期归档后三端隐藏。
5. **来货出入：** 飞书机器人收图 → Excel 核对与明确确认 → 对应明细台账 → 网页查看／调整、工厂详情只读查看；无独立一级菜单。
6. **合同与箱贴：** 网页订单详情按订单＋工厂导出，私有文件与首次快照受控；小程序不增加导出入口。

## 6. 公共交互与扩展边界

- 已启用账号登录后请求角色对应微信原生订阅授权，允许、拒绝或关闭均继续登录；“我的”可再次请求。管理员合同出货外部提醒使用飞书。
- 通知中心提供全部／未读与触底分页，进入对象并按规则标记已读；不提供删除、批量已读或自建订阅设置页。
- 管理员头像更换仅影响小程序；退出清除会话并保留身份绑定。Web／Codex 共同授权按对应技术设计执行。
- 颜色、尺寸、表格与布局按[网页表格规范](../../shared/管理员网页端表格视觉规范.md)、[小程序复刻规范](../../shared/小程序原型复刻规范.md)及已确认原型执行，本文不复制像素参数。
- `dev-preview` 是开发辅助页；周出货回填、月账单、工厂分析、库存预警尚无已批准正式页面。Codex 与机器人入口见各自手册。
