## 4. 已实施定向补拉技术方案

### 4.1 查询与预览

1. 扩展现有运维脚本，增加定向模式、商品名称或款号参数；默认只读预览，显式提交参数才写库，输出目标环境及实际匹配款号。
2. 名称使用 exactly_name；零匹配返回未找到，多款同名返回候选并要求指定款号。模糊查询只辅助选款，不直接写入。已有款号时按 i_ids 查询并复核来源名称及分类。
3. 读取所有匹配分页，按 sku_id 去重；核对来源身份、时间、规格、七分类及 enabled。异常、冲突或同名多款未消歧时不发布；停用/范围外项在预览中明确报告，不能作为可用商品插入。
4. 预览目标库中的新增、已有、拟更新、拒绝及旧来源忽略记录。执行时重新获取并校验，重新核对数据库；来源或匹配范围发生变化时返回稳定错误，须重新运行预览，不套用旧的35条预期直接写入。

### 4.2 事务与复用边界

- 复用商品适配器的鉴权、限频、分页解析和 ProductSyncService 的已有模型/图片任务。以同一 SKU 为唯一写入依据，已有 SKU 不重复新增。
- 最小实现由内部运维命令同步执行，暂不新增定向后台任务类型或管理页面。沿用同步批次互斥机制防止与全量/增量并发覆盖；实际字段与实现接缝在编码前核对。
- 同批选定SKU读取校验完成后，在一个事务内写入款式、规格、审计及图片任务；失败整批回滚，重试重新定向读取。首次/增量原有持久暂存与续跑保留，不为少量定向数据另建暂存表。
- 定向结果不进入“全库成功游标”的选择范围；若复用 product_sync_runs，必须让游标查询只选 initial/incremental 成功记录，并用测试覆盖无历史全量批次的生产库。
- `_upsert_available` 是内部帮助函数，不是运维入口：它假设调用者已判断可用性。服务边界完成范围/启用/时间/冲突校验；共享更新函数同时校验SKU归属，避免旧来源覆盖较新规格/款式资料及同时间规格冲突，不可绕过服务私有函数插库。
- 新商品可复用图片缓存及待导入候选重校验；显式区分重校验内部任务与真实通知，补资料不派工、不发业务通知。
- 将所需运维模块打包进镜像，不打包与本任务无关的演示脚本；定向查询通过真实聚水潭来源完成，不使用 FakeJstProductSource 作为生产运维通道。

### 4.3 现有数据调整

分类不是独立的“帽子／服装资料表”，不要删除业务行或source_category字段。待导入汇总从本地明细重算；独立的受控一次性命令预览差异，仅更新派生分类汇总，并按版本及锁防止覆盖同时发生的导入/修改。无明细或无法还原的值报告异常；禁止从“帽子”猜测成童帽春夏等具体类别。

重算范围包含仍供列表查看的待处理及已导入候选，保留状态、日期人工覆盖、数量、关联订单和审计。正式订单已有明细分类及合同历史快照不跟随当前商品分类重写。预计无需 schema 迁移，是否确有必要以最终设计核对为准。
