## 正式实现及删除清单

- 后端：`shipments/service.py` 将原确认的有效差额、目标行、审计及完成恢复迁入连续保存；首次提交／重提自动快照，撤回冲销最新有效数量并保留首次7天期限。`db/models.py` 及迁移 `20261010_0053` 增加首次提交时间、允许系统保存人为空。
- 删除 `POST /admin/shipments/{id}/receipt/confirm`、`ReceiptConfirm`、service `confirm_receipt`；删除MCP `save_receipt`／`confirm_receipt`及专用输入类型。PUT保存必需幂等键，GET快照及合法规格选项继续使用。
- 删除网页订单关联表格及其单号／详情跳转、状态、请求、类型、专用样式和测试数据；删除 `GET /admin/orders/{id}/shipments`、专用响应模型及服务／查询投影。共享 `order_shipment_ids`、列表 `orderId`筛选、订单数量及小程序关联入口保留。
- 两客户端删除人工确认调用；网页支持连续保存、固定键重试、冲突保留输入和退回只读；小程序删除确认时间等专用展示，工厂撤回使用服务器 `canWithdraw`。OpenAPI及两端类型通过生成命令同步。
- 删除旧收货通知生成和专用发送逻辑；保留旧业务事件及关联投递的终结保护，防止历史重试补发。新装箱修改通知保存每次不可变差异；同值保存不产生业务副作用。
- 删除失去调用方的 `admin-web/scripts/shipment-receipt-fixture.mjs` 和 `verify-shipment-receipt-edge.mjs`。有效原报、草稿、历史审计、收货快照、退回与数量台账继续承担业务职责。
- 新增 `server/scripts/convert_auto_receipts.py`，默认只读；schema就绪并提供最新报告digest才可写入。真实未生效草稿、首次时间缺证／冲突／未来值、预检后数据变化均阻止执行；转换事务保护原报、台账、订单、退回和阶段事实不变。
