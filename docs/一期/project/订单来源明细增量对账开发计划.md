# 订单来源明细增量对账开发计划

> 执行使用 superpowers:executing-plans，逐项实施并验证。

目标是修复已导入订单新增明细及工厂拆分的遗漏。方案依据为[技术设计](订单来源明细增量对账设计.md)，对应 Issue #260。技术栈沿用 Python 3.13、SQLAlchemy、FastAPI、MySQL 8、现有 worker 和锁文件。

全局约束为只读飞书来源、保护人工覆盖及历史执行事实、完整订单事务和既有20分钟任务。已有发货仅在用户确认的工厂保留、采购唯一、数量可承接及总量守恒条件下自动调整。客户端与数据库结构沿用现有契约。

审查重点为旧运行任务恢复、来源集合并发变化、同 SKU 同厂重复采购身份、拆分后发货及冻结回填映射，以及对账提交后派工失败的恢复。
