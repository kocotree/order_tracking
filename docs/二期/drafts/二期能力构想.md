## 共用边界

- MySQL 8.0 保存正式业务事实，OSS 保存受控凭证；Base 回填仅限未来批准的输出列，不改变现行订单来源只读约束。
- 收货差额与包装阶段来货出入分别保留业务证据；同一事实不得重复计算。质检返修未关联正常订单批次，缺少分母时不能计算真实批次次品率。
- 初始已发数量缺乏逐笔发货日期，不能拆成历史周出货。实际到货日期不能由收货确认时间替代。
- 月账单仅汇总数量，不新增单价、金额、费用、税费或付款能力；已有核定账单及图片、公式保持原状。
- 候选方案须完成需求、交互、技术设计与开发计划确认；真实数据写入和外发按具体任务授权执行。

## 周出货回填

### 已核验的来源结构

2026-09-08 只读核对“生产部--下单表以及成品进度表-外协填写”的字段结构：共 91 个字段，其中 33 个期间出货数字字段；当时未读取业务记录或写入。字段结构会变化，实施前重新核验。

| 字段 | 用途与限制 |
|---|---|
| 订单编号、工厂、商品名称、产品颜色&规格 | 定位来源订单明细，名称不能代替唯一关联 |
| 产品编码及其查找引用、下单颜色编号、款号 | 先核对与系统 SKU 的对应关系，查找引用不写入 |
| 下单明细ID | 自动编号，真实记录标识与导入来源关联需核实 |
| `26.9.1-9.6出货` 等期间列 | 目标可写数字列，按明确日期区间映射 |
| 出货总数、未出数量、出货进度 | 公式列，只读；回填期间列会间接影响其结果和看板提醒 |

历史期间列包含按月拆周、两周合并及一周拆段。不能按统一周序号推断，须校验区间重叠、缺口及新列维护责任。

### 回填与接管

粒度固定为“期间 × 来源订单明细行”，不输出每周 × 工厂 × SKU 汇总；同厂同 SKU 跨订单分别计算。已有来源关联必须唯一，缺失或多匹配时不写入。

已确认覆盖回填、初始基线排除及接管边界见[建设计划](../project/二期需求建设计划.md#周出货回填的已确认规则)。仍需确定：

1. 发货、确认、退回、作废及跨周更正的归期与数量口径；返修是否独立统计。
2. 首个接管期间及订单行、人工值保护、冲突处理与新增期间列维护。
3. 预览、批准、写入、回读的证据及失败重试方式。

候选同步按行与期间重算目标值，保存上次写入值、输出版本、来源范围与结果。人工更改、匹配异常、缺列或期间缺口须报告，未知值不写成 0，不自动清空历史列。资源标识仅存受控配置；输出列与来源输入字段分开，避免再次作为初始已发基线读入。

## 月账单数量汇总

### 已读样例

2026-09-08 核对“锦诚 26.8已核普票.xlsx”的 Sheet1，源文件未改写：

- A1:H1 为日期、名称、规格、数量、单价、总金额、采购单号、入库单号；I 列含凭证图片。
- 86–112 行为来货出入，含正负数、未知单号及多个入库单号；113–274 行为次品退回负数量。
- B280:H286 按产品汇总发货、来货出入、退货、总数量、单价和总金额；样例总数量为前三项相加。
- 287 行后的跨月印花费、货款及税费仅作样例背景，不纳入数量功能。

候选输出保留 SKU 明细并按产品汇总，生成独立文件；不覆盖已核账单的合并单元格、DISPIMG 图片或金额公式。

| 数量分项 | 待确认来源及处理 |
|---|---|
| 正常来货 | 系统发货或聚水潭实际入库；两者的单据与发生时间分别核实 |
| 来货出入 | 复用已确认正式记录；基数已包含差异时不重复加减 |
| 质检退回 | 仓库退回事实、结算月份及哪些退回计入扣账 |
| 客退 | 来源和区分规则；样例中的次品退回不能全部归为客退 |
| 返修发回／报废 | 是否参与结算、方向和避免二次扣减的规则 |

每行保留工厂、月份、SKU、正负数量、来源单据与凭证。先确认基数和调整项互不重复，再定义合计公式；跨月补登、更正、关账后的处理须明确账期。

## 工厂履约与质量分析

月度复盘为主，日／周补充严重延期与异常。下表均为候选口径：

| 指标 | 候选计算与必要数据 |
|---|---|
| 数量及时率 | 合同截止时点有效发货数量 ÷ 应发数量 |
| 整单及时率 | 截止前全部发完订单数 ÷ 当期到期订单数 |
| 来货差异率 | 多货和少货绝对数量 ÷ 同口径验收实收数量 |
| 次品率／报废率 | 质检次品 ÷ 同口径质检实收；报废 ÷ 次品 |
| 返修完成周期 | 明确的完成时间减仓库退回时间 |
| 重复问题 | 同工厂、商品／规格与次品原因的重复出现 |

先补齐批次关系、完整分母与事件时间；缺失时显示不可计算，不能填 0。及时率依据截止时点历史事实，不能用今天调整后的数量倒推。

后端按确认公式生成不可变日／月快照及异常；AI 依据结构化指标和证据起草解释与建议，由管理员确认报告。保留公式、快照、模型和提示词版本。候选页面为经营概览、工厂分析与 AI 月报，支持趋势、证据下钻和导出；默认只读，不自动评罚工厂或发送通知。

## 库存风险与催货建议

每日分析目标 SKU 和采购单；候选预测窗口为 7／14／30 天，结合库存、销售速度、订单需求、采购进度、计划交期和实际入库。

| 数据 | 候选用途与约束 |
|---|---|
| 库存明细 | 按 SKU 对 `qty` 去重汇总；缺失数量不视为 0 |
| 销售订单 | 受控窗口内销售速度、季节性和订单需求 |
| 采购单 | 采购数、入库数、退货数、剩余数、计划交期与供应商；先核对各字段语义 |
| 采购入库 | 按 `io_id` 去重；实际入库时间查询使用 `date_type=2`，实施前验证接口字段 |
| SKU／款式资料 | SKU 连接业务事实，款号用于款式汇总 |

库存、锁定量、订单占用和仓库待发分开；可用库存公式必须单独确认。固定时点保存查询范围、页数、数量与字段覆盖及每日快照，计算需求、覆盖天数、缺货日期、在途覆盖和交期风险；通过历史回测及人工复核评估误报、漏报。

候选页面为库存预警、每日分析、采购／催货证据。每条风险保留 SKU、款号、规格、原始量、预测、采购与入库证据、触发规则、与前日差异、建议动作及公式版本；日报重点展示新增、变化和解除的风险。

AI 仅解释已计算结果和起草建议。自动深查、待办草稿和次日跟踪须另行定义需求；创建待办或外发消息须明确授权。对聚水潭保持只读。
