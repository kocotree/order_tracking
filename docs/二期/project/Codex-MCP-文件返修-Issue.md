# 二期：MCP Excel 文件与质检返修

对应 [#155](https://github.com/kocotree/order_tracking/issues/155)。

依赖 [基础接入 #151](https://github.com/kocotree/order_tracking/issues/151)，配合 [Plugin #152](https://github.com/kocotree/order_tracking/issues/152) 尽早验证真实 Codex 文件通路；为合同和发货导出提供共用交付能力。本轮仅建票。

## 范围

- [ ] 实测目标 Codex 本地引用/拖入附件到远程 MCP 的上传与下载，记录版本及契约；不把未经验证的原生参数视为已可用。
- [ ] 标准 `.xlsx` 上传，复用 parser、预览和私有存储；每批最多 20 份、每份 20 MiB、一文件一工厂，按内容验证格式。
- [ ] 文件来源 HTTPS/主机限制、地址及跳转校验、SSRF 防护、流式大小/超时限制，不外传凭据或记录临时 URL。
- [ ] 质检校验/预览/确认创建、返修周期列表/详情/归档、原件下载，与 Web 工厂任务和通知链路一致。
- [ ] 批量默认全部预检失败即停止，明确允许部分执行才处理合格项；逐文件报告中断结果，原幂等键恢复。
- [ ] 受权下载、登录恢复及 Codex 本地接收，供合同和发货工具复用；不提供公开永久附件链接。

## 验收

- [ ] 标准、损坏、伪造扩展名、非 xlsx、超限、供应商匹配失败、重复、预览过期及归档限制均覆盖。
- [ ] 部分失败、重试和并发不产生重复事实，逐文件状态准确。
- [ ] 真实 Codex 上传→预览→创建→下载完成，大小/哈希完整；周期和工厂可见任务与 Web 一致，不能用回网页上传替代完成。
- [ ] 越权、失效链接、内部地址及越界跳转拒绝；安全测试、隔离 MySQL 回归、静态检查及 PR/main CI 通过。

## 依据与边界

遵守 [AGENTS.md](https://github.com/kocotree/order_tracking/blob/main/AGENTS.md)；本地 `docs/二期/project/` 下 Codex 能力对照、技术设计和开发计划尚未提交推送，实施前验收并固化正式需求。文件机制不兼容须修订设计并实测，不删减上传目标。不支持 OCR。任务生成、通知发出和工厂实际查看分开记录；真实通知、部署及生产操作按现有确认门执行。
