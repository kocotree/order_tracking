# 二期 Codex 管理员能力对照与验收草案

> 更新：2026-09-30。本文维护管理员 Web 与 Codex 的覆盖目标和验收标准；已注册工具及覆盖差异见[接口说明](../../shared/delivery/接口与外部集成说明.md)，实际结果使用[全系统验收记录](../../shared/delivery/验收记录.md)。目标覆盖不代表全部业务已验收。

本业务线使用独立[技术设计](Codex管理员接入技术设计.md)和[开发计划](Codex管理员接入开发计划.md)，按五项 MCP 和一项 Plugin 组织；复用飞书网页登录，无额外授权确认页或客户端管理页。

## 已确认目标与执行规则

- 所有已启用管理员均可使用 Codex，以本人身份授权。普通管理员和最高管理员分别沿用网页权限；最高管理员专属的管理员启停能力仍只对最高管理员开放。
- Web 与 Plugin 共享同一账号的共同授权、最近活动时间和有效期。首次连接打开浏览器，公司受信任 Codex 客户端复用有效网页登录身份自动绑定；未登录走现有飞书登录后继续。任一端有效业务使用更新共同活动时间，连续 30 天无活动失效。共同授权过期、账号停用或统一退出/撤销时，两端一起失效；两端分别持有短期访问凭据。
- Codex 应能完成当前管理员网页的全部业务操作，并看到相同业务数据、校验结果与提交结果。用户授权具体目标和修改内容后可连续执行；遇到额外数量变化、覆盖已有值或对象归属歧义，应先展示差异取得确认。
- 整批操作提交前发现任一不合格项时，默认停止整批并报告原因；用户明确允许部分执行时才处理合格项。执行中断后报告已完成与未完成对象，不推断整批成功。
- 唯一匹配使用系统稳定标识；多个候选交由用户选择。工厂名称相似只作线索。合同出货时间来自用户本次输入、附件或明确指定的可靠来源；缺乏依据时询问。
- 业务文件上传仅支持现有 `.xlsx`；本次只验收 Codex。网页已有产品图片与发货凭证的查看能力保留，通过受权链接访问；不增加图片、PDF、截图识别。

## 接入设计与覆盖核验

1. **身份与授权。** Web 会话和 MCP grant 共用账号授权，凭据分别保管；核验共同续期、停用与统一退出，旧凭据不得因重新登录复活。
2. **MCP 接入。** 工具复用同一业务服务与数据库；核对版本、幂等键、错误和审计，超时先按业务 ID 或原幂等键查结果；箱贴和来货出入专用工具缺口继续保留为待补项。
3. **文件交付。** 原生文件参数、服务器读取上限及实际客户端支持须专项联调；Agent 下载使用本人 OAuth 权限并核对字节和摘要。用户机器路径不能直接交给服务器读取，未验证的文件能力不标记已支持。
4. **发货统计口径。** 当前发货单列表的 `summary` 查询包含非草稿的历史状态；同厂同日汇总导出仅取有效的 `SHIPPED` 原始单。对话查询复用相应页面或下载入口的口径并注明来源。提问仅说“发了多少”而两种口径会产生不同结果时，按已确认的歧义处理规则询问；不新增默认统计口径。日汇总结构化投影与网页日汇总使用同一查询。
5. **Plugin 与 Skill。** 独立的小 Plugin 仓库只分发 MCP 连接和业务 Skill，不复制服务器业务代码。Skill 记录对象定位、来源更新与派工顺序、发货统计口径、收货和返修边界、确认条件、错误恢复和回读规则。后端始终执行权限与数据约束。

## 验收标准

- 使用普通管理员、最高管理员及已停用账号分别在 Web 与 Codex 验证同一对象的可见范围和操作权限；普通管理员无法启停其他管理员，停用账号无法继续调用 MCP。
- 验证只使用 Web、只使用 Plugin 均可维持共同授权；两端均无有效活动 30 天后同时失效；任一入口统一退出后两端旧凭据均拒绝，重新登录不恢复旧授权。清除本地凭据时需要恢复身份或重新连接，不能凭账号名称自动登录。
- 对上表每个网页业务动作，至少验证一个正常路径；写操作同时覆盖版本冲突或业务校验失败。Web 与 Codex 操作同一测试数据时，最终状态、数量、附件、通知和审计归属一致。
- 使用隔离测试数据复现“补合同日期后全部派工”“工厂名称或采购来源变化后先更新未派工明细再派工”“按厂查询今天的有效发货与明细”“网页装箱修改保存后通过MCP读取有效结果”“上传 `.xlsx` 创建质检返修任务”。预览存在未解决项时不提交；提交后按对象 ID 回读。
- 验证整批预检失败、用户明确允许部分处理、提交途中超时与重试、重复提交、多人并发修改、下载无权限附件。报告每个对象的实际完成状态，不把调用成功等同于业务完成或工厂已查看通知。
- 生产能力仅在对应代码通过 PR 完整 CI、合并后 `main` CI、发布与实际业务验收后才宣称可供所有管理员使用。

## 维护方式

新增或退役 Web 操作时，同步本表、工具契约、技术设计及对应验收项；真实客户端、Plugin 分发和业务结果统一记入交付资料。本文不保存临时建票、未提交或部署停止点。
