## 已确认目标与执行规则

- 所有已启用管理员均可使用 Codex，以本人身份授权。普通管理员和最高管理员分别沿用网页权限；最高管理员专属的管理员启停能力仍只对最高管理员开放。
- Web 与 Plugin 共享同一账号的共同授权、最近活动时间和有效期。首次连接打开浏览器，公司受信任 Codex 客户端复用有效网页登录身份自动绑定；未登录走现有飞书登录后继续。任一端有效业务使用更新共同活动时间，连续 30 天无活动失效。共同授权过期、账号停用或统一退出/撤销时，两端一起失效；两端分别持有短期访问凭据。
- Codex 应能完成当前管理员网页的全部业务操作，并看到相同业务数据、校验结果与提交结果。用户授权具体目标和修改内容后可连续执行；遇到额外数量变化、覆盖已有值或对象归属歧义，应先展示差异取得确认。
- 整批操作提交前发现任一不合格项时，默认停止整批并报告原因；用户明确允许部分执行时才处理合格项。执行中断后报告已完成与未完成对象，不推断整批成功。
- 唯一匹配使用系统稳定标识；多个候选交由用户选择。工厂名称相似只作线索。合同出货时间来自用户本次输入、附件或明确指定的可靠来源；缺乏依据时询问。
- 业务文件上传仅支持现有 `.xlsx`；本次只验收 Codex。网页已有产品图片与发货凭证的查看能力保留，通过受权链接访问；不增加图片、PDF、截图识别。

## 管理员网页与 Agent 能力对应表

表中“现有接口”仅说明当前本地后端已提供业务入口；所有行都尚未提供 Codex 可用的 MCP 工具和 Agent 授权。操作颗粒度可按业务合并，最终仍需覆盖每个网页动作。页面依据 `admin-web/src/router/index.ts`、`admin-web/src/api/client.ts`；接口以 `server/openapi/openapi.json` 和 `server/app/api/` 为准。

| 网页范围 | 应能通过对话完成的动作 | 现有业务入口 | 接入时须核对的结果 |
| --- | --- | --- | --- |
| 登录、我的账号 | 首次绑定、查看当前身份、统一退出或撤销共同授权 | 飞书网页登录、`GET /me`、`POST /auth/logout`；需扩展共同授权校验 | 任一端使用共同续期；统一退出、共同授权过期或账号停用使同账号 Web/Plugin 一起失效；普通与最高管理员权限一致 |
| 订单看板 | 查询待导入、今日发货记录、逾期和最近订单；按关键词定位 | `GET /admin/dashboard/orders`、订单查询 | 看板指标与当前网页同口径；返回可继续定位的订单 ID |
| 待导入订单列表 | 获取飞书新订单并查询运行结果；筛选、排序、分页、查看候选；批量导入、排除候选 | `/admin/import-runs`、`/admin/import-candidates` | 获取不等于导入；排除后不再获取的影响要说清；批量逐单报告 |

| 订单列表与草稿 | 搜索、筛选、排序、分页；手工建草稿、编辑草稿、删除草稿 | `GET /orders`、`POST /admin/orders`、`PUT/DELETE /admin/orders/{id}` | 精确定位订单编号；删除范围与网页一致；保留版本和操作记录 |
| 订单详情与派工 | 查看明细、发货关联和审计；维护未派工字段、数量与日期；预览及确认来源更新；预览及确认选中明细派工；历史草稿发布入口 | `/orders/{id}`、`/admin/orders/{id}/details*`、`/source-refresh/*`、`/dispatch/*`、`/publish` | 来源更新预览确认后才写入；派工使用已保存值；全部派工必须逐条核验，不能静默跳过 |
| 订单后续操作 | 查询可撤回工厂、按工厂撤回派工、确认完成、撤销完成并填写原因、删除符合条件的订单 | `/dispatch/factories`、`/dispatch/withdraw`、`/complete`、`/reopen`、`DELETE /admin/orders/{id}` | 资格、数量、状态和原有通知/审计完全一致；完成前回读条件 |

| 人员管理 | 查申请、审核通过并绑定工厂或拒绝；查工厂用户并启停；最高管理员查其他管理员并启停 | `/admin/factory-applications*`、`/admin/users*` | 精确匹配申请人与工厂；操作后回读状态；最高管理员边界由后端验证 |

网页的搜索、分页、弹窗和下载属于以上业务动作的展示形式。Agent 返回结构化结果与可追溯的业务 ID，支持继续操作和核验。网页登录本身作为授权流程实现，无需伪装成普通业务工具。

## 当前缺口与最小实施边界

1. **身份与授权。** 现有管理员写路由主要使用网页 Cookie 与 CSRF，`IdentityAccessService.authenticate_session` 按 `terminal="web"` 或 `"mini"` 识别会话。新增同账号 Web/Plugin 共同授权记录，网页会话和 MCP grant 均绑定该记录；共同有效期与活动时间作为续期依据。统一退出/撤销原子失效共同授权，旧凭据不能因重新登录复活。继续把本人 `user_id` 传入业务服务，不分发网页 Cookie 或服务器密钥。
2. **MCP 接入。** 在现有后端仓库部署远程 MCP 入口，工具复用同一业务服务与数据库；按上表提供可发现的查询、预览、提交、文件工具。保留版本、幂等键、错误码和审计信息；提交超时先按业务 ID 或幂等键查结果。MCP 与 API 的路由部署方式、SDK 和认证细节进入技术设计核定。
3. **文件交付。** Web 浏览器当前可用 `File` 上传及文件流下载。技术设计提出使用原生文件参数接收客户端文件引用，复用标准 Excel 解析；Codex 私有 MCP 的实际支持和大小上限须完成专项联调。下载复用登录鉴权的直达文件链接。不能把用户机器路径交给服务器假定可读，不能把尚未通过联调的方案描述为已支持。
4. **发货统计口径。** 当前发货单列表的 `summary` 查询包含非草稿的历史状态；同厂同日汇总导出仅取有效的 `SHIPPED`/`VOID_PENDING` 原始单。对话查询复用相应页面或下载入口的口径并注明来源。提问仅说“发了多少”而两种口径会产生不同结果时，按已确认的歧义处理规则询问；不新增默认统计口径。日汇总结构化投影与网页日汇总使用同一查询。
5. **Plugin 与 Skill。** 独立的小 Plugin 仓库只分发 MCP 连接和业务 Skill，不复制服务器业务代码。Skill 记录对象定位、来源更新与派工顺序、发货统计口径、收货和返修边界、确认条件、错误恢复和回读规则。后端始终执行权限与数据约束。

## 验收标准

- 使用普通管理员、最高管理员及已停用账号分别在 Web 与 Codex 验证同一对象的可见范围和操作权限；普通管理员无法启停其他管理员，停用账号无法继续调用 MCP。
- 验证只使用 Web、只使用 Plugin 均可维持共同授权；两端均无有效活动 30 天后同时失效；任一入口统一退出后两端旧凭据均拒绝，重新登录不恢复旧授权。清除本地凭据时需要恢复身份或重新连接，不能凭账号名称自动登录。
- 对上表每个网页业务动作，至少验证一个正常路径；写操作同时覆盖版本冲突或业务校验失败。Web 与 Codex 操作同一测试数据时，最终状态、数量、附件、通知和审计归属一致。
- 使用隔离测试数据复现“补合同日期后全部派工”“工厂名称或采购来源变化后先更新未派工明细再派工”“按厂查询今天的有效发货与明细”“逐箱调整后保存并确认收货”“上传 `.xlsx` 创建质检返修任务”。预览存在未解决项时不提交；提交后按对象 ID 回读。
- 验证整批预检失败、用户明确允许部分处理、提交途中超时与重试、重复提交、多人并发修改、下载无权限附件。报告每个对象的实际完成状态，不把调用成功等同于业务完成或工厂已查看通知。
- 生产能力仅在对应代码通过 PR 完整 CI、合并后 `main` CI、发布与实际业务验收后才宣称可供所有管理员使用。
