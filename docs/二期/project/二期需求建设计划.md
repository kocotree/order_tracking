## 已确认的实施边界

- 来货出入复用数量台账，采购子单必须唯一关联系统订单明细与 SKU，发货单可空；识别结果只作候选，正式登记须管理员明确确认。
- 原型只覆盖管理员订单详情与工厂任务详情；飞书侧使用需求附录的消息卡片文案及真实 Excel 样例，不制作聊天 HTML 页面。网页表格为 7 列，工厂端无记录时隐藏整区。
- Excel 回传不允许手工新增无标识行；漏识别明细重新拍照处理。原图长期保留，数量纠正使用差额调整，不删除已登记记录。
- 识别固定使用 `qwen3.5-flash` 和 `single_v12_boxes.txt`，不识别图片日期。#208 增量随 PR #209 进入 v1.1.6：颜色直接连接尺码、原图嵌入、全派工状态采购匹配及未派工登记；唯一候选忽略未发数量，多候选沿用已确认选择规则。
- Codex 使用已启用管理员本人身份，复用网页登录及共同授权，无额外授权确认页或客户端管理页；业务上传仅支持 `.xlsx`。新增 Web 能力须同步核对 MCP 覆盖。
- 箱贴独立于来货出入需求，复用订单、工厂、SKU 图片及私有文件；图片数据准备依赖 #188，导出范围按 #186。
- 仓库员工入口、价格金额、付款、工厂／SKU 周汇总导出不在已批准范围；未批准业务线按各自确认门推进。

## 周出货回填的已确认规则

2026-09-11 确认：派工后先在小程序发货，再登记飞书。本周系统有效出货覆盖对应飞书周列，重复回填不累计；初始已发基线不计入本周，不开发交接周历史数量合并。仅更新已接管明细对应期间，其他行和历史周保留。

一期订单来源继续只读。回填必须在正式二期需求中明确目标列、接管范围、数据保护与授权后才能启用。

## 待确认事项

| 主题 | 需要确认的具体结果 |
|---|---|
| 回填期间 | 上海时区下原表月末拆周、两周合并、期间重叠／缺口及新列维护方式 |
| 回填数量与更正 | 有效出货统计中原报、收货差额、撤回、退回及跨周变更的归期；返修是否分项 |
| Base 接管 | 首个期间、来源行唯一匹配、人工值保护、冲突与缺列处理、预览和回读证据 |
| 月账单基数 | 系统发货或聚水潭实际入库的来源选择；差异已包含时不得重复计入 |
| 账期与异常 | 未知日期、多入库单、无系统发货、跨月补登、更正及关账后处理 |
| 质检／客退／返修 | 各自来源、正负方向、分母、是否参与数量结算及重复事实识别 |
| 分析与预警 | 指标公式、完整分母、截止时点快照、数据覆盖、历史回测及人工复核标准 |

## 后续资料与验收要求

每条未实现业务线完成“样本与口径 → 正式需求 → 交互原型 → 技术设计 → 开发计划与 Issue”的确认顺序。样本须覆盖跨订单同 SKU、跨月期间、撤回退回、已有人工值、无匹配行／列及重复事实；保持来源可追溯，不以金额相等替代数量正确。

已实现业务继续按[全系统验收记录](../../shared/delivery/验收记录.md)补齐运行环境、客户端、文件往返、真实通知及业务签收证据。共享测试、生产数据、Base 写入和发布按具体任务授权执行。
