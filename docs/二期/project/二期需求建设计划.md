> 日期：2026-09-08，2026-09-17 更新。状态：来货出入 V1.1 需求与两处页面原型已确认，技术设计为待确认草案；其他业务线仍不是已批准的开发计划。

## 1. 本轮结论

二期分为四条业务线：飞书机器人辅助登记来货出入；既有 Base 每周出货回填；月账单数量汇总；工厂分析和库存预警。取消仓库人员操作路线。

来货出入已确认改为先生成 Excel、管理员明确确认后正式登记；发货单可空，采购子单必须唯一关联订单明细和 SKU。已确认只回填原表周列、取消工厂/SKU周汇总导出；月账单只做数量分项，暂不加价格和金额。工厂分析和库存预警沿用原构想。当前只做需求和文档，不代表来货出入运行代码、数据库、机器人或真实通知已获开发授权。

## 2. 已定方向下仍需细化的业务规则

| 决策 | 当前建议（未批准） | 为什么必须先定 |
|---|---|---|
| 来货出入（已形成评审稿） | Excel 核对、采购子单与订单 SKU 唯一关联、整批确认、数量调整、订单详情展示和工厂通知已写入正式评审稿 | 待全文确认后再进入原型和技术设计 |
| 回填期间与归期 | 建议按上海时区、普通发货业务日期和现有列的实际日期区间映射 | 原表有月末拆周和两周合并，需检查期间重叠、遗漏和新列维护 |
| 出货数量 | 原报、确认后数量、扣退回净数量三选一，并规定跨周调整 | 不同口径影响历史周数、未出数量和提醒 |
| 月账单基数 | 核实使用系统原报、确认量还是聚水潭入库量，差异只加一次 | 样例有采购/入库单，不能把发货等同实际入库 |
| 历史与异常 | 未知日期、多个入库单、无系统发货单、跨月补登、正式更正分别定义 | 不能用登记日期或任意来源替代缺失事实 |
| Base 接管 | 明确首个期间、订单行范围、已有人工值保护、冲突处理和缺列处理 | 避免覆盖人工历史或重复累计；回填会影响现有公式链 |
| 质检/客退/返修 | 明确各自来源、正负方向及是否参与结算 | 一期质检返修与按发货单退回不是同一种业务，客退来源尚未核实 |

## 3. 需求建设步骤与可验收产物

| 步骤 | 产物 | 通过条件 |
|---|---|---|
| 1. 样本与口径 | 消息样本清单、周出货口径表、月账单数量来源表 | 上节决策有明确答案；用具体单据演算并确认 |
| 2. 二期需求评审稿 | `docs/二期/requirements/二期需求文档.md` 已创建；当前完成来货出入首版 | 包含角色、对象、字段、流程、数量、错误处理、排除项与验收标准，待用户全文批准 |
| 3. 交互/原型 | 飞书正常与异常处理流程、周出货回填预览、月数量明细；分析页面按后续切片确认 | 每页先确认展示内容与操作，审批后制作并逐页核对 |
| 4. 技术设计 | 机器人认证与身份、识别/去重、账单事实关联、同步幂等、权限、文件、审计、快照与回滚 | 不复制一套收货事实，现有 Base 输入输出无循环和重复累计，技术方案获批 |
| 5. 开发计划和 Issues | 有依赖关系的独立切片，每个 Issue 可独立验收 | 不提前创建没有确认规则的开发任务；开发前复核一期依赖与当前 CI |

首批样本至少覆盖：单 SKU 多货/少货、多 SKU、模糊手写、同凭证重发、已确认收货差异、无系统发货单、多个入库单号、缺日期及跨月补登。只使用获准范围的资料，不扫描同事全部聊天记录。

周出货回填样例至少覆盖：同厂同 SKU 跨两个订单、跨月周、撤回作废、跨周确认/退回、返修发回、初始已发基线、原表已有人填写、没有匹配行或期间列。月汇总先用本次账单的数量分项做可追溯对照，确保差异已生效时不会二次扣减；不以金额相等代替数量来源正确，本次不验证取价和金额。

## 4. 建议开发顺序（需求与设计批准后）

1. 周出货按来源订单明细计算，再做回填预览和受控 Base 同步；先验证统计口径及来源行匹配，不做独立周汇总导出。
2. 来货出入需求全文确认后，先完成三处交互原型，再设计数量生效、Excel 回传、匹配、幂等和通知闭环；正式登记始终需要管理员确认。
3. 合并既有收货差额、机器人登记、质检/客退等来源，生成月账单数量明细与汇总；先证明数量不重复且来源可追溯，暂不接入价格和金额。
4. 补齐可用指标分母与事件时间，再做工厂指标、月快照和 AI 月报。
5. 库存方向独立盘点聚水潭字段和固定快照，小范围回测后做规则预警，再加 AI 解释与催货建议。

以上是建议依赖顺序，不是立即实施授权，也不要求等所有分析指标都齐全才开始周报或差异登记。

## 2026-09-11 周出货回填交接边界（已确认）

用户按周一派工；派工后先在小程序发货，再登记飞书。本周系统有效出货覆盖写入对应飞书周列，不与现有周值累加；重复回填不重复计数，初始已发基线不计入本周。不开发交接周历史数量合并。仅更新已接管明细对应期间，不影响其他行/历史周。期间列映射、跨周调整/撤回等细则继续按二期需求门确认。本轮只记录，不写飞书或实现回填。
