# 出货阶段汇总回填需求

日期：2026-10-06。业务规则来自本次用户确认，本文为待审阅的正式需求候选；技术设计和实施计划尚待确认。文档跟踪：Issue #225。功能尚未实施、未启用。

## 1. 目标与范围

跟单管理系统按月内阶段汇总工厂提交的正常发货原报数量，自动回填既有飞书下单表的对应订单明细行。月初建好当月阶段出货数字列，并扩展“出货总数”公式。每次实际执行保留日志。

本功能是订单来源只读约束的有限例外：只允许创建阶段出货列、更新本功能接管行的对应阶段单元格，以及扩展“出货总数”公式。其他来源字段、其他公式、历史阶段与未接管行均保留。目标资源标识只存受控配置。

本需求不增加网页、小程序页面或通知，不涉及价格、月账单、返修统计、收货差额或来货出入汇总。

## 2. 数量与接管

- 起点为北京时间 **2026-10-06 00:00:00**，此前发货不纳入本功能。
- 使用工厂正式提交的正常发货原报数量。按订单明细汇总，同 SKU 跨订单分别计算；同明细多次发货合计。
- 草稿、截止时已撤回或作废的发货不计入。退回数量不扣减，收货确认、收货差额、来货出入、管理员数量调整和初始已发基线均不参与。
- 日期归属使用系统正式提交时间，精确到时间点；仅日期字段不足以判定22点边界。已确认发货日期来源于工厂正式提交，不引入人工回填日期。
- 同一正常发货单成功汇总后，撤回重提也不再次计入。根发货单作为去重身份，撤回历史副本和重提草稿均不能独立累计。
- 截止前撤回、尚未成功汇总的单据，后续正式重提按重提时间和重提原报数量归属；截止后操作不改变已冻结阶段。
- 按已有来源关联唯一定位飞书记录，核对订单编号、明细身份及来源范围。缺失、歧义或身份变化须记录错误，禁止用名称猜测关联。
- 对已确定接管的“行＋阶段”写入本阶段绝对合计，允许覆盖该单元格现有人工数值；禁止在旧值上累加。接管范围来自本阶段提交事实关联的明细；仅有撤回等排除事实时，证据完整才可确定为0。无阶段事实的其他行不清空，关联未知不写0。

## 3. 月内阶段

以周一至周日为基础，每个月单独划分。月初不足一周的片段为1～2天时并入随后一周，3天及以上独立成段；月末片段为1～2天时并入之前一周，3天及以上独立成段。阶段标签不跨月。

2026年10月沿用已存在阶段，自 `26.10.6-10.11出货` 开始；其后为 `26.10.12-10.18出货`、`26.10.19-10.25出货`、`26.10.26-10.31出货`。不修改10月早期列，也不按新算法重排历史月份。

2026年11月按新规则建立：

| 字段 | 标签日期 | 执行时间（北京时间） |
|---|---|---|
| `26.11.01-11.08出货` | 11月1日至8日 | 11月8日22:00 |
| `26.11.09-11.15出货` | 11月9日至15日 | 11月15日22:00 |
| `26.11.16-11.22出货` | 11月16日至22日 | 11月22日22:00 |
| `26.11.23-11.30出货` | 11月23日至30日 | 11月30日22:00 |

新列统一采用 `YY.MM.DD-MM.DD出货`，历史列允许月、日不补零，通过实际日期区间识别，保留原名。

## 4. 22点截止与连续归属

每个阶段结束当天北京时间22:00触发。区间左闭右开，恰好22:00归下一阶段：

| 阶段 | 实际统计窗口（北京时间） |
|---|---|
| 首阶段 | `[2026-10-06 00:00, 2026-10-11 22:00)` |
| 下一阶段 | `[2026-10-11 22:00, 2026-10-18 22:00)` |
| 11月首阶段 | `[2026-10-31 22:00, 2026-11-08 22:00)` |

字段日期表示阶段标签，实际窗口以前一阶段截止时间连续衔接。因此10月31日22点后的发货计入11月首阶段。该归属为已确认业务口径，不执行自然月零点截断。

调度按截止时间判断到期任务，月初负责建当月列。停机恢复后执行遗漏的技术任务，仍按原截止点取事实，不能把恢复时的当前状态当成截止状态。

## 5. 字段和公式

- 每月1日北京时间开始准备当月全部阶段列；首次启用或停机恢复时补齐应有结构。已有唯一同区间数字列直接复用。
- 仅检查接管区间的连续性；历史早期不同分段不阻止接管。接管范围内重叠、重复区间、日期缺口、同名非数字列均报错。
- 创建成功后登记字段 ID；后续名称变化须核对区间，删除重建须核验新身份。结构异常不能自动删列或改类型。
- “出货总数”保留原有历史项及 `ROUND`、`SUM`、`IFBLANK` 计算语义，每个新增阶段只加入一次。其他公式通过依赖自然更新。
- 公式结构或历史引用与已核验基线不一致时停止公式修改，记录冲突；不能用重建整条公式掩盖人工调整。

## 6. 快照、失败和日志

阶段截止时固定发货身份、数量、来源关联及排除原因。后续补录、修改、撤回和退回不重算已冻结阶段。技术失败重试始终使用同一快照。

字段创建、公式修改、按行写入、回读验证分步记录。请求超时须先查远端结果；部分成功只重试未确认项。同一阶段重复执行不能重复建列、重复加公式项或累计数量。

每次实际执行或重试有一条可查询记录，至少包括执行 ID、阶段、北京时间计划截止点、开始/结束时间、尝试次数、成功/失败状态、目标行数、成功行数、数量合计、排除数量及原因、失败步骤和错误原因。轮询发现无到期任务不产生业务执行日志。

不能可靠还原的历史事实应报告待核验，禁止静默遗漏或猜测数量。系统停机、权限丢失、字段容量不足和外部限流均须保留失败记录；终止错误由运维处理后重试原任务。

## 7. 验收标准

| 场景 | 预期 |
|---|---|
| 月初1/2天、3天；月末1/2天、3天 | 前两类合并，3天独立；月份无日期遗漏或重叠 |
| 2026年11月 | 列名与第3节四列一致 |
| 10月接管 | 复用指定历史列，10月6日前不写 |
| 21:59:59、22:00、月末22:00 | 分别归本阶段、下阶段、下月首阶段 |
| 提交事务跨越22点、任务延迟和进程重启 | 所有已提交事实有唯一归属，不漏记、不重复 |
| 原报100、确认95、退回10 | 本需求按原报100统计 |
| 截止前撤回，下一阶段重提 | 本阶段排除；从未汇总的根单可按新提交进入下一阶段 |
| 成功汇总后撤回重提 | 旧阶段不变、后续不重复计入 |
| 同SKU跨订单、一次发货含多条明细 | 写入各自来源行，合计守恒 |
| 重试、部分写入、远端成功后本地中断 | 回读同一快照，最终值与单次成功相同 |
| 字段/公式人工变化、行关联缺失 | 有明确错误和待处理项，无猜测覆盖 |
| 当月建列重跑、跨年、闰年2月 | 列及公式引用不重复，日期有效 |
