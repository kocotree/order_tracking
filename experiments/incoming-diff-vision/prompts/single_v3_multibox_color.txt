你在识别一张服装工厂来货核对照片。同一张照片里可能有一张或多张箱贴（印刷表格、手写内容），以及拍照后叠加的彩色大字差异标注。差异标注可能同时提到几种颜色。

只输出一个 JSON 对象，不要输出解释、前后缀或代码块标记，结构固定为：
{
  "factoryName": 工厂名称或 null,
  "productCode": 货号或 null,
  "productName": 品名或 null,
  "color": [照片中各张箱贴上的完整颜色名称，不含尺码后缀],
  "packQuantity": 唯一可确定的箱贴装箱数量数字或 null,
  "diffNoteText": 叠加差异标注的原文整句或 null,
  "lines": [
    {"color": 该条差异的完整颜色名称或 null, "size": 尺码或 null, "direction": "多"或"少", "quantity": 差异数量的绝对值数字}
  ],
  "confidence": 0 到 1 的数字,
  "unresolvedFields": [无法确定的字段名]
}

规则：

1. 先找出同一张照片里的所有箱贴，分别读出工厂、货号、品名、颜色、尺码和装箱数量。`color` 始终是数组：一张箱贴只有一种颜色时也放一个元素；多张箱贴的颜色去重后分别放入；没有读到箱贴颜色时放空数组。标注中出现但箱贴上没有的颜色不加入这个数组。

2. 多张箱贴的工厂、货号、品名只在能确认相同时合并为一个值；某张箱贴读不清时，可用另一张清晰的同字段。若读到互相冲突的值，返回 null，并在 `unresolvedFields` 写入字段名。多张箱贴的装箱数量不同或无法确定对应哪一张时，`packQuantity` 填 null。装箱数量只作参考，绝不是差异数量。

3. 要登记的差异方向和数量只来自彩色大字差异标注。标注里有几条差异，`lines` 就放几条；没有差异标注时，`lines` 为空数组、`diffNoteText` 为 null。`diffNoteText` 保留标注原文，包括颜色简称或笔误，不做补全。

4. 每条 `lines[].color` 分别确定，不把某张箱贴的颜色套到所有差异上：
   a. 标注写了完整颜色名，优先用标注中的颜色名；即使它没有出现在箱贴上，也保留标注中的颜色名。若与箱贴名称只有明显笔误或字序差异，且能唯一对应同一种颜色，用箱贴上的完整名称。
   b. 标注只写「灰」「蓝」等简称时，在箱贴颜色中找唯一能对应的完整名称，例如箱贴有「碧潭灰」「暮山紫」，标注写「灰」，该条填「碧潭灰」。有两个以上可能对应的名称时填 null，并在 `unresolvedFields` 写入 "lines.color"。
   c. 标注没写颜色，且箱贴颜色只有一种时，用那一种完整名称。箱贴有多种颜色、无法唯一确定该条属于哪种时填 null，并在 `unresolvedFields` 写入 "lines.color"。

5. `direction` 保留「多」或「少」的原文判断，不换成正负号。`quantity` 填绝对值数字：「少一个」记作 1，「多10」记作 10。

6. 每条差异的尺码按下列优先级确定：
   a. 标注里写了尺码（如「120少1」「m少一个」），用标注里的。
   b. 标注没写尺码时，从该条差异对应的箱贴上取。箱贴有「尺码」行，就用它；该行列出多个尺码时，取「装箱数量」有数字的那一列对应的尺码。箱贴没有「尺码」行、只有「颜色及规格」行时，尺码是颜色后面的字母后缀，例如「盛夏樱桃粉L」的尺码是 L。箱贴其他位置单独手写的尺码字母也算。
   c. 商品本身没有尺码时，`size` 填 null。商品有尺码但无法从标注或对应箱贴唯一确定时，`size` 填 null，并在 `unresolvedFields` 写入 "lines.size"。不要借用另一种颜色箱贴上的尺码。

7. 尺码去掉单位和符号，只保留本体：「120CM」「120#」都写成 "120"，字母尺码统一大写，「m」写成 "M"。

8. 「厚款/薄款」若写在品名旁，原样保留在 `productName` 中，例如「小括号弯刀裤(厚款)」。不要改写成产品资料里的「厚绒/薄绒」，也不要凭商品名称猜测厚薄。

9. 图上没有写明且无法唯一确定的字段返回 null；`color` 没有读到值时返回空数组。发货日期不在本次输出范围内，不要输出这个字段。只输出 JSON。
