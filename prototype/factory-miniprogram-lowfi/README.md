# 工厂小程序低保真原型

本目录用于逐页确认工厂小程序的页面内容、字段、操作和跳转，不是微信小程序正式实现代码。业务范围以 `docs/requirements/一期需求文档.xml` V1.31 为准，页面层级以 `docs/project/一期三端页面地图.md` 为准。

## 已确认的原型口径

- 正常任务列表按订单维度展示，一张订单一张卡片，不按产品规格拆卡。
- 任务列表卡片不展示颜色/规格，任务详情再展示产品规格明细。
- 创建发货单从任务列表页进入，不从任务详情进入。
- 创建发货单采用“先添加箱号，再逐箱选择订单规格并填写数量，最后填写凭证并预览提交”的方向。
- 一张发货单可以包含本厂多个订单和多个产品规格，一只箱子也可以混装。
- 同一产品规格跨订单时，默认按合同出货时间最早的订单优先分配，提交前展示分配结果并允许调整。

任务列表默认显示未完成任务，已完成任务可以通过状态筛选查看。

## 当前必须解决的问题

1. 创建发货单第二步存在渲染错误，箱号选择、区块标题和上下步按钮没有显示。
2. 当前只保存箱号，没有保存每个箱子的订单规格和装箱数量。
3. 装箱数量、凭证和备注进入下一步后会丢失，预览页无法展示真实内容。
4. 缺少装箱合计、可发数量和无效提交校验。

## 下一步讨论顺序

1. 确认创建发货单的完整页面步骤及每一步展示字段和操作。
2. 确认逐箱装箱、装箱组和混装箱的交互方式。
3. 确认同一规格跨订单的自动分配与人工调整方式。
4. 确认预览页内容和提交前校验。
5. 方案确认后再修改页面代码；创建发货单确认完成后，继续质检单返修任务。

## 原型边界

- 任务卡片可以进入任务详情；点击尚未制作的底部页签时只提示后续逐页确认。
- 当前创建发货单流程只能用于讨论页面方向，不能视为可用或已验收流程。
- 正式开发将在 `miniprogram/` 中建立微信小程序项目，本原型不会直接作为生产代码上线。
