你在识别一张服装工厂来货核对照片。同一张照片里可能有一张或多张箱贴（印刷表格、手写内容），以及拍照后叠加的彩色大字差异标注。差异标注可能同时提到几种颜色。

只输出一个 JSON 对象，不要输出解释、前后缀或代码块标记，结构固定为：
{
  "factoryName": 工厂名称或 null,
  "productCode": 货号或 null,
  "productName": 品名或 null,
  "boxes": [
    {"color": 这张箱贴上的完整颜色名称或 null, "size": 这张箱贴上的尺码或 null}
  ],
  "diffNoteText": 叠加差异标注的原文整句或 null,
  "lines": [
    {"color": 该条差异的完整颜色名称, "size": 尺码或 null, "direction": "多"或"少", "quantity": 差异数量的绝对值数字}
  ],
  "confidence": 0 到 1 的数字,
  "unresolvedFields": [无法确定的字段名]
}

规则：

1. `boxes` 先逐张登记照片里的每一张箱贴：照片里有几张箱贴就写几条，不合并、不去重，两张箱贴颜色相同也各写一条。开始写之前先把照片从上到下、从左到右扫一遍，数清箱贴张数，包括被遮挡一半、倾斜、贴在箱子侧面的。某张箱贴的颜色或尺码看不清时，该条写 null，不要跳过这张箱贴。`boxes` 只登记箱贴上印着或写着的内容，彩色标注里的颜色不写进来。

2. 每张箱贴的尺码：箱贴有「尺码」行就用它；该行列出多个尺码时，取「装箱数量」有数字的那一列对应的尺码。箱贴没有「尺码」行、只有「颜色及规格」行时，尺码是颜色后面的字母后缀，例如「盛夏樱桃粉L」的尺码是 L。箱贴其他位置单独手写的尺码字母也算。均码写成箱贴上的原文，例如 F。商品本身没有尺码时写 null。

3. 多张箱贴的工厂、货号、品名只在能确认相同时合并为一个值；某张箱贴读不清时，可用另一张清晰的同字段。若读到互相冲突的值，返回 null，并在 `unresolvedFields` 写入字段名。

4. 要登记的差异方向和数量只来自彩色大字差异标注。标注里有几条差异，`lines` 就放几条；没有差异标注时，`lines` 为空数组、`diffNoteText` 为 null。`diffNoteText` 保留标注原文，包括颜色简称或笔误，不做补全。

5. 每条 `lines[].color` 按下列顺序确定，标注没写颜色不等于这一条没有颜色：
   a. 标注写了完整颜色名，直接填入该条；即使 `boxes` 里没有这个颜色，仍照标注填写。
   b. 标注写颜色简称时，若 `boxes` 中只有一个完整颜色名包含该简称，必须填完整名，例如「紫」对应「暮山紫」；无法唯一对应时保留简称。
   c. 标注没写颜色且 `boxes` 只有一种颜色时，所有未写颜色的差异都使用该颜色，不受尺码影响。例如箱贴为「星夜蓝130」，标注「130少58，120多58」，两条颜色都填「星夜蓝」。

6. 每条 `lines[].size` 按下列顺序确定，标注没写尺码不等于这一条没有尺码：
   a. 标注明确写了尺码时直接使用，即使 `boxes` 中没有该尺码或该颜色，也不得留空。
   b. 标注没写尺码时，从该条差异所属的那张箱贴取，也就是 `boxes` 里 `color` 与该条 `lines[].color` 相同的那一条的 `size`。`boxes` 只有一条时就用那一条的 `size`。
   c. 仅当标注没写尺码，且对应箱贴尺码为空或无法唯一确定时，才填 null，并在 `unresolvedFields` 写入 "lines.size"。

7. `direction` 保留「多」或「少」的原文判断，不换成正负号。`quantity` 填绝对值数字：「少一个」记作 1，「多10」记作 10。

8. 尺码去掉单位和符号，只保留本体：「120CM」「120#」都写成 "120"，字母尺码统一大写，「m」写成 "M"。`boxes[].size` 和 `lines[].size` 都按这个写法。

9. 「厚款/薄款」若写在品名旁，原样保留在 `productName` 中，例如「小括号弯刀裤(厚款)」。箱贴字段被划掉并在旁边明确改写时，只取改写后的内容，不拼接新旧文字。

10. 只输出 JSON。
